# Стратегічна логіка продукту WEEXP — одна воронка → рушій → навчання

> Не набір інструментів, а ОДНА система. Кожен крок годує наступний і, зрештою,
> Learning Core (moat). Кабінет — хаб цієї воронки.

## Наскрізний шлях клієнта

```
Відвідувач
  → ЕКСПРЕС-АУДИТ (калькулятор /calculator)         ← гачок: недоотриманий оборот
  → ЗАЯВКА + оглядовий PDF                           ← лист власнику (/api/lead, Resend)
  → АКАУНТ у кабінеті (/app)                          ← сесія (localStorage MVP → magic-link)
  → ПРОФІЛЬ компанії                                  ← дані магазину
  → ГЛИБОКИЙ АУДИТ (T1–T4)                            ← глибина = обсяг доступів = достовірність
  → ЗНАХІДКИ + ДОРОЖНЯ КАРТА                          ← рушій worker/ (19 блоків, Meta-Audit, ARS)
  → СПІВПРАЦЯ / ЗРОСТАННЯ                             ← повторний аудит
  → LEARNING CORE                                     ← провалідовані знахідки → калібрування,
                                                        патерни, бенчмарки, нові golden-кейси
```

## Єдине джерело правди

| Шар | Файл | Роль |
|-----|------|------|
| Модель грошей + ніші + достовірність | `src/lib/audit.ts` | Спільна для калькулятора і кабінету (без дублювання) |
| Акаунт + профіль + воронка | `src/lib/account.ts` | Сесія, профіль, `getJourney()`, стадії воронки |
| Калькулятор (топ воронки) | `src/pages/CalculatorPage.tsx` | 3 кроки → PDF + заявка; пише snapshot і стадію `lead` |
| Кабінет (хаб) | `src/pages/CabinetPage.tsx` | Огляд-шлях, профіль, аудити, глибокий аудит T1–T4 |
| Рушій глибокого аудиту | `worker/` | runAudit → знахідки, Meta-Audit/Quality Gate, Run Record |
| Навчання | `worker/src/learning/` | Провалідовані аудити → калібрування + бенчмарки + golden |

## Принцип глибини (одна змінна)

Глибина T1–T4 — єдина змінна і в калькуляторі, і в кабінеті, і в рушії:
T1 зовнішній обхід (до 35%) → T2 + аналітика (до 55%) → T3 + бізнес-дані (до 78%) →
T4 живі доступи (до 92%). Більше даних НЕ роздуває суму — підвищує достовірність.

## Стан і наступні кроки

**Зроблено (код, перевірено):** калькулятор з нуля (3 кроки, PDF, заявка); кабінет з нуля
(шлях-воронка, профіль, аудити, глибокий аудит T1–T4 із заявкою на почту); єдина модель
`audit.ts` + воронка `account.ts`.

**Рішення прийнято:** авторизація — абстракція-first (`account.ts`): зараз localStorage-MVP,
далі magic-link/Supabase підключається заміною драйвера без переписування UI.

**Наступне (owner-рішення / інфра):**
- Підключити реальну авторизацію (magic-link) + серверне сховище профілю/аудитів.
- Звʼязати кнопку «Замовити глибокий аудит» із запуском `worker/runAudit` (черга + вебхук
  у кабінет), а результати (знахідки/PDF) підтягувати в розділи «Знахідки» і «Документи».
- Розділ «Доступи» — інтейк T1–T4 з інструкціями (перевикористати логіку з data room).
- Historical comparison і Learning Core на реальних прогонах.
