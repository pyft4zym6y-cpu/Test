# Что забираем себе: открытый софт и чужие скиллы

Решение по итогам внешнего поиска 26.08.2026 (полный разбор — артефакт
«Карта открытого маркет-стека»). Здесь только то, что берём, и как.

---

## 1. Открытый софт — в движок аудита

| Что | Зачем именно нам | Куда | Усилие |
|---|---|---|---|
| **Crawl4AI** (Apache-2.0, ~68k★) | Страница → чистый markdown локально, без внешних API. Заменяет связку `mcporter` + `exa.web_search_exa`, которой **нет в образе** (`TOOLING_GAP §1.3`), из-за чего соцсети, внешний инфофон и отзывы тихо деградируют | `worker/Dockerfile`, `worker/src/agentReach.ts` | 1 день |
| **Unlighthouse** | Lighthouse по всему сайту со смарт-сэмплингом + бюджеты. Сейчас Website-аудит опирается на один прогон PageSpeed | Website-аудит, блок CWV и доступности | 1–2 дня |
| **SEOnaut** (MIT, ~771★, Go+MySQL) | Детерминированный тех-SEO: битые ссылки, редирект-петли, дубли мета, порядок заголовков — с уровнями критичности. Снимает эти проверки с LLM | SEO-аудит, замена самодельных проверок | 2 дня |
| **Elmo** (MIT, self-host) | Измерение видимости бренда в ChatGPT, Claude, Perplexity, Gemini, Copilot, Grok и AI Overviews. Закрывает `TOOLING_GAP §2.3` без платных трекеров (LLM Pulse от €49/мес) и без ожидания `geo-analyzer` | GEO/AEO-блок SEO-аудита | 2 дня |
| **SerpBear** (self-host) | Безлимитный трекинг позиций, свой SERP API, GSC и идеи ключей из Google Ads, алерты. Даёт динамику между прогонами — то, чего разовый аудит не даёт | Пост-аудит клиента, повод для повторной продажи | 1 день |
| **Carbone** | Шаблон + JSON → детерминированный PDF/DOCX/XLSX/PPTX, есть MCP. Вёрстка отчёта перестаёт быть кодом | Рендер клиентского отчёта | 2 дня |
| **CrUX API** | Полевые CWV по любому домену без доступов — единственный способ мерить конкурентов по реальным пользователям (уже в `TOOLING_GAP §2.1`) | Website-аудит, блок «против конкурентов» | 0.5 дня |

Во вторую очередь, по мере необходимости: **PostHog** и **OpenReplay** (поведенческие
факты и записи сессий вместо скриншотов), **GrowthBook** (рекомендации аудита →
проверяемые эксперименты), **PyMC-Marketing** (CLV и медиа-вклад одним стеком),
**Google Meridian** (распределение бюджета — отдельный модуль/апселл, в 12 слоях его нет).

Чек-листы, которые берём как ТЗ, а не как код: 19 AI-краулеров и структура отчёта из
`indexcraft/ai-seo-audit-agent`, 28 детерминированных правил и карта 39 модулей из
`BlogPilot`, 42 проверки в 14 категориях из `optmyzr-skills/google-ads-audit`.

## 2. Свои скиллы — подключить, а не докупать

71 скилл установлен, движком не вызывается ни один (`TOOLING_GAP §1.1`). Полный разбор —
`docs/tooling/SKILLS_CATALOG.md`. 27 из них — прямые кандидаты в рантайм аудита.

Предлагаемое расширение `DOMAIN_SKILLS` в `worker/src/domainSkills.ts` (маркетплейс-скиллы
идут **вторым слоем** к 22 OS-скиллам методологии, не вместо них):

| Аудит | Добавить |
|---|---|
| `seo` | `seo-audit`, `seo-technical`, `seo-page`, `seo-schema`, `seo-geo`, `seo-sxo`, `seo-ecommerce`, `seo-local`, `ecommerce-keyword-research` |
| `website` | `cro`, `ab-testing`, `site-architecture`, `playwright-cli` |
| `acquisition` | `ads-audit`, `ads-google`, `ads-meta`, `ads-budget`, `google-shopping-optimization` |
| `analytics` | `ads-attribution`, `ads-report` |
| `business` | `ads-math` |
| `market` | `ads-competitor`, `competitor-profiling` |
| `product` | `product-page-seo`, `competitor-price-analysis` |
| `customer` | `churn-prevention` |
| `technology` | `penetration-testing-with-strix` (опционально, по согласию клиента) |
| все | `agent-reach` как источник внешних сигналов |

Важно про кеш: блок всех скиллов обязан оставаться байт-в-байт одинаковым между вызовами,
иначе префиксный кеш промпта не совпадёт (см. комментарий к `ALL_SKILLS`). Второй слой
подключать тем же приёмом — стабильный алфавитный список в кешируемом префиксе, а в
профильном блоке только указатель, какие линзы ведут в этом аудите.

Чего в открытом виде **нет** и придётся писать самим: RFM/LTV из выгрузки магазина
(есть только `PyMC-Marketing` как библиотека), доля голоса и тональность в PR
(единственное живое — `HasData/social-listening-tool`), аудит магазина целиком —
каталог, навигация, чекаут, доверие.

## 4. Порядок

1. `Crawl4AI` в `worker/Dockerfile` + явная пометка в отчёте вместо тихой деградации.
2. Второй слой скиллов в `domainSkills.ts` — 27 установленных скиллов подключаются к 12 аудитам.
3. `Unlighthouse` и `SEOnaut` как источники детерминированных проверок.
4. `Elmo` self-host → GEO-блок.
5. Чек-лист Optmyzr в слой Paid; Google Ads Scripts как обходной путь, пока `notfair-googleads` не авторизован.
6. `Carbone` под рендер отчёта; `SerpBear` — клиенту, на пост-аудит.
7. `lanavitta-run01` → регресс-тест: детерминированные проверки наконец дают на чём его завести.

## 5. Оговорки

- Три MCP (`citedy-seo-agent`, `labelhead-artist-momentum`, `notfair-googleads`) не
  авторизованы и в неинтерактивной сессии авторизованы быть не могут — нужен OAuth через
  настройки коннекторов claude.ai или `/mcp` в интерактивной сессии.
- Лицензии проверять перед встраиванием: `n8n` — Sustainable Use License (не OSI),
  `Matomo` — платные плагины даже в self-host.
- Звёзды и даты — со страниц проектов на 26.08.2026; у мелких репозиториев меняются быстро.
  GitHub API в сессии закрыт скоупом репозитория, поиск шёл вебом.
