# Библиотеки: чем усилить воркер

Срез 26.08.2026. Отправная точка — реальное состояние `worker/package.json`:
**8 рантайм-зависимостей на 21 тысячу строк кода**.

```
@anthropic-ai/sdk · axe-core · docx · mammoth · playwright · pptxgenjs · xlsx · zod
```

Всё остальное написано руками: `crawl.ts` — 1041 строка обхода и 30 проверок
голд-стандарта, `crux.ts` — свой клиент Chrome UX Report, `pdf.ts` — рендер через
отдельный headless-браузер, `xlsx.ts`, `report.ts`, `techaudit.ts`. Тестов — ноль.

Ниже — что имеет смысл поставить, что именно оно снимает с нас и чего трогать не надо.

---

## 1. Обход и разбор страниц

| Библиотека | Что даёт | Что снимает с нас |
|---|---|---|
| **crawlee** | Очередь запросов с персистентностью, автоскейл конкурентности, ротация сессий и прокси, единый интерфейс над HTTP и headless. Стандарт продовых краулов на Node в 2026 | Оркестрацию в `crawl.ts`: очередь, ретраи, лимиты. **Проверки не трогаем** — 30 голд-стандартных проверок это наша ценность, а не инфраструктура |
| **cheerio** | Разбор статического HTML в стиле jQuery поверх parse5 | Запуск браузера там, где он не нужен: robots, sitemap, служебные страницы. Прямая экономия времени прогона |
| **@mozilla/readability + turndown** | Страница → чистый текст → markdown | Тот же результат, что даёт Crawl4AI, но без Python в образе. Меньше токенов на вход LLM |
| **robots-parser** | Разбор `robots.txt` по правилам, проверка конкретного user-agent | Ручной парсинг в GEO-блоке: 19 AI-краулеров проверяются одной функцией |
| **sitemapper** | Разбор `sitemap.xml`, включая индексные и вложенные | Свой обход карты сайта |
| **metascraper** | Метаданные, Open Graph, микроразметка с цепочкой фолбэков | Ручное вытаскивание мета в `techaudit.ts` |
| **linkinator** | Битые ссылки: краулер + API + CLI, сделан под SEO-аудит и CI | Целый блок проверок, которого у нас сейчас нет |

## 2. Производительность, доступность, разметка

| Библиотека | Что даёт | Заметка |
|---|---|---|
| **lighthouse** (node module) | Программный запуск полного аудита: производительность, доступность, best practices, SEO. С 10-й версии считает INP вместо FID | Умеет подключаться к уже запущенному Chromium — тому самому, что поднимает `crawl.ts` |
| **unlighthouse** | Lighthouse по всему сайту со смарт-сэмплингом, дашборд, бюджеты | Обёртка над первым; ставить, если нужен обход целиком, а не выборка |
| **@axe-core/playwright** | Инъекция `axe-core` прямо в страницу нашего обхода | `axe-core` уже в зависимостях, но без адаптера его надо звать руками |
| **schema-dts** | Типы Schema.org для TypeScript | Генерация JSON-LD с проверкой на этапе компиляции. Валидацию чужой разметки всё равно делает сервис Google |
| **html-validate** | Валидатор HTML с конфигурируемыми правилами | Проверить актуальность перед вводом |

CrUX у нас **уже реализован** (`crux.ts`, 126 строк, свой клиент к
`chromeuxreport.googleapis.com`) — в план внедрения он больше не нужен, вопреки
записи в `TOOLING_GAP §2.1`.

## 3. Кабинеты и внешние данные

| Библиотека | Что даёт | Состояние |
|---|---|---|
| **googleapis** | Официальный клиент: Search Console, Sheets, Drive, OAuth 2.0, сервисные аккаунты | v176.0.0, публикуется еженедельно |
| **@google-analytics/data** | GA4 Data API: реальные конверсии и выручка → калибровка revenue-gap | Официальный |
| **google-ads-api** (Opteo) | GAQL-запросы из Node, типизированные ресурсы | v24.1.0 |
| **facebook-nodejs-business-sdk** | Meta Ads и Insights | Официальный SDK Meta |
| **@shopify/shopify-api** | Admin и Storefront API | Для клиентов на Shopify — структурные товары и цены без парсинга |
| **DataForSEO** | SERP, ключи, ссылки, on-page и Merchant одним ключом | Официального npm-клиента нет, ходить REST'ом через `undici` |

Это и есть ответ на главный дефицит из `OSS_ADOPTION.md`: данные берутся не
через чужой платный MCP, а напрямую библиотеками из образа.

## 4. Числа: статистика и модели

| Библиотека | Что даёт | Зачем нам |
|---|---|---|
| **simple-statistics** | Описательная статистика, регрессии, доверительные интервалы | Значимость A/B и разброс метрик без самодельной математики |
| **arquero** или **danfojs** | Таблицы в памяти: группировки, джойны, оконные функции | Когорты и сводки вместо цепочек `reduce` |
| **PyMC-Marketing** *(Python)* | Байесовский MMM **и** CLV: BG/NBD, Pareto/NBD, BG/BB, сегментация RFM | Единственный зрелый способ дать «деньги» из выгрузки магазина. Библиотека `lifetimes` переведена в режим поддержки и переехала именно сюда |
| **statsmodels · scikit-learn · Prophet · CausalImpact** *(Python)* | Регрессии, сегментация, прогноз сезонности, оценка эффекта вмешательства | Второй контур; поднимать отдельным сервисом, а не тащить Python в Node-образ |

## 5. Отчёт

| Библиотека | Что даёт | Что меняет |
|---|---|---|
| **exceljs** | Полноценная работа с XLSX: стили, формулы, ширины | Замена `xlsx@0.18.5`: **SheetJS больше не публикуется в npm после этой версии**, апдейты живут на их сайте. Версию в проде надо проверить на известные уязвимости |
| **vega-lite + vega** или **echarts** (SSR) | Детерминированный рендер графиков в SVG на сервере | Графики отчёта перестают зависеть от вёрстки страницы |
| **resvg-js** или **sharp** | SVG → PNG | Нужен, если график едет в PDF или в письмо |
| **@napi-rs/canvas** | Canvas без нативного Cairo | Альтернатива `chartjs-node-canvas`, у которого тяжёлая нативная сборка |
| **satori** | JSX/HTML → SVG | Карточки и обложки отчёта из кода, без браузера |
| **docxtemplater** | DOCX из шаблона с плейсхолдерами | Вёрстка отчёта уходит из кода в шаблон; правит не разработчик. Альтернатива — Carbone (PDF/DOCX/XLSX/PPTX из одного шаблона) |
| **@mermaid-js/mermaid-cli** | Диаграммы из текста | Причинная карта «находка → причина → метрика → ₴» рисуется сама |

`docx`, `pptxgenjs` и рендер PDF через Playwright у нас уже стоят и работают —
их меняем только на шаблонный подход, если надоест верстать кодом.

## 6. Инфраструктура прогона

| Библиотека | Что даёт | Зачем нам |
|---|---|---|
| **p-limit** / **p-queue** | Ограничение конкурентности; `p-queue` умеет приоритеты, паузу, интроспекцию | Параллельные вызовы Claude и обход без самодельных семафоров |
| **p-retry** | Ретраи с экспоненциальной задержкой, чистый ESM | Сеть и 429 от API кабинетов |
| **undici** | HTTP-клиент с пулами соединений, на нём построен родной `fetch` | Массовые запросы к CrUX, DataForSEO, кабинетам |
| **bullmq** | Очередь на Redis: отложенные задачи, приоритеты, ретраи, rate limit | Прогоны аудита как задачи, а не как долгий HTTP-запрос |
| **js-tiktoken** | Подсчёт токенов до вызова | Для Claude точнее использовать `count_tokens` из Anthropic API; библиотека — для грубой оценки бюджета |

`zod` v4 уже стоит — это правильный инструмент для схем структурированного вывода
LLM, ничего добавлять не нужно.

## 7. Тесты — ноль на 21 тысячу строк

| Библиотека | Что даёт |
|---|---|
| **vitest** | Раннер с API как у Jest, нативный ESM и TypeScript — совпадает со стеком воркера |
| **msw** или **nock** | Перехват HTTP: Anthropic, CrUX, GSC, кабинеты мокаются, регресс гоняется без сети и без денег |
| **@playwright/test** | Уже стоит в корневом проекте — переиспользовать для сценариев обхода |

Материал для первого теста лежит готовым: `worker/reference/weexp-os/lanavitta-run01/`
с `findings.json` и `coverage.json` — снапшот-тест движка из реального прогона.

## 8. Что не брать

| Что | Почему |
|---|---|
| **LangChain / LlamaIndex (JS)** | У нас свой пайплайн на `@anthropic-ai/sdk` с кешируемым префиксом. Фреймворк добавит слой абстракции поверх того, что уже работает, и сломает контроль над префиксом кеша |
| **chartjs-node-canvas** | Тянет нативный Cairo и Pango в образ; тот же результат даёт SSR ECharts или Vega плюс `resvg-js` |
| **jsdom** для обхода | У нас настоящий браузер. jsdom нужен там, где браузер избыточен, — но там дешевле `cheerio` |
| **Свой HTTP-клиент поверх fetch** | `undici` уже под капотом Node и делает это лучше |

---

## Порядок

1. **vitest + msw**, снапшот на `lanavitta-run01` — до любых новых зависимостей, иначе менять `crawl.ts` вслепую.
2. **cheerio + robots-parser + sitemapper + linkinator** — дешёвые проверки уходят из браузера, появляется блок битых ссылок.
3. **googleapis + @google-analytics/data + google-ads-api** — прямой доступ к данным вместо чужого MCP.
4. **p-limit + p-retry + undici** — прогон перестаёт падать на сети и упирается в лимиты осознанно.
5. **lighthouse** программно на существующем Chromium — CWV и доступность по-настоящему, а не одним замером.
6. **exceljs** вместо замороженного `xlsx@0.18.5` — заодно проверить уязвимости текущей версии.
7. **crawlee** — только после тестов: он меняет оркестрацию обхода, самую рискованную часть.
8. **PyMC-Marketing** отдельным сервисом, когда дойдём до RFM, LTV и медиа-вклада.

Версии в таблицах — по npm на 26.08.2026; перед установкой сверять актуальные.
