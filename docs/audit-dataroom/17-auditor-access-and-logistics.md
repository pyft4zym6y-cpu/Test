# 17 · Логистика аудита: доступ и организация

> Как передать систему внешнему аудитору «под микроскоп» — безопасно и по правилам.

## O-01 · Скоуп и цели аудита

**Цель:** независимая проверка продукта и процессов WEEXP Commerce OS.

**В периметре:** `worker/` (движок), `portal/` (портал), `portal/api/` (serverless),
данные и потоки (разделы 04–06), методология (09), процессы (10), безопасность (05),
приватность (11).

**Вне периметра (по умолчанию):** смежные приложения репозитория (`weexp-site/`, `school/`,
`video/`, корневой лендинг) — при желании расширяется отдельным скоупом.

**Критерии оценки (предлагаемые):** корректность и безопасность архитектуры; защита данных
и соответствие GDPR; отсутствие выдумок в выводах (методологический контроль); операционная
зрелость; управляемость рисков. Уточняется с аудитором.

## O-02 · Как дать аудитору доступ (read-only, безопасно)

| Что | Как дать | Права |
|-----|----------|-------|
| Репозиторий | GitHub: пригласить как **read-only** collaborator (или приватный форк) | Чтение |
| Ветка для аудита | Указать ветку (напр. `main` или актуальную `claude/*`) | — |
| Портал (демо) | Запустить в **демо-режиме** (`npm run preview` без Supabase) — данные в localStorage, без реальных клиентов | Просмотр |
| Движок | Запустить локально с тестовым `ANTHROPIC_API_KEY` на тестовом сайте | Просмотр |
| Supabase (при необходимости) | Read-only роль или экспорт схемы `portal/supabase/schema.sql` (без данных клиентов) | Чтение схемы |
| Прод-данные | **Не давать.** Аудит логики/RLS — на тестовых данных | — |
| Секреты | **Не передавать реальные ключи.** Аудитор использует свои тестовые | — |

**Принцип:** аудитор видит код, схему, процессы и может воспроизвести прогон на **тестовых**
данных. Реальные данные клиентов и продовые секреты не передаются (минимизация).

## O-03 · NDA и обращение с данными (📝)

Подписать NDA с аудитором до передачи доступа. Правила: не копировать данные клиентов вовне,
не публиковать находки без согласования, удалить копии после аудита. Владелец: LEG.

## O-04 · План и сроки (📝)

Предлагаемая последовательность:
1. Kickoff + подписание NDA + выдача read-only доступа.
2. Изучение data room (разделы 00–16).
3. Разбор кода и воспроизведение прогона (тестовые данные).
4. Проверка RLS/безопасности (S-1…S-10), приватности (раздел 11).
5. Интервью с командой по процессам (при необходимости).
6. Отчёт аудитора + совместная приоритизация митигаций.

Контактные лица и сроки — заполнить (PO). Основной контакт: `hello@weexp.agency`.
