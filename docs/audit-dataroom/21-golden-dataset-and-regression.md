Отвечает на замечание №5. Реализовано в коде: `worker/golden/` (schema + cases) +
`worker/scripts/goldenCheck.ts`.

## Что это

Набор эталонных (обезличенных) e-commerce-кейсов с заранее проверенными ожиданиями:
наблюдения обхода, диапазоны метрик, обязательные темы находок, запреты на выдумки
(`mustNotContain`). После изменения модели/промпта/методологии/скоринга прогоняем набор →
before/after regression. Golden — живой бенчмарк: «как только перестаёшь обновлять — начинаешь
измерять прошлое» (Langfuse, 2026).

## Как запускать

```bash
# только валидация кейсов
npx tsx scripts/goldenCheck.ts --all
# сверка реального прогона с кейсом
npx tsx scripts/goldenCheck.ts --case golden/cases/case-001-lanavitta-t1.json --run results/<id>
```

Раннер сверяет `audit-run-record.json` + тексты находок с ожиданиями, печатает PASS/FAIL и
возвращает код ≠0 при провале hard-проверки (для CI-гейта).

## Размер набора (по стадиям)

Источники расходятся в цифрах; принят ярусный таргет (Langfuse/Statsig/QASkills, 2026):

| Ярус | Кейсов | Назначение |
|------|--------|-----------|
| Smoke | 20–50 | Ловит грубые регрессии |
| Per-feature | 50–100 (≈40–60 core + 15–25 edge) | Покрытие фичи |
| Confidence | 100–500 | Статистическая значимость |
| Production-mirror | 100–1000 | Зеркало продакшена |

Правило: **«60 осмысленных кейсов лучше 500 случайных»**; растить набор — из каждого
реального провала добавлять кейс. Дедуп против обучающих данных документировать (контаминация).

## Definition of Done для кейса

Кейс готов, когда: вход зафиксирован; ожидания получены из **проверенного человеком**
прогона (reviewer заполнен); наблюдения помечены `verified:true` с источником; заданы
`mustNotContain`; данные обезличены (без реального домена/PII/денег).
