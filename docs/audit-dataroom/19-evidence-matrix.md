Центральный артефакт audit-ready (замечание №2 внешнего аудита). Превращает
«документ → описание → статус» в **«утверждение → доказательство → источник → проверка →
владелец → статус → риск»**. Практика SOC 2/ISO: контроль↔доказательство — связь
многие-ко-многим; одно доказательство закрывает несколько утверждений
(источник: amitkoth.com/soc-2-control-evidence-mapping, secureframe.com, 2026).

**Легенда проверки:** ✅ verified (проверено на артефакте) · 🟡 partial · ⛔ gap (нет).
**Метод:** Code = проверка кода/конфигурации · Run = артефакт прогона · Doc = документ ·
Test = запуск теста/скана · Vendor = аттестация субпроцессора.

## Как читать матрицу

- **✅** — доказательство существует и проверено на артефакте *сейчас*.
- **🟡** — механизм/документ есть, но не протестирован/не заполнен до конца.
- **⛔** — пробел; связанный риск указан, владелец назначен, план — в соответствующем разделе.

Сводка: из 18 контролей — **7 ✅, 7 🟡, 4 ⛔**. Пробелы концентрируются в юр/приватности/
BCDR — это ожидаемо (данные у владельцев) и отражено в реестре рисков (раздел 15).

## Правила поддержания (Definition of Done для строки)

Строка переходит в ✅ только когда: артефакт существует и доступен по ссылке; метод
проверки указан; проверку выполнил не автор (separation of duties); дата проверки
зафиксирована; связанный риск обновлён. Обновление — ежемесячно и при каждом релизе.
