# {{BRAND}} — сайт на MODX Revolution

Новый отдельный сайт (не weexp.agency) для того же типа бизнеса —
операционный e-commerce-консалтинг: аудит / консалтинг / управління,
кейси, калькулятор, ресурси (блог), бриф. Дизайн, структура и дерево —
свои, не копия weexp.agency (см. `SITEMAP.md`).

Целевая площадка — **MODX Revolution** (PHP CMS с чанками/сниппетами/TV
и админкой для редактирования контента), поэтому весь фронтенд собран
как набор MODX-ресурсов, а не SPA.

## Что в этой папке

```
modx-site/
├── SITEMAP.md              финальное дерево страниц, URL, навигация
├── CONTENT_PLAN.md         план контента по каждой странице (черновики UA)
├── modx/
│   ├── tvs.md              таблица Template Variables
│   ├── templates/          HTML-шаблоны ресурсов (Template) — 11 шт.
│   ├── chunks/             переиспользуемые блоки (Chunk) — 8 шт.
│   └── snippets/           PHP-логика (Snippet) — пример кастомного сниппета
```

## Как это встанет в MODX

1. **Templates** (`modx/templates/*.tpl.html`) — создать в MODX Manager
   (Elements → Templates → New Template), вставить содержимое файла как есть.
   Имя файла без `.tpl.html` = имя шаблона в MODX.
2. **Chunks** (`modx/chunks/*.chunk.html`) — Elements → Chunks → New Chunk,
   имя без `.chunk.html`.
3. **Snippets** (`modx/snippets/*.php`) — Elements → Snippets → New Snippet,
   вставить PHP-код (без открывающего `<?php`, MODX добавляет сам).
4. **TVs** — создать по таблице в `modx/tvs.md`, привязать к шаблонам
   в указанной там колонке «Шаблоны».
5. **Resource tree** — создать ресурсы по дереву в `SITEMAP.md`: контейнеры
   (`isfolder=1`) для хабов (`Симптоми`, `Как ми працюємо`, `Результати`,
   `Ресурси`), обычные ресурсы — для листовых страниц. Alias каждого ресурса
   = последний сегмент URL из таблицы в `SITEMAP.md`.
6. **Навигация** — `Header.chunk.html` сейчас со статичным списком ссылок
   (проще для старта и ревью). Когда дерево устоится, заменить на
   `[[pdoMenu]]` (или собственный сниппет `Menu.php`) — тогда пункты меню
   будут подтягиваться из дерева ресурсов автоматически.

## Что нужно от владельца, чтобы продолжить

- **Название бренда** — сейчас везде плейсхолдер `{{BRAND}}`.
- **Логотип и цветовая палитра** — дизайн пока не привязан к конкретным
  цветам/шрифтам (это отдельная задача после утверждения контента).
- **Реальные кейсы** — 4–6 анонимизированных историй по структуру
  Було → Проблема → Рішення → Результат → Уроки (TV на `CaseDetail`,
  см. `modx/tvs.md`). Черновик и заполнение — по факту от владельца, так же
  как это было собрано для weexp.agency.
- **Контакты для формы брифа/заявки** — куда слать лиды (email/Telegram).

## Локальная разработка/превью MODX

MODX требует PHP + MySQL/MariaDB. Быстрый локальный старт (не входит в этот
каркас, делается по потребности):

```bash
composer create-project modx/revolution modx-local
# либо DDEV: ddev config --project-type=php --docroot=modx-local && ddev start
```

Дальше — обычная установка MODX (`setup/`), после которой можно вручную
или через `xPDOTransport`-пакет импортировать содержимое `modx/`.
