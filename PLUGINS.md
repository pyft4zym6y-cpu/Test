# Плагины и инфраструктура — что подключено и где применяем

Пять инструментов из запроса делятся на **две категории** по способу подключения.
Это важно: три из них — плагины Claude Code (конфигурируются файлом и активируются
в самом Claude Code), а два — **внешняя инфраструктура** (прокси/шлюз, которые
запускаются отдельным процессом и к которым мы подключаем воркер аудита).

| # | Инструмент | Категория | Что делает | Где применяем |
|---|---|---|---|---|
| 1 | [claude-plugins-official](https://github.com/anthropics/claude-plugins-official) | Плагин-маркетплейс CC | Официальный каталог Anthropic (сотни плагинов) | Источник плагинов для команды |
| 2 | [agents-observe](https://github.com/simple10/agents-observe) | Плагин CC (+MCP) | Живой дашборд хуков: видно, что делают агенты | Наблюдение за прогонами воркера и суб-агентами |
| 3 | [claude-mem](https://github.com/thedotmack/claude-mem) | Плагин CC (+MCP) | Память между сессиями | Сохранение контекста аудит-движка между сессиями |
| 4 | [OmniRoute](https://github.com/diegosouzapw/OmniRoute) | Инфраструктура (npm-шлюз) | Роутинг 338+ провайдеров, фолбэк, сжатие токенов | Шлюз перед Anthropic API воркера |
| 5 | [headroom](https://github.com/headroomlabs-ai/headroom) | Инфраструктура (SDK/прокси/MCP) | Сжатие контекста до отправки в LLM | Сжатие крупных payload обхода в воркере |

> **Важно про среду.** Часть этих инструментов поднимает локальные серверы
> (дашборды `localhost:4981`, `localhost:20128`) и регистрирует хуки. Они
> предназначены для **вашего локального Claude Code / машины**, где движок
> запускается постоянно. В облачной веб-сессии Claude Code контейнер эфемерный —
> дашборды из него недоступны, а глобально установленные npm-пакеты не переживают
> перезапуск. Поэтому durable-часть, которую я закоммитил, — это **конфиг и
> проводка** (`.claude/settings.json`, `worker/src/headroom.ts`, env-переменные);
> сами серверы поднимаются в вашей постоянной среде по инструкциям ниже.

## Категория A. Плагины Claude Code

Подключаются через `/.claude/settings.json` (уже закоммичен). Регистрация
маркетплейса — безопасна (это просто ссылка на git-репозиторий, код не
исполняется). Активация плагина (`enabledPlugins`) — уже запускает его хуки/MCP
при старте будущих сессий Claude Code на этом репозитории.

Что записано в `.claude/settings.json`:

```jsonc
{
  "extraKnownMarketplaces": {
    "claude-plugins-official": { "source": { "source": "github", "repo": "anthropics/claude-plugins-official" } },
    "agents-observe":          { "source": { "source": "github", "repo": "simple10/agents-observe" } },
    "thedotmack":              { "source": { "source": "github", "repo": "thedotmack/claude-mem" } }
  },
  "enabledPlugins": {
    "agents-observe@agents-observe": true,   // наблюдение
    "claude-mem@thedotmack": true            // память
  }
}
```

### 1) claude-plugins-official — каталог плагинов

Официальный маркетплейс Anthropic (сотни плагинов от партнёров). Мы его
**зарегистрировали как источник** — отдельные плагины из него ставятся по одной
команде, а не оптом (включать сотни хуков нельзя). Активировать нужный плагин:

```
/plugin install <имя>@claude-plugins-official
# или интерактивно:  /plugin  →  Discover
```

Либо декларативно — добавить строку в `enabledPlugins` того же
`.claude/settings.json`, например `"chrome-devtools-mcp@claude-plugins-official": true`.

**Рекомендованные для нашего аудит-движка** (ставить по мере надобности):

| Плагин | Зачем нам |
|---|---|
| `chrome-devtools-mcp` | Управление реальным Chrome — усиливает обход/journey-тесты |
| `firecrawl` | Промышленный краулинг/скрейп страниц клиента |
| `playwright`-совместимые / `browser-use` | Автоматизация браузера для проверок |
| `code-review` | Ревью кода воркера (у нас уже есть скилл `/code-review`) |
| `frontend-design` | Помощь по вёрстке отчётов/консоли |
| `exa`, `context7` | Внешний поиск и актуальная документация в контексте |

> ⚠️ **Доверие.** Anthropic курирует каталог, но не контролирует MCP-серверы
> внутри сторонних плагинов. Перед активацией любого плагина проверьте, что
> доверяете источнику: плагин может нести MCP-сервер и хуки, которые исполняются.

### 2) agents-observe — наблюдение за агентами

Плагин + MCP + локальный дашборд. Захватывает **каждое** хук-событие Claude Code
(вызовы инструментов, промпты, жизненный цикл суб-агентов) и стримит в дашборд
`http://localhost:4981`.

- **Где применяем.** Когда воркер аудита гоняет пайплайн и я разворачиваю
  суб-агентов (как для диаграмм по отчётам) — в дашборде видно всю иерархию
  «родитель → суб-агент», какие файлы читаются, какие инструменты вызываются,
  полные payload. Это отладка «что реально делает автономный прогон».
- **Активация локально:** плагин уже включён в `settings.json`; при следующем
  старте `claude` в этом репозитории он поднимется сам. Дашборд — на :4981.
- **Каветы:** нужен Node; дашборд-сервер локальный (в облачном контейнере не
  виден). Это инструмент для вашей рабочей машины.

### 3) claude-mem — память между сессиями

Плагин + MCP. Автоматически снимает наблюдения об использовании инструментов,
делает семантические резюме и **подкладывает релевантный контекст в новые
сессии**. Поиск по памяти — скилл `mem-search`; приватные куски помечаются
`<private>`.

- **Где применяем.** Аудит-движок разрабатывается длинными сессиями (реестр,
  премиум-агенты, диаграммы…). claude-mem держит «долгую память» о решениях и
  структуре проекта между сессиями — меньше потерь контекста после компакта.
- **Активация:** включён в `settings.json`. По README для полной установки хуков
  на локальной машине выполните один раз:
  ```
  npx claude-mem install
  ```
  (Требуется Node 20+, Bun; SQLite в комплекте.)
- **⚠️ Приватность.** claude-mem пишет наблюдения (в т.ч. фрагменты данных
  клиентов, которые проходят через сессию) в **локальную SQLite**. Для чужих
  аудитов помечайте чувствительное `<private>` или держите память выключенной на
  клиентских прогонах. Если не хотите включать это на весь репозиторий/команду —
  перенесите строку `claude-mem@thedotmack` из `settings.json` в личный
  `.claude/settings.local.json` (не коммитится).

## Категория B. Инфраструктура (шлюз/сжатие) для воркера

Это **не** плагины Claude Code — это отдельные процессы. К воркеру аудита
(`worker/`) они подключаются через переменные окружения и точку интеграции в
коде.

### 4) OmniRoute — AI-шлюз перед Anthropic API

npm-шлюз на `localhost:20128`: роутинг по 338+ провайдерам, авто-фолбэк при
исчерпании квоты/сбое, сжатие токенов, 19 стратегий маршрутизации, локальный
дашборд. Совместим с Anthropic SDK (эндпоинт `/v1`).

**Как подключаем к воркеру (без единой правки кода).** Клиент в
`worker/src/anthropic.ts` создаётся как `new Anthropic()` — SDK сам читает
`ANTHROPIC_BASE_URL`. Достаточно:

```bash
# 1) поднять шлюз (на вашей/серверной машине, не в эфемерном контейнере)
npm install -g omniroute && omniroute            # → http://localhost:20128

# 2) направить воркер на шлюз (env воркера / Railway)
export ANTHROPIC_BASE_URL="http://localhost:20128/v1"
# ANTHROPIC_API_KEY остаётся вашим ключом; роутинг/фолбэк делает OmniRoute
```

- **Где применяем.** Перед всеми вызовами Claude из аудита (`ask()`,
  `createMessage()`, веб-поиск-агенты, премиум-слой). Даёт: устойчивость к 429/529
  (фолбэк на другого провайдера вместо падения аналитического слоя), контроль
  затрат, единый дашборд расхода токенов по прогонам.
- **Каветы.** Меняете дата-флоу: запросы идут через локальный шлюз — держите его
  рядом с воркером и следите за доступностью. Для прод-надёжности можно оставить
  прямой Anthropic как дефолт и включать OmniRoute только там, где нужен фолбэк.

### 5) headroom — сжатие контекста (уже проброшен в воркер)

Сжимает объёмные payload (DOM обхода, блоки страниц, логи, RAG) **до** отправки в
LLM: заявлено 60–95% экономии токенов на JSON, 15–20% на кодовых агентах, локально.

**Что уже сделано в коде.** Добавлен модуль `worker/src/headroom.ts` и точка
вызова в `worker/src/anthropic.ts` (`ask()` сжимает пользовательский payload перед
отправкой — системный промпт не трогается). Сделано **безопасно по умолчанию**:

- выключено, пока не задан `HEADROOM_COMPRESS=1`;
- зависимость грузится динамически — её отсутствие не ломает сборку;
- результат принимается, только если это непустая строка **короче** исходной,
  иначе — молчаливый откат к оригиналу; любая ошибка → оригинал.

Поэтому по умолчанию поведение воркера **не меняется ни на байт**. Включение:

```bash
cd worker && npm i headroom-ai      # поставить SDK
export HEADROOM_COMPRESS=1          # включить сжатие
export HEADROOM_MIN_LEN=2000        # (опц.) порог: мелкие payload не сжимаем
```

- **Где применяем.** Самые толстые вызовы — контент-аудит по всем страницам,
  причинная карта, синтез, где в Claude уходят большие срезы DOM/блоков. Там
  экономия токенов максимальна.
- **Альтернатива.** headroom умеет работать и как прокси/MCP-сервер — но для нас
  точечное сжатие payload в `ask()` чище и безопаснее, чем заворачивать весь
  трафик.
- **Каветы.** Сжатие меняет текст, уходящий в модель. Мы держим его opt-in и
  применяем только к пользовательской нагрузке (не к выверенным системным
  промптам). Прогоните контроль качества отчётов с включённым флагом, прежде чем
  ставить его в прод.

## Чек-лист активации

**В Claude Code (локально, у вас на машине):**
1. Открыть репозиторий — `.claude/settings.json` уже регистрирует 3 маркетплейса и
   включает `agents-observe` + `claude-mem`.
2. `npx claude-mem install` — один раз, чтобы доустановить хуки памяти.
3. Запустить `claude`; дашборд наблюдения — `http://localhost:4981`.
4. По надобности: `/plugin install <имя>@claude-plugins-official`.

**Для воркера аудита (env вашей среды / Railway):**
5. OmniRoute: поднять `omniroute`, задать `ANTHROPIC_BASE_URL=http://localhost:20128/v1`.
6. headroom: `npm i headroom-ai` в `worker/`, задать `HEADROOM_COMPRESS=1`.

**Безопасность.** Пункты 1–3 запускают сторонние хуки/MCP в будущих сессиях.
Это осознанное решение по доверию; для клиентских прогонов учитывайте приватность
claude-mem (см. выше).
