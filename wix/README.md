# Дубль админки на Wix

`weexp-admin-wix.html` — один самодостаточный файл: разметка, стили и логика внутри.
Вставляется в Wix как есть, ничего собирать и деплоить не нужно.

## Как поставить (5 минут)

1. Редактор Wix → **Add (+) → Embed Code → Embed HTML** (в Wix Studio: **Embed → Custom Code / HTML iframe**).
2. В настройках элемента выбрать **Code**, а не *Website address*.
3. Открыть `weexp-admin-wix.html`, скопировать **всё содержимое файла целиком** и вставить в поле.
4. Растянуть элемент на всю ширину и задать высоту **900–1200 px** — Wix не умеет
   подгонять высоту iframe под содержимое, поэтому панель скроллится внутри себя.
5. Страницу с этим элементом закрыть паролем в Wix (**Page Settings → Permissions → Password**)
   и убрать из меню. Это не защита данных — данные защищает RLS, — а гигиена: чтобы
   форма входа не висела на публичной странице.
6. Publish.

Обновление: заменить содержимое поля новой версией файла. Отдельного деплоя нет.

## Что внутри работает

- Вход теми же аккаунтами, что и на `weexp.agency/admin` (e-mail + пароль Supabase).
- **Заявки** — доска по стадиям, карточка заявки, смена стадии (пишет в базу по-настоящему).
- **Клієнти** — список из `diagnostics`, стадия воронки, результат экспресс-аудита,
  статусы доступов, проекты.
- **Дашборд** — счётчики по стадиям.
- Поиск по любой вкладке, выгрузка видимого списка в CSV.
- Автообновление раз в 2 минуты, только когда вкладка на экране.

## Чего в дубле нет — и почему это не чинится настройками Wix

Эти разделы боевой админки ходят в наши серверные функции `/api/*` на домене
weexp.agency. Страница на Wix — другой домен, доступа к ним у неё нет:

| Раздел | Почему не переносится |
|---|---|
| Команда и роли | `/api/team` работает под серверным ключом Supabase. В браузер такой ключ не кладут никогда — он даёт полный доступ к базе мимо всех правил. |
| Запуск воркера аудита, SLA, AI-черновики проектов | серверные функции + ключи Anthropic/GA4 |
| Создание проекта из заявки, файлы клиента | требует записи в несколько таблиц и Storage под правами админа |

Всё это остаётся в основной админке; из карточек дубля стоят прямые ссылки туда.

Отдельно: **вставить weexp.agency/admin в Wix через «Embed a site» нельзя.** Наш
заголовок `Content-Security-Policy: frame-ancestors 'self'` (корневой `vercel.json`)
запрещает встраивание сайта в чужие домены — это защита от кликджекинга, и снимать
её ради Wix не стоит. Поэтому дубль сделан копией интерфейса, а не рамкой.

## Безопасность

- В файле лежит только **публичный** ключ Supabase (`sb_publishable_…`) — тот же,
  что уже находится в JS-бандле сайта. Он публичен по устройству: доступ решает RLS
  на стороне базы, а не секретность ключа.
- Серверный ключ (service-role) в файл не попадает; это проверяется тестом
  `weexp-site/src/system/admin/__tests__/wixMirror.test.ts` — он же ловит расхождение
  названий стадий и адреса проекта Supabase между дублем и приложением.
- Права пользователя дубль не выдаёт и не расширяет: без роли запросы вернут пусто,
  и панель об этом прямо напишет.

## Требования к базе (уже выполнены для боевой админки)

- SELECT-политика RLS для админов на таблицы `leads` и `diagnostics`;
- UPDATE-политика на `leads` — иначе смена стадии не сохранится
  (панель покажет это текстом, а не сделает вид, что сохранила).

## Если панель пустая или не грузится

- «Код панелі не завантажився» — браузер не получил библиотеку Supabase с
  `cdn.jsdelivr.net` (блокировщик, корпоративный фильтр). Проверить сеть, перезагрузить.
- Пустые списки с красной плашкой — текст ошибки от Supabase: обычно нет роли у
  аккаунта или нет SELECT-политики.
- Пустые списки без плашки — данных действительно нет.
- Safari с «Prevent cross-site tracking» может не дать iframe сохранить сессию:
  панель предупреждает об этом на экране входа, вход будет держаться до перезагрузки.
