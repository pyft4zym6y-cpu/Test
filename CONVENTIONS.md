# Конвенції репозиторію weexp

Короткий документ про рішення, які інакше кожного разу приймаються заново.

## Мова

| Де | Мова | Чому |
|---|---|---|
| Інтерфейс сайту | українська + англійська | дві версії, `seo-data.json` — єдине джерело мета |
| Інтерфейс адмінки й кабінету | **українська** | внутрішній інструмент української команди |
| Коментарі в коді | **українська** | щоб не тримати в голові дві мови на одному екрані |
| Повідомлення комітів | англійська | звична мова git-історії |
| SQL-міграції в `docs/` | українська в коментарях | їх читає команда, не зовнішній підрядник |

Історично коментарі змішані (укр/рос) — це наслідок того, що частини системи
писалися в різний час. Нове пишемо українською; старе перекладаємо лише коли
й так торкаємось файлу, окремим комітом не ганяємо.

## Дані

- **Джерело правди** — `diagnostics.data` (jsonb) на клієнта. Таблиці `p_*` —
  проекція для аналітики, писати в них не можна (їх перебудовує тригер).
- **Будь-який запис** у `diagnostics` іде через `mutateRecord()` у `lib/supa.ts`:
  він перевіряє, що рядок реально оновився (інакше RLS «мовчки успішний»),
  тримає оптимістичну конкурентність і пише подію в журнал.
- **Статуси не зберігаються.** Стадія аудиту/проєкту виводиться з даних
  (`auditRequests.ts → auditStatusOf`). Якщо стадія «неправильна» — правити
  треба дані або функцію, а не додавати поле статусу.
- **Ролі** перевіряються двічі: у UI (`can()`) для зручності і в базі
  (`weexp_can_write()` у RLS) для безпеки. Ключ Supabase публічний — сама лише
  перевірка в React нічого не захищає.
- **`AC-NN` — два різні простори імен, не одне.** Кабінет
  (`weexp-site/src/data/accessCatalog.ts`) і портал
  (`portal/src/data/accesses.json`) роздають номери незалежно, і з 32 спільних
  19 означають різні системи (AC-22: «остатки і закупівельні ціни» в порталі,
  «CDP / програма лояльності» в кабінеті). Звести їх — це міграція даних
  (`accessLog`, `access_status`, шляхи в Storage `uploads/<client>/<access_id>/`)
  і питання, чи потрібні два клієнтських входи взагалі. До того рішення діє
  правило: **ідентифікатор не показуємо людині без назви системи поруч**, і
  жоден модуль не імпортує обидва каталоги. Тримає
  `admin/__tests__/accessNamespace.test.ts`.

## Межі масштабу

Названі явно, щоб не впертись у них раптово:

| Що | Межа | Що робити далі |
|---|---|---|
| Список клієнтів | сторінки по 200, пошук у браузері | понад ~500 — серверний пошук (`tsvector` над `p_*`) |
| Наскрізний пошук | по полях полегшеного запису; відповіді анкети не входять | те саме |
| Маржа й цикл на дашборді | рахуються в браузері по всіх завантажених рядках | понад ~500 — серверний агрегат |
| `admin_events` | ретенція 12 міс. | індекси є на (at), (user_id, at), (actor, at) |
| `audit_runs` | важкі поля чистяться через 6 міс. | — |
| Realtime | сигнал «щось змінилось» → звичайне перечитання | якщо перечитувань забагато — фільтрувати підписку по клієнту |

## Міграції

Застосовувати в цьому порядку, у Supabase SQL Editor:

1. `docs/admin-roles-and-events.sql` — ролі, журнал дій, RLS
2. `docs/audit-runs.sql` — прогони рушія (потрібні функції з п.1)
3. `docs/entities-projection.sql` — проекція сутностей для аналітики
4. `docs/rate-limit.sql` — ліміт частоти для відкритих форм

Стан застосування видно в адмінці: **Налаштування → Стан бази**.

## Збереження

- **Автозбереження** — тільки через `useAutosave` (`system/admin/useAutosave.ts`):
  дебаунс, `beforeunload`, збереження при демонтажі, стан і кнопка «Повторити».
  Свій `setTimeout` + `void save(...)` писати не можна — саме так втрачалися дані.
- **Результат запису не викидати.** `void savePatchFor(...)` без перевірки — це
  зелений тост поверх відмови RLS. Або `await` з повідомленням, або відкат стану.
- **Map-секції** (`accessLog`, `assessment`, `findingReviews`) писати через
  `mergeMapFor`: `savePatchFor` кладе секцію цілком і затирає правку колеги в
  сусідньому ключі.
- **Діалоги** — `askConfirm` / `askText` з `admin/dialog.tsx`, не нативні
  `confirm/prompt`. Особливо там, де текст побачить клієнт.

## Гроші

Дохід — платежі проєкту (`payments`). Собівартість — тарифні позиції по місяцях
(`tariff[].items[]`: години × ставка). Маржа = оплачено − собівартість; рахує
`money()` в `auditRequests.ts`. Бюджет-матриця (`budget`) — це ПЛАН, у маржу не
входить.

## Тести

`npm test` у `weexp-site/`. Покрито те, що ламається тихо: похідний статус,
фази, SLA. Правило просте — якщо помилка проявляється порожньою колонкою або
неправильним підписом, а не винятком, вона має бути під тестом.
