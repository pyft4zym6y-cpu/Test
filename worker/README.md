# weexp · AI-аудитор Commerce OS (воркер)

Автономный рантайм аудита — «свой воркер» (вариант A): настоящий браузер
(Playwright) + Claude API. Заменяет ручную работу e-com директора/консультанта/
аудитора: обходит сайт, разбирает UX/UI/CRO и контент, сравнивает конкурентов,
копает внешние источники, а на выходе собирает материалы по методологии
Commerce OS (AD-15, мини-отчёты, дорожную карту с Гантом).

Живёт **отдельно** от клиентского портала. Клиент видит только intake-портал и
финальные материалы; сам аудитор ему не показывается.

## Четыре тира полноты данных

Один аудитор работает на любом тире по одной методологии: с ростом тира не
переделывает выводы, а уточняет ячейки и повышает уверенность.

| Тир | Вход | Слой метода | Уверенность |
| --- | --- | --- | --- |
| **T1** | только сайт(ы) клиента + вольный запрос — годится для негласного аудита | L0 внешний обход | ~30 |
| **T2** | + сайты конкурентов + частичные ответы на вопросы | L0 + начало L1 | ~50 |
| **T3** | 80%+: ответы, выгрузки, скрины из аналитики | L1–L2 по выгрузкам | ~75 |
| **T4** | живые доступы (GA4/CRM/реклама) | L1–L3 полный | ~90 |

Модель тиров — `src/tiers.ts`.

## Что уже готово — T1, слой L0 (обход → анализ → материалы)

- **`src/crawl.ts`** — обход сайта настоящим браузером: обнаруживает
  представительные страницы (главная, каталог/PLP, карточка/PDP, корзина),
  гоняет 30 проверок голд-стандарта по **отрендеренному** DOM (видит JS-контент),
  определяет платформу и аналитику, читает robots.txt/sitemap.xml.
- **`src/report.ts`** — детерминированный L0-отчёт наблюдений (без LLM):
  соответствие голд-стандарту, дерево страниц, узкие места, сравнение
  клиент↔конкуренты.
- **`src/method.ts`** — кураторский метод-контекст: ДНК, каркас отчёта (20 секций),
  чертёж AD-15 (10 слайдов), системный промпт аналитика.
- **`src/analyze.ts`** — аналитический слой: Claude по методологии превращает
  обход в структурированный аудит L0 (находки, боли по причинам, конкурентные
  разрывы, недостающие факты, черновой scope, открытые вопросы). Деньги на L0
  не считает — помечает «требует L1».
- **`src/deliverables.ts`** — единая слайд-модель AD-15 (питает Markdown и .pptx)
  и **дорожная карта с диаграммой Ганта** (mermaid). Числа из обхода, структура и
  язык из метода, всё с метками факт/допущение.
- **`src/export/pptx.ts`** — рендер AD-15 в **`.pptx`** (фирменный лаймовый
  акцент, 10 слайдов) через `pptxgenjs`.
- **`src/export/docx.ts`** — рендер аудит-отчёта в **`.docx`** (резюме, точка А,
  находки, боли, конкуренты, узкие места, открытые вопросы) через `docx`.
- **`src/portalEngine.ts`** — **единый источник расчёта**: импортирует чистые
  модули портала (`../portal/src/lib/report`, `engine`, `data/method`) и считает
  Health Score, критические разрывы, решения с трассой «почему» и scope **теми же
  формулами**, что портал — без дублирования. Питается ответами опросника
  (`--answers file.json`, map `{qid: answer}`). На T1 без ответов Health Score =
  «требует опросника» (честно); раскрывается на T2–T3.
- **`src/money.ts`** — **деньги цепной атрибуцией** (порт `gap_calculator.py`, та
  же формула выручки, что `forecast()` портала): недополученный оборот =
  разность двух состояний воронки, вклад рычага = прирост при его подмене
  факт→цель поверх уже применённых. Инвариант **Σ вкладов = потенциал**
  (складывать разрывы нельзя). Baseline — `--baseline file.json`
  (`{ "levers": {traffic,cr,aov,pay,redeem,base,repeat,opr:{fact,target}}, "extra": [{name,monthly}] }`).
- **`src/agent.ts`** — агентный обход (флаг `--agentic`): Claude сам добирает
  факты через инструменты `crawl_page` (обойти ещё страницу браузером),
  `fetch_url` (скачать внешний источник), `web_search` (поиск в вебе), затем
  сдаёт анализ вызовом `finish`. Это автономность «сам заходит и копает».
  Обёрнут в откат на одношаговый `analyze()` при сбое.
- **`src/run.ts`** — CLI-оркестратор: обход → `dataset.json` + `L0-report.md`,
  затем (при `ANTHROPIC_API_KEY`) анализ → `analysis.json`, `AD-15.md` + **`AD-15.pptx`**,
  `roadmap.md`, **`audit-report.docx`**.

`ANTHROPIC_API_KEY` — ключ Claude (для анализа и материалов); `AUDIT_MODEL` —
модель, по умолчанию `claude-opus-5`.

## Запуск

```bash
npm install
npx playwright install chromium   # на своей инфраструктуре — свой браузер
npm run audit -- --tier 1 --site https://shop.example --request "смотрите, анализируйте"
# конкуренты (T2+):
npm run audit -- --tier 2 --site https://shop.example --competitor https://a.example --competitor https://b.example
# агентный обход (Claude сам добирает факты инструментами):
npm run audit -- --tier 1 --site https://shop.example --agentic
# с ответами опросника (T2+) — движок считает Health Score/разрывы/решения:
npm run audit -- --tier 2 --site https://shop.example --answers ./answers.json
# с baseline (T3+) — деньги цепной атрибуцией в AD-15 и отчёте:
npm run audit -- --tier 3 --site https://shop.example --answers ./answers.json --baseline ./baseline.json
```

Результат — в `results/<домен>-t<тир>-<время>/`.

**Окружения с предустановленным Chromium:** задайте `CHROME_PATH=/путь/к/chrome`
— воркер запустит его вместо скачивания. Прокси берётся из `HTTPS_PROXY`, если задан.

## Дорожная карта модулей (дальше)

1. **Приём выгрузок/скринов (T3)** — парсинг выгрузки заказов и скринов из
   аналитики в ответы/levers автоматически (сейчас baseline подаётся файлом).
2. **Живые коннекторы (T4)** — GA4 уже есть в `portal/api/ga4.js`; дальше CRM и
   рекламные кабинеты по одному.
3. **Оркестрация из портала** — запуск аудита кнопкой из админ-части портала и
   складывание результатов клиенту, а не только CLI.
4. **КП и бюджет** — сборка коммерческого предложения (20 секций RAY.UA) и
   бюджета из cost_base поверх готового аудита.

_Уже есть: агентный обход (`--agentic`), движок портала (`--answers`) и деньги
цепной атрибуцией (`--baseline`) — Health Score, разрывы, решения, scope и
недополученный оборот считаются той же математикой, что в портале/методе._

Методологические чертежи — в `../portal/method/references/`.
