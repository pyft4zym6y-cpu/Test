## 04 · Methods
**Протокол технического SEO-аудита (адаптация seo-audit):** краулинг сайта до 500 страниц с уважением robots.txt, затем разбор по слоям:
1. **Technical** — robots.txt, sitemap, canonical, Core Web Vitals (LCP/INP/CLS), заголовки безопасности.
2. **Content / E-E-A-T** — тонкий контент, читаемость, готовность к цитированию ИИ-системами.
3. **Schema** — детекция и валидация разметки, рекомендации по генерации недостающей.
4. **Sitemap** — структура, полнота, недостающие страницы.
5. **Performance** — измерения LCP/INP/CLS по факту, не по лабораторным данным.
6. **Visual** — скриншоты, мобильное тестирование, зона над сгибом.
7. **GEO (генеративный поиск)** — доступ AI-краулеров, наличие/качество `llms.txt`, цитируемость бренда в ответах генеративных систем. Это прямо закрывает узкое место документа «протокола GEO-мониторинга нет».
8. **Local** — включается условно (GBP-сигналы, NAP-консистентность) для локального/гибридного бизнеса.

Health Score считается по взвешенной сумме 8 слоёв (веса калибруются по нише — берутся из каталога KPI).

**Прямые протоколы через Google Search Console MCP (mcp-gsc, раунд 3 — реальный установленный инструмент, не концепция):**
- `indexing-audit` — снятие 20 самых заметных страниц по показам, batch-инспекция индексации, классификация по вердикту (Indexed / Soft 404 / Not indexed / Canonical mismatch), приоритизация: критично — страницы с показами, но не в индексе.
- `cannibalization-check` — поиск запросов, где 2+ страницы конкурируют за одну и ту же выдачу, с рекомендацией на консолидацию (canonical/редирект/объединение контента).
- `seo-weekly-report` — регулярный отчёт по позициям/кликам/показам.
- `content-opportunities` — запросы с высокими показами и низким CTR/позицией — кандидаты в приоритет контент-плана.
Эти протоколы требуют реального доступа к Search Console (MCP-сервер `search-console-mcp`/`mcp-gsc`, см. `docs/mcp-and-plugins-map-round3.md`) — без доступа выполняются вручную по той же логике через выгрузку.

## 05 · Evidence
Вес доказательства — по общей иерархии (см. `knowledge/base/04-crosscheck/evidence-hierarchy.md`).

## 06 · Standards
Технический эталон — по актуальным Core Web Vitals порогам Google (LCP<2.5s, INP<200ms, CLS<0.1). Эталон разметки — Schema.org JSON-LD по типу страницы. Источник метода: seo-audit, уровень доказательства 4 (внешняя методика без нашей проверки на клиентских данных).

## 07 · Findings
Пишутся по единому контракту находки (см. `knowledge/registries/findings-contract.md`). Единица обмена с synthesis-os.

## 08 · Outputs
`SEO-01 Health Score Report`, `SEO-02 GEO Citability Report` (новый артефакт), `SEO-03 Technical Issues Backlog`.

## 09 · Quality Gates
Определяется по мере заполнения Methods/Standards. Пример условия: AQC выше порога, все блоки эталона разобраны.

## 10 · Metrics
Срок проявления эффекта — обязательное поле, заполняется по мере прогонов.

## 11 · Maturity
5 уровней: нет процесса · чек-лист · стандарт · измеряется · данные.

## 12 · Dependencies
- **Обратные · кто зависит от нас:** `merchandising-os` — при изменении наших Outputs или контракта находки эти скилы обязаны быть уведомлены
- **Входящие:** data-os
- **Исходящие:** content-os (требования к текстам)

## 13 · Аудит-модуль
**Модуль 05 · Внешний поиск и цитируемость.** Основной слой доступа: **L0**.
Чек-лист L0: индексация и рендеринг; архитектура каталога и глубина вложенности; видимость по категорийным и товарным кластерам; каннибализация; разметка; hreflang при нескольких рынках; присутствие в ответах генеративных систем по ключевым запросам.
L2: Search Console, логи сервера, история позиций.
Выход в отчёт: карта видимости, разрывы архитектуры, оценка недобранного спроса в трафике и деньгах.
## 14 · AI Layer
Профиль агента заполняется последним — от протоколов, а не наоборот.
