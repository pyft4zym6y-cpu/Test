### Протокол запаса и точки перезаказа · принят через карантин, прогон RUN-01
Источник: `external/product-os/inventory-demand-planning`. Уровень **E5-M** — выводимое утверждение, проверяется пересчётом, а не выборкой.

1. Считать позицию запаса как `IP = на складе + в пути − отложено − зарезервировано`. Перезаказ по остатку на складе без учёта того, что уже в пути, даёт двойной заказ.
2. Страховой запас при стабильном сроке поставки: `SS = Z × σ_d × √(LT + RP)`. **Ограничение применимости:** формула верна только для нормально распределённого стационарного спроса. Для позиций с большим числом нулевых периодов она не работает — там нужен метод Кростона и бутстрап распределения.
3. При вариативном сроке поставки: `SS = Z × √(LT_avg × σ_d² + d_avg² × σ_LT²)` — учитывает дисперсию и спроса, и срока.
4. Z по уровню сервиса: 90% → 1.28, 95% → 1.65, 99% → 2.33.
5. **Исправление источника.** Источник утверждает, что переход с 95% на 99% «почти удваивает» страховой запас. Пересчёт: 2.326 / 1.645 = 1.41, то есть **+41%, а не удвоение**. Утверждение принято с исправлением, преувеличение занесено в реестр антипаттернов как типовой дефект вендорского материала.
6. Перед принятием уровня сервиса — посчитать стоимость запаса, которую он требует. Уровень сервиса выбирается ценой, а не желанием.

## 13 · Аудит-модуль
**Модуль 08 · Ассортимент и данные о товаре.** Основной слой доступа: **L0**.
Чек-лист L0: ширина и глубина ассортимента по категориям; полнота атрибутов в карточках (доля заполненных по выборке); наличие товаров без остатка в выдаче; дубли и склейки; сопоставимость с ассортиментом конкурентов по товарным методам.
L2: выгрузка каталога целиком, ABC и XYZ, оборачиваемость, поставщики и сроки.
Выход в отчёт: доля заполненности атрибутов по категориям, разрыв ассортимента, находки качества данных — они же вход для фасетов merchandising-os.
