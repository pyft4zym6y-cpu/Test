# Пакеты знаний — как добавлять свои методички (без кода)

Любой `.md`-файл в этой папке аудитор **сам подмешивает** в анализ как
дополнительный метод-контекст. Чтобы добавить своё знание (скилл, чек-лист,
стандарт, тон подачи, отраслевую специфику) — **положите сюда файл** и
запушьте в ветку. Railway пересоберёт, и следующий аудит его учтёт.

Кода писать не нужно. Это «путь Б»: знание вплетается в машину файлом.

## Формат файла

Начните файл с необязательного блока настроек (frontmatter):

```
---
title: Короткое имя пакета
scope: analyze, uxui, prototype
---

Дальше — сам текст методички в свободной форме (markdown).
```

- **title** — как пакет назовётся в контексте (по умолчанию — имя файла).
- **scope** — где подмешивать. Значения:
  - `analyze` — главный аудит (находки, боли, scope);
  - `uxui` — UX/AQC-разбор страниц;
  - `prototype` — сверка композиции с эталоном;
  - `all` или пусто — везде.

Без frontmatter файл подмешивается **везде** (`all`).

## Правила

- Один файл ≈ до 20 000 символов (длиннее — усекается). Дробите на несколько.
- Всего на один вызов подмешивается до ~60 000 символов — самые нужные пакеты
  держите короткими и по делу.
- `README.md` игнорируется (не подмешивается).
- При конфликте с базовым методом приоритет у базового; расхождение отмечается.

## Проверить, что пакет «виден»

Откройте `…/health` вашего сервера — поле `knowledge` показывает число
загруженных пакетов. Выросло на 1 после добавления файла — значит подхватился.

## Что сюда класть, а что — нет

- **Класть:** знание и правила (эталоны, чек-листы, тон, отраслевые нюансы,
  playbook-логика словами).
- **Не класть:** новые действия (новый источник данных, коннектор, парсер
  файла) — это требует кода, делается отдельно.
