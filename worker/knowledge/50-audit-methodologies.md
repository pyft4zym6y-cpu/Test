# 50 · Методології та еталонні стандарти аудиту (авторитетні джерела)

Цей пакет закриває методологічні прогалини рушія: кожен розділ — стандарт або
framework з першоджерела, з порогами, формулами та правилами застосування.
Використовуй як довідник під час аналізу: цитуй назву стандарту в знахідках
(«за порогами Google CWV…», «за методологією Baymard…») — це підвищує довіру
і робить висновок перевірюваним.

## 1. Web performance — Google Core Web Vitals (web.dev)
- LCP (Largest Contentful Paint): добре ≤ 2.5s, погано > 4.0s (75-й перцентиль, мобайл).
- INP (Interaction to Next Paint, замінив FID у 2024): добре ≤ 200ms, погано > 500ms.
- CLS (Cumulative Layout Shift): добре ≤ 0.1, погано > 0.25.
- TTFB орієнтир ≤ 800ms. Оцінюй польові дані (CrUX) вище лабораторних (Lighthouse).
- Правило знахідки: повільний LCP на PDP/лістингу → прямий вплив на конверсію; посилайся на дослідження Deloitte/Google «0.1s ≈ +8% конверсії в retail».

## 2. Checkout та e-commerce UX — Baymard Institute
- Середня частка покинутих кошиків ≈ 70% (метадослідження Baymard).
- Топ-причини відмов: додаткові витрати на доставку/податки, примусова реєстрація, задовгий/складний checkout, невидимість повної вартості наперед, недовіра до сайту з карткою.
- Еталон: guest checkout обовʼязковий; ≤ 12–14 полів форми; вартість доставки видно до checkout; індикатор кроків; автозбереження кошика.
- PDP-еталон: ≥ 6 фото, відгуки з розподілом оцінок, наявність/строк доставки над fold, повернення описане біля CTA.

## 3. Доступність — WCAG 2.2 AA (W3C)
- Контраст тексту ≥ 4.5:1 (великий текст ≥ 3:1); фокус видимий; таргети ≥ 24×24 CSS px;
  форми з label; альтернативи для зображень; навігація з клавіатури.
- В ЄС діє European Accessibility Act (EAA, з 28.06.2025) — e-commerce у скоупі; невідповідність = юридичний ризик, не лише UX.

## 4. SEO / GEO / AEO
- E-E-A-T (Google Search Quality Rater Guidelines): досвід, експертиза, авторитетність, довіра — сторінки «Про нас», автори, відгуки, зовнішні згадки.
- Технічна база: індексованість (robots, sitemap, canonical), структуровані дані schema.org (Product, Offer, Review, Organization, FAQ), hreflang для мультимови.
- GEO/AEO (оптимізація під AI-відповіді): llms.txt, чіткі фактологічні блоки, FAQ-розмітка, цитованість бренду в зовнішніх джерелах.
- Правило: без GSC-даних не стверджуй про трафік — тільки про технічний стан.

## 5. Юніт-економіка (формули — фіксований канон)
- Contribution margin = AOV × валова маржа − змінні витрати на замовлення (доставка, пакування, платіжка, повернення).
- CAC рахуємо ТІЛЬКИ на нових клієнтів: CAC = маркетинг-витрати / нові клієнти.
- LTV (когортний) = Σ contribution margin за життя когорти; швидка оцінка = AOV × маржа × середня к-ть покупок. Здорове LTV:CAC ≥ 3:1; payback ≤ 12 міс.
- MER (marketing efficiency ratio) = увесь виторг / увесь маркетинг-бюджет — контроль зверху над канальними ROAS.
- CCC (cash conversion cycle) = DIO + DSO − DPO; для e-commerce критичний DIO (оборотність складу).

## 6. Retention / CRM
- RFM-сегментація (Recency, Frequency, Monetary) — базовий канон сегментів: champions, loyal, at-risk, hibernating; під кожен сегмент — свій сценарій.
- Email deliverability: SPF + DKIM + DMARC обовʼязкові (Gmail/Yahoo bulk-sender rules 2024: DMARC мінімум p=none, one-click unsubscribe, spam rate < 0.3% у Postmaster).
- Метрики: repeat rate 90/365 днів, час між 1-ю та 2-ю покупкою, частка виторгу з CRM-каналів (орієнтир 25–35% для зрілого D2C).
- NPS / CSAT / CES — три різні інструменти: лояльність / задоволеність транзакцією / зусилля; не підміняти одне одним.

## 7. Пріоритезація знахідок
- ICE = Impact × Confidence × Ease; RICE = (Reach × Impact × Confidence) / Effort.
- У роадмапі хвилями: Wave 1 = quick wins (ICE високий, залежностей нема), Wave 2 = фундамент (аналітика/дані), Wave 3 = масштабування. Кожна задача має Owner, Effort, залежності — інакше це не роадмапа, а список побажань.

## 8. Стратегія та бренд
- JTBD (Jobs-to-be-Done, Christensen/Ulwick): формулюй сегменти через «роботу», яку наймають продукт виконати, а не через демографію.
- CBBE (Keller): salience → performance/imagery → judgments/feelings → resonance; аудит бренду = перевірка кожного рівня доказами (брендовий пошук, direct-трафік, повторні покупки, UGC).
- Порівняння з конкурентами — тільки спостережувані факти (ціни, асортимент, доставка, контент), без вигаданих часток ринку.

## 9. Операції та склад
- Safety stock = z × σ(попиту за lead time); reorder point = середній попит × lead time + safety stock.
- ABC/XYZ: A ≈ 80% виторгу — щотижневий контроль; C + Z (нестабільний попит) — кандидати на виведення.
- Перевіряй частку OOS (out-of-stock) топ-SKU і частку повернень по категоріях — два найдорожчі «тихі» витоки.

## 10. Маркетплейси (Allegro / Amazon)
- Allegro: Smart! і рейтинг продавця — головні важелі buy-box-аналога; ціна з доставкою, строк відправки, якість карток (заповненість параметрів) вирішують видимість.
- Amazon: Buy Box ≈ ціна + Prime/FBA + метрики продавця (ODR < 1%, late shipment < 4%); контент = A+ сторінки, головне фото на білому.
- Канон аудиту: маркетплейс = окремий P&L (комісії + логістика + реклама можуть зʼїсти всю маржу — рахуй contribution по каналу).

## 11. Комплаєнс ЄС для e-commerce (юридичний шар знахідок)
- GDPR: підстава обробки, cookie-консент (не pre-checked), DPA з процесорами, право на видалення.
- Consumer Rights Directive: 14 днів на повернення дистанційної покупки без пояснень.
- Omnibus Directive: при знижці показуй найнижчу ціну за попередні 30 днів.
- VAT OSS/IOSS: поріг дистанційних продажів в ЄС €10,000 → далі VAT країни покупця через OSS.
- GPSR (з 13.12.2024): відповідальна особа в ЄС для товарів, маркування; EPR (упаковка/електроніка/текстиль) — реєстрація у країнах продажу; Польща: KSeF — обовʼязкове е-фактурування (етапи з 2026).
- Ці пункти — чекліст «критичних» знахідок: юридичний ризик завжди Severity High.

## 12. Аналітика та вимірювання
- GA4: перевір збір e-commerce подій (view_item, add_to_cart, begin_checkout, purchase) і відповідність виторгу в GA4 vs платформа (розбіжність > 10% = знахідка).
- Consent Mode v2 обовʼязковий для ЄС-трафіку з Google-рекламою (з березня 2024).
- Ієрархія доказів: 1) вивантаження замовлень (факт) → 2) GA4/платформа → 3) відповіді анкети → 4) експертна оцінка. Кожній знахідці — рівень доказовості; нижчий рівень = нижча confidence.
- Калібрування: якщо ledger показує систематичне завищення confidence у домені — знижуй на крок (ECE-дисципліна).

## 13. Зрілість та цільова модель
- 5-рівнева шкала зрілості (за мотивами CMMI): L1 ad-hoc → L2 повторюваний → L3 визначений → L4 вимірюваний → L5 оптимізований. Оцінка домену = найнижчий рівень, який ПОВНІСТЮ виконано (не середнє з бажаного).
- Цільова модель (Б) описується тими самими 12 доменами, що й діагностика (А) — тоді роадмапа стає різницею станів, і Гант A→Б будується механічно.

## 14. AI в бізнесі клієнта
- EU AI Act: більшість e-commerce кейсів (рекомендації, чат-боти) = minimal/limited risk → обовʼязок прозорості (маркувати бота як бота). Заборонені практики (маніпулятивний таргетинг вразливих) — червона лінія.
- Аудит AI-готовності: якість даних (без чистого фіду/CRM AI не запуститься) → кейси з ROI (опис товарів, підтримка, прогноз попиту) → люди й процеси.

## Правила застосування пакета
1. Кожна знахідка = факт (доказ + рівень доказовості) + стандарт (звідси) + наслідок у грошах/ризику + рекомендація з Owner і Effort.
2. Пороги зі стандартів не «памʼятай приблизно» — бери звідси дослівно.
3. Якщо даних для стандарту нема (нема GSC, нема вивантаження) — пиши «потрібні дані», не вигадуй значення.
