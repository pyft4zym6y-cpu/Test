# Discovery Portal — установка (≈20 минут)

Клиентский портал диагностики: 643 вопроса по 26 блокам (с ветвлением и
автосохранением) + чек-лист передачи 20 доступов. Код — `portal/` в этом
репозитории. Вопросы зашиты в приложение (`src/data/questions.json`),
в базе хранятся только ответы.

## 1. Supabase (бесплатный тариф)

1. https://supabase.com → New project (регион EU). Дождитесь создания.
2. **SQL Editor** → New query → вставьте целиком `portal/supabase/schema.sql` → Run.
3. Там же выполните первичную настройку (шаблоны в конце schema.sql):
   - добавьте себя админом (`is_admin=true`);
   - создайте первого клиента и участников с их e-mail.
4. **Authentication → URL Configuration**: Site URL = `https://discovery.weexp.agency`
   (плюс добавьте его в Redirect URLs).
5. **Project Settings → API**: скопируйте `Project URL` и `anon public` ключ.

## 2. Vercel — второй проект из того же репозитория

1. Vercel → Add New → Project → выберите репозиторий `Test` (тот же).
2. **Root Directory: `portal`** (главная настройка!). Framework: Vite.
3. Environment Variables:
   - `VITE_SUPABASE_URL` = Project URL из шага 1.5
   - `VITE_SUPABASE_ANON_KEY` = anon ключ из шага 1.5
4. Deploy.
5. Settings → Domains → Add → `discovery.weexp.agency` (домен на Vercel —
   привяжется автоматически).

## 3. Проверка

- Откройте discovery.weexp.agency → введите e-mail, добавленный в `members` →
  ссылка из письма → дашборд с опросниками.
- Ответьте на пару вопросов → обновите страницу: ответы на месте.
- Зайдите под админ-e-mail → вкладка «Админ»: сводка по клиентам + выгрузка CSV.

## Рабочий процесс с клиентом

1. Создали клиента + участников в Supabase (SQL из schema.sql, 1 минута).
2. Отправили каждому участнику ссылку discovery.weexp.agency («вход по вашему
   рабочему e-mail, пароль не нужен»).
3. Клиент заполняет опросники (роли подсказаны тегами) и отмечает статусы
   доступов; ветки-уточнения открываются автоматически по ответам.
4. Вы смотрите прогресс в «Админ», выгружаете CSV → переносите в
   Discovery-XLSX для интерпретаций и роутинга.

## Безопасность

- Вход только по magic-link; e-mail не из `members` внутрь не попадает.
- RLS: клиент видит и пишет только свои ответы; админ читает всё.
- Пароли не собираются нигде — только приглашения «просмотр» и файлы;
  в UI это правило показано клиенту явно.
- `noindex` в разметке — портал не попадёт в поиск.

## Обновление вопросов

Изменился XLSX-фреймворк → скажите Claude в чате: перегенерируем
`src/data/questions.json` из нового файла, `git push` — Vercel выкатит сам.
Ответы клиентов не пострадают (связь по ID вопроса).

## Serverless-функции (папка api/)

На Vercel вместе с порталом деплоятся две функции (в демо-режиме недоступны):

- **`/api/fetch`** — качает HTML чужих сайтов для L0-скрининга (кнопка
  «Прогнать скрининг» в консультантской ветке). Настройки не требует.
- **`/api/ga4`** — тянет baseline из GA4 Data API (кнопка «⇓ Подтянуть из GA4»).
  Требует три переменные окружения (Vercel → Settings → Environment Variables):
  1. `GA4_PROPERTY_ID` — числовой ID ресурса (GA4 Admin → Property settings);
  2. `GA4_SA_EMAIL` — client_email сервисного аккаунта Google Cloud;
  3. `GA4_SA_KEY` — private_key этого аккаунта (вставить целиком, с `\n`).
  Сервисный аккаунт создаётся в Google Cloud Console (IAM → Service accounts →
  ключ JSON), затем его e-mail добавляется в GA4 клиента как «Наблюдатель»
  (Admin → Property access management). Это делается один раз на ваш аккаунт —
  дальше каждый клиент просто добавляет тот же e-mail в свой GA4.

## После обновления v5

В Supabase заново прогоните `supabase/schema.sql` (SQL Editor → Run) — добавились
колонки `screen` и `budget` в `report_meta`. Скрипт идемпотентный.

## AI-прогон AQC (v9)

Функция `/api/aqc` прогоняет страницу клиента по AQC-чеклисту через Claude API.
Настройка: Vercel → Environment Variables → `ANTHROPIC_API_KEY` (ключ из
console.anthropic.com), опционально `AQC_MODEL` (по умолчанию claude-sonnet-5).
Вердикты AI — гипотезы с достоверностью 25 (правило метода): в чеклисте они
пунктирные, пока консультант не подтвердит рукой.

## Вход только по приглашениям (v11)

Форма входа перед отправкой magic-link проверяет e-mail через RPC `is_invited`:
письмо со ссылкой уходит только адресам, которые вы заранее добавили в
клиента (раздел «Клиенты» → участник). Чужой адрес видит вежливый отказ
с контактом. Чтобы включить — прогоните `supabase/schema.sql` ещё раз
(скрипт идемпотентный, добавится только функция). Пока функции нет в базе,
форма работает по-старому: ссылка уходит всем, но в портал без записи в
members всё равно не попасть.

## Email-уведомления консультанту (v10)

Портал шлёт письмо на вашу почту, когда клиент проходит вехи: вводные готовы →
опросник 25% → 60% → выдан ключевой доступ (GA4/заказы) → бриф ЛПР готов.
Каждая веха — ровно одно письмо.

Настройка (2 минуты):
1. resend.com → аккаунт → API Keys → создать ключ.
2. Vercel → Environment Variables: `RESEND_API_KEY` (ключ из шага 1) → Redeploy.
   Ключ живёт ТОЛЬКО в Vercel env — в код и git его не класть.

Адрес получателя по умолчанию зашит в `api/notify.js` (DEFAULT_NOTIFY_EMAIL);
переменная `NOTIFY_EMAIL` переопределяет его без правки кода. Опционально
`NOTIFY_FROM` — адрес на подтверждённом в Resend домене, например
`portal@weexp.agency`; без него письма идут с onboarding@resend.dev
(для боевого использования подтвердите домен weexp.agency в Resend → Domains).
Без `RESEND_API_KEY` функция тихо бездействует — портал работает как раньше.
