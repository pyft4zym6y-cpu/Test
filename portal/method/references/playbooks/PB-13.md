# PB-13 · Ценовая архитектура и промо-дисциплина

| Домен | Ценообразование |
| --- | --- |
| Срабатывает по правилам | R37 |
| Вопросы-источники | PR-001…PR-015, SL-019, PX-025, PX-032 |
| Длительность | 4 недели |
| Deliverable | D-28 Ценовая архитектура (XLSX) |
| Владелец у клиента | Категорийный менеджер / собственник |


### 1  Зачем нужен этот плейбук
Цена — самый быстрый рычаг прибыли и самый недоуправляемый в большинстве e-commerce. Скидки раздаются реактивно, промо каннибализирует маржу, а цена товара не связана ни с его ролью в линейке, ни с ценностью для клиента. Ценовая архитектура наводит порядок: она определяет уровни цен, правила скидок и промо-дисциплину.
Плейбук строит ценовую структуру линейки, промо-календарь с гайдрейлами и связывает цены с contribution margin из PB-12. Результат — рост маржи без потери объёма и защита от скидочной зависимости.

|  | Корневая проблема Цены и скидки живут своей жизнью. Больше половины заказов проходит со скидкой, глубина промо не ограничена, а маржа эродирует. Компания привыкает продавать через скидку и теряет способность продавать по полной цене. |
| --- | --- |


### 2  Когда подключать: симптомы и триггеры
Плейбук подключается, если в ходе Discovery подтвердился хотя бы один из триггеров ниже.

| Триггер (что услышали от клиента) | Правило |
| --- | --- |
| Нет ценовой премии за бренд | R37 |
| Скидки > 50% заказов, эрозия маржи | — |
| Нет ценовой архитектуры линейки | — |


### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Прайс-лист и текущая маржа по SKU — Ценовая структура. [обязательно]
История промо и скидок с результатами — Промо-дисциплина. [обязательно]
Цены конкурентов по ключевым позициям — Ценовое позиционирование. [обязательно]
Contribution margin по SKU (из PB-12) — Границы скидок. [обязательно]
Данные об эластичности спроса (если есть) — Чувствительность к цене. [желательно]
Ценовая политика по каналам и МП — Каннибализация каналов. [желательно]

|  | Проверка перед стартом Нужен contribution margin по SKU из PB-12. Без него ценовые решения принимаются вслепую: невозможно понять, где скидка ещё оставляет прибыль, а где уже уводит в минус. |
| --- | --- |


### 4  Пошаговый процесс
Шаг 1. Провести аудит текущего ценообразования
Собрать прайс, фактические цены продаж и реальную маржу по SKU.
Измерить долю заказов со скидкой и среднюю глубину скидки.
Выявить позиции, продающиеся ниже CM2 — прямой убыток.
Шаг 2. Построить ценовую архитектуру линейки
Определить роли товаров: входные, ядро, премиум, аксессуары.
Задать ценовые уровни и разрывы между ними без пересечений.
Проверить, что есть путь наращивания чека вверх по линейке.
Шаг 3. Сопоставить цену с ценностью и конкурентами
Сравнить цены с конкурентами по ключевым позициям.
Определить, где есть право на ценовую премию (бренд, сервис, уникальность).
Выявить позиции, где цену можно поднять без потери спроса.
Шаг 4. Навести промо-дисциплину
Установить гайдрейлы: максимальная глубина скидки по категориям.
Построить промо-календарь вместо реактивных распродаж.
Задать правило: промо только на позициях с достаточным запасом маржи.
Шаг 5. Смоделировать эффект
Рассчитать влияние новой архитектуры на среднюю маржу и AOV.
Показать сценарии: рост цены на X% при разной эластичности.
Оценить риск потери объёма и заложить его в модель.
Шаг 6. Внедрить и связать со смежными плейбуками
Убыточные SKU → PB-28 (вывод или репрайсинг).
Право на премию → PB-46/PB-50 (бренд и ценовая премия).
Зафиксировать правила в регламенте и «63 Decision Log».

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Доля промо-заказов | Заказы со скидкой / все заказы | > 50% = скидочная зависимость |
| Средняя глубина скидки | Σ скидок / Σ выручки по промо | Контролировать по категориям |
| Ценовая премия | (Наша цена − цена конкурента) / цена конкурента | Обоснована ли ценностью |
| Гайдрейл скидки | Макс. скидка при CM2 ≥ 0 | Скидка не уводит SKU в минус |
| Эффект репрайсинга | Δ маржи × объём − потерянный объём × маржа | Чистый эффект на прибыль |


### 6  Что получается на выходе (Deliverable)
D-28 «Ценовая архитектура и промо-календарь» (XLSX):
Лист «Аудит» — текущие цены, маржа, доля и глубина промо.
Лист «Архитектура» — уровни цен по ролям товаров и линейкам.
Лист «Бенчмарк» — сравнение с конкурентами по ключевым позициям.
Лист «Промо-календарь» — план акций с гайдрейлами по марже.
Лист «Сценарии» — эффект изменения цен при разной эластичности.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Измерена доля и глубина промо, выявлены убыточные позиции.
✓  Построена ценовая архитектура линейки без пересечений уровней.
✓  Проведён ценовой бенчмарк с конкурентами.
✓  Установлены гайдрейлы скидок и промо-календарь.
✓  Смоделирован эффект на маржу и AOV.
✓  Убыточные SKU переданы в PB-28.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Скидка без учёта маржи позиции | Промо уводит SKU в убыток | Гайдрейл: скидка только при CM2 ≥ 0 |
| Цена без ролей в линейке | Нет пути наращивания чека | Строить архитектуру уровней |
| Копировать цены конкурентов | Гонка на дно, потеря маржи | Цена от ценности, а не от конкурента |
| Реактивные распродажи | Скидочная зависимость | Промо-календарь с дисциплиной |
| Игнорировать эластичность | Потеря объёма при росте цены | Моделировать сценарии спроса |
