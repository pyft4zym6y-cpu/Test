# PB-02 · Funnel Teardown (разбор воронки продаж)

| Домен | Продажи |
| --- | --- |
| Срабатывает по правилам | R21 |
| Вопросы-источники | SL-001…SL-020, PL-011, AN-004 |
| Длительность | 3 недели |
| Deliverable | D-50 Разбор воронки продаж (Deck / XLSX) + D-87 Описание воронок (XLSX) |
| Владелец у клиента | Head of Sales / собственник |


### 1  Зачем нужен этот плейбук
Когда выручка падает или не растёт при стабильном трафике, деньги теряются где-то в воронке — но где именно, без разбора не видно. Funnel Teardown раскладывает путь от захода до оплаты на шаги, находит точки максимальных потерь и переводит расплывчатое «плохо продаётся» в конкретный список утечек с приоритетами.
Плейбук проводит пошаговый разбор воронки продаж: измеряет конверсию каждого шага, сегментирует потери и связывает их с причинами, давая основу для CRO и оптимизации привлечения.

|  | Корневая проблема Продажи не растут или падают, а причина не локализована. Трафик есть, но где теряются клиенты — на входе, в каталоге, в карточке, в корзине или чекауте — неизвестно. Оптимизация ведётся вслепую по всей воронке сразу. |
| --- | --- |

### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Доступ к аналитике: полная воронка по шагам — Точки потерь по этапам. [обязательно]
Данные о конверсии по источникам и устройствам — Сегментация потерь. [обязательно]

История обращений (вопросы до покупки) — Возражения на этапе выбора. [опционально]

### 4  Пошаговый процесс
Шаг 1. Определить структуру воронки
Задать шаги воронки: заход → каталог → карточка → корзина → чекаут → оплата.
Определить метрику конверсии для каждого перехода.
Учесть разные пути (прямой в карточку, поиск, категории).
Шаг 2. Измерить конверсию по шагам
Рассчитать конверсию каждого перехода и общую.
Найти шаги с максимальным относительным отвалом.
Сравнить с бенчмарками по индустрии.
Шаг 3. Сегментировать потери
Разложить конверсию по устройствам (мобайл/десктоп).
Разложить по источникам трафика и его качеству.
Выявить, где теряются целевые сегменты (PB-43).
Шаг 4. Связать потери с причинами
Наложить барьеры клиентов из PB-40 на точки отвала.
Проверить технические причины (скорость, ошибки — PB-14).
Оценить качество трафика на входе (реклама).
Шаг 5. Приоритизировать точки роста
Оценить потенциал каждого шага: отвал × объём × маржа.
Выделить точки с максимальным эффектом от улучшения.
Отделить проблемы качества трафика от проблем сайта.
Шаг 6. Передать в оптимизацию
Точки потерь на сайте → PB-15 (UX/CRO гипотезы).
Проблемы качества трафика → PB-03 (каналы).
Барьеры → PB-40, технические причины → PB-14.

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Конверсия шага | Перешли дальше / вошли на шаг | Локализация потерь |
| Сквозная конверсия | Оплатили / зашли | Общее здоровье воронки |
| Потенциал шага | Отвал × объём × маржа | Приоритет улучшения |
| Разрыв по устройствам | CR десктоп − CR мобайл | Мобильные проблемы |


### 6  Что получается на выходе (Deliverable)
D-02 «Разбор воронки продаж» (Deck/XLSX):
Структура воронки — шаги и метрики переходов.
Конверсия по шагам — где максимальные потери.
Сегментация потерь — по устройствам, источникам, сегментам.
Причины — связь потерь с барьерами и техникой.
Приоритеты — точки роста по потенциалу.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Определена структура воронки с метриками переходов.
✓  Измерена конверсия по шагам, найдены точки отвала.
✓  Потери сегментированы по устройствам и источникам.
✓  Потери связаны с причинами (барьеры, техника, трафик).
✓  Приоритизированы точки роста по потенциалу.
✓  Выводы переданы в PB-15, PB-03, PB-14.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Разбор на недостоверной аналитике | Ложные точки потерь | Сначала проверить трекинг (PB-10) |
| Смотреть только общую конверсию | Не видно, где именно теряется | Раскладывать по шагам |
| Игнорировать сегментацию | Мобильные потери скрыты | Разбивать по устройствам и источникам |
| Путать проблему трафика и сайта | Оптимизация не туда | Отделять качество трафика от UX |
