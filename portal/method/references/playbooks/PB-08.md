# PB-08 · Retention-контур и жизненный цикл клиента

| Домен | CRM / Retention |
| --- | --- |
| Срабатывает по правилам | R28 |
| Вопросы-источники | CR-001…CR-018, CU-024, CU-030, CO-015 |
| Длительность | 4 недели |
| Deliverable | D-25 Архитектура retention-флоу (Miro / DOC) |
| Владелец у клиента | CRM-менеджер / Head of Marketing |


### 1  Зачем нужен этот плейбук
Привлечь клиента дорого, удержать — в разы дешевле, но большинство e-commerce вкладывает почти весь бюджет в привлечение и почти ничего в удержание. Retention-контур превращает разовых покупателей в повторных: выстраивает жизненный цикл клиента и автоматические сценарии, которые возвращают его к покупке.
Плейбук проектирует архитектуру retention-флоу по этапам жизненного цикла — от welcome до реактивации — на основе сегментации базы и данных о поведении.

|  | Корневая проблема Клиенты покупают один раз и не возвращаются, а компания это не отслеживает и не управляет этим. База не сегментирована, retention-флоу нет или они примитивны, причины оттока не изучены. Каждая продажа начинается с нуля и с оплаты привлечения. |
| --- | --- |


### 2  Когда подключать: симптомы и триггеры
Плейбук подключается, если в ходе Discovery подтвердился хотя бы один из триггеров ниже.

| Триггер (что услышали от клиента) | Правило |
| --- | --- |
| Не изучались причины ухода к конкуренту | R28 |
| Низкий repeat rate, нет retention-флоу | — |
| База не сегментирована по жизненному циклу | — |


### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Доступ к CRM/ESP (Klaviyo и т.п.): флоу, сегменты, метрики — Аудит текущих механик. [обязательно]
Выгрузка клиентской базы с историей покупок — RFM, когорты, lifecycle. [обязательно]
Метрики email/push: open, click, revenue — Эффективность каналов. [обязательно]
Данные о повторных покупках и оттоке — Repeat rate, churn. [обязательно]
Данные о причинах отписки/оттока — Churn reasons. [желательно]
Сегментация текущей базы (если есть) — Отправная точка. [опционально]

|  | Проверка перед стартом Нужен доступ к CRM/ESP и выгрузка базы с историей покупок. Без данных о повторных покупках невозможно построить когорты и понять, где именно теряются клиенты. |
| --- | --- |


### 4  Пошаговый процесс
Шаг 1. Проанализировать текущее удержание
Рассчитать repeat rate, частоту покупок, отток по когортам.
Оценить долю выручки от повторных клиентов.
Провести аудит текущих флоу и сегментов в CRM/ESP.
Шаг 2. Сегментировать базу по жизненному циклу
Построить RFM-сегментацию: давность, частота, ценность.
Выделить этапы: новый, активный, под угрозой оттока, ушедший.
Определить ценные сегменты и приоритеты работы с ними.
Шаг 3. Спроектировать карту жизненного цикла
Определить целевое поведение на каждом этапе.
Спланировать переходы между этапами и триггеры.
Заложить точки, где вмешательство даёт максимальный эффект.
Шаг 4. Разработать retention-флоу
Welcome-серия для новых клиентов и первое повторное касание.
Реактивационные сценарии для угасающих клиентов.
Пострановые механики: пополнение, кросс-сейл, годовщина.
Шаг 5. Заложить экономику и измерение
Связать флоу с LTV из PB-12: какой прирост повторных покупок даёт эффект.
Задать метрики каждого флоу: revenue, конверсия, влияние на repeat rate.
Определить контрольные группы для честной оценки.
Шаг 6. Связать со смежными плейбуками
Причины оттока → PB-45 (Voice of Customer).
Сегменты → PB-43 (персоны и ICP).
Механики повторных покупок → PB-09 (лояльность).

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Repeat rate | Клиентов с 2+ покупками / всего | Ключевой показатель удержания |
| Retention по когортам | Активны через N мес / когорта | Динамика удержания |
| Доля выручки от повторных | Выручка повторных / общая | Зависимость от привлечения |
| Time to 2nd purchase | Медианный срок до 2-й покупки | Окно для welcome-флоу |
| Churn rate | Ушедших / активных за период | Скорость оттока |


### 6  Что получается на выходе (Deliverable)
D-25 «Архитектура retention-флоу» (Miro/DOC):
Анализ удержания — repeat rate, когорты, отток, аудит текущих флоу.
RFM-сегментация — сегменты базы по давности, частоте, ценности.
Карта жизненного цикла — этапы, целевое поведение, триггеры.
Библиотека флоу — welcome, реактивация, кросс-сейл, пополнение.
План измерения — метрики флоу и контрольные группы.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Рассчитаны repeat rate, когорты и отток.
✓  Построена RFM-сегментация базы.
✓  Спроектирована карта жизненного цикла с триггерами.
✓  Разработаны ключевые retention-флоу.
✓  Флоу связаны с LTV и планом измерения с контрольными группами.
✓  Причины оттока переданы в PB-45.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Один флоу для всей базы | Нерелевантная коммуникация, отписки | Сегментация по жизненному циклу |
| Флоу без контрольных групп | Невозможно доказать эффект | Всегда закладывать контроль |
| Игнорировать причины оттока | Реактивация без устранения причины | Связать с VoC (PB-45) |
| Retention без связи с LTV | Механики без экономического смысла | Опираться на юнит-экономику PB-12 |
