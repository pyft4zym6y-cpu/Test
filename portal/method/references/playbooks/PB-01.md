# PB-01 · Discovery & Diagnostic Program (мастер-плейбук)

| Домен | Стратегия |
| --- | --- |
| Срабатывает по правилам | по итогам диагностики |
| Вопросы-источники | Все блоки 10–35, матрицы 40–44 |
| Длительность | 4–6 недель |
| Deliverable | D-01 Discovery Report (PDF / Deck) + D-02 Матрица зрелости с оценками (XLSX) + D-49 Итоговый Roadmap с бюджетом и ROI (Deck) |
| Владелец у клиента | Собственник / спонсор проекта |


### 1  Зачем нужен этот плейбук
Любая трансформация начинается с честного диагноза. Discovery & Diagnostic Program — это мастер-плейбук, который запускает всю систему: комплексно оценивает бизнес по всем доменам, вычисляет Health Score, выявляет корневые проблемы и через роутинг подключает нужные специализированные плейбуки.
Плейбук проводит полную диагностику на основе структурированных вопросов, матриц зрелости и рисков, и собирает Executive Summary с приоритизированным роадмапом трансформации.

|  | Корневая проблема Бизнес хочет расти или трансформироваться, но не имеет объективной картины своего состояния. Проблемы лечатся симптоматически, приоритеты неясны, а решения принимаются без диагноза. Нет отправной точки для программы изменений. |

### 2  Когда подключать: симптомы и триггеры
Плейбук подключается, если в ходе Discovery подтвердился хотя бы один из триггеров ниже.

| Триггер (что услышали от клиента) | Правило |
| --- | --- |
| Старт любого трансформационного проекта | — |
| Нужна полная диагностика бизнеса | — |
| Подготовка коммерческого предложения | — |


### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Полный набор доступов из листа «05 Доступы» — Комплексная диагностика. [обязательно]
Интервью со всеми ключевыми стейкхолдерами — Контекст и цели. [обязательно]
Управленческая и финансовая отчётность — Финансовая картина. [обязательно]
Доступ к историческим данным продаж — Аналитическая база. [обязательно]

|  | Проверка перед стартом Диагностика требует широкого доступа к данным и стейкхолдерам. При отказе в ключевых доступах соответствующие домены оцениваются с пониженной уверенностью, что явно фиксируется в отчёте. |
| --- | --- |


### 4  Пошаговый процесс
Шаг 1. Настроить периметр и доступы
Согласовать цели диагностики и зоны фокуса со спонсором.
Получить доступы по листу «05 Доступы».
Составить карту стейкхолдеров и план интервью.
Шаг 2. Провести диагностику по доменам
Пройти структурированные вопросы по всем блокам (10–35).
Зафиксировать ответы с весами, флагами проблем и уверенностью.
Собрать доказательства и данные под ключевые ответы.
Шаг 3. Заполнить матрицы
Оценить зрелость по доменам (L1–L5).
Заполнить матрицы рисков, ограничений, возможностей.
Рассчитать E-commerce Health Score.
Шаг 4. Выявить корневые проблемы
Отделить симптомы от корневых причин.
Приоритизировать проблемы по влиянию и критичности.
Связать проблемы с критическими разрывами (CG).
Шаг 5. Применить роутинг
По сработавшим правилам подключить нужные плейбуки.
Сформировать Scope программы из плейбуков.
Приоритизировать по влиянию и последовательности.
Шаг 6. Собрать Executive Summary и роадмап
Собрать топ-проблемы, возможности, Quick Wins, High Impact.
Построить фазированный роадмап трансформации.
Оформить экономику программы и ожидаемый эффект.

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Health Score | 0.6 × зрелость + 0.4 × (100 − штрафы разрывов) | Интегральное здоровье e-commerce |
| Зрелость домена | Средневзвешенная оценка по вопросам | Уровень L1–L5 |
| Критический разрыв | Флаги проблем × вес × критичность | Приоритет вмешательства |
| Приоритет плейбука | Влияние / трудозатраты | Порядок в роадмапе |


### 6  Что получается на выходе (Deliverable)
D-01 «Discovery Report + Health Score + Roadmap» (Deck/PDF):
Диагностика по доменам — ответы, зрелость, доказательства.
Матрицы — зрелость, риски, ограничения, возможности.
Health Score — интегральная оценка с разбором.
Корневые проблемы — приоритизированные причины.
Scope программы — подключённые плейбуки по роутингу.
Executive Summary + роадмап — выводы, Quick Wins, фазы, экономика.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Согласован периметр, получены доступы, составлена карта стейкхолдеров.
✓  Пройдена диагностика по всем доменам с фиксацией уверенности.
✓  Заполнены матрицы и рассчитан Health Score.
✓  Выявлены корневые проблемы, отделённые от симптомов.
✓  Применён роутинг, сформирован Scope программы.
✓  Собраны Executive Summary и фазированный роадмап.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Диагноз по симптомам | Лечение следствий, не причин | Доходить до корневых причин |
| Пропуск доменов из-за нехватки данных | Слепые зоны в картине | Фиксировать пониженную уверенность |
| Роадмап без приоритизации | Распыление ресурса | Приоритет по влиянию/трудозатратам |
| Отчёт без Quick Wins | Нет ранних побед для доверия | Выделять быстрые победы |
