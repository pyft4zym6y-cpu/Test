### 1  Зачем нужен этот плейбук
Органический трафик — самый маржинальный канал: он не требует оплаты за клик и накапливается во времени. Но он же и самый хрупкий: одна неудачная миграция, закрытый в robots раздел или обвал Core Web Vitals способны обнулить годы работы. Технический SEO-аудит находит, что мешает сайту нормально индексироваться и ранжироваться.
Плейбук проводит полную техническую диагностику: индексация, скорость, структура, разметка, ссылочный профиль — и выдаёт приоритизированный бэклог исправлений, где каждая задача оценена по влиянию и трудозатратам.

|  | Корневая проблема Сайт теряет органический трафик или не растёт, и никто не знает почему. SEO либо не ведётся вообще, либо ведётся вслепую: правки вносятся без диагностики, после миграции трафик просел, а причины не найдены. Деньги на контент и ссылки тратятся на фундамент с трещинами. |

Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:

### 4  Пошаговый процесс
Шаг 1. Проверить индексацию и покрытие
Сверить число страниц в Search Console с реальным размером каталога.
Найти важные страницы вне индекса и мусорные страницы в индексе.
Проверить robots.txt, sitemap.xml, канонические теги и директивы noindex.
Шаг 2. Диагностировать структуру и дубли
Выявить дубли из-за фасетной навигации, параметров и пагинации.
Проверить каноникализацию и склейку дублирующегося контента.
Оценить глубину вложенности: важные страницы не должны быть глубже 3 кликов.
Шаг 3. Оценить производительность (Core Web Vitals)
Замерить LCP, INP, CLS на ключевых типах страниц.
Найти тяжёлые элементы: неоптимизированные изображения, блокирующие скрипты.
Проверить мобильную версию отдельно — большая часть трафика мобильная.
Шаг 4. Проверить разметку и техническое SEO
Аудит мета-тегов: title, description, заголовки H1–H3.
Проверить структурированные данные Schema.org (Product, Breadcrumb, FAQ).
Оценить внутреннюю перелинковку и распределение ссылочного веса.
Шаг 5. Проанализировать ссылочный профиль
Оценить количество и качество внешних ссылок против конкурентов.
Найти токсичные ссылки и потерянные (битые) беклинки.
Определить разрыв по ссылочной массе с лидерами ниши.
Шаг 6. Собрать приоритизированный бэклог
Классифицировать находки по влиянию (трафик/риск) и трудозатратам.
Выделить Quick Wins: высокое влияние при низких затратах.
Передать критичные проблемы в PB-14 (платформа), структуру — в PB-05.

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Coverage ratio | Проиндексировано / всего важных страниц | Цель: близко к 100% |
| Index bloat | Мусорных в индексе / всего в индексе | Высокий = разбавление краулингового бюджета |
| LCP | Время загрузки основного контента | Цель: < 2.5 сек |
| INP | Отклик на взаимодействие | Цель: < 200 мс |
| CLS | Сдвиг макета | Цель: < 0.1 |
| Link gap | Домены-доноры конкурента − наши | Разрыв ссылочной массы |


### 6  Что получается на выходе (Deliverable)
D-21 «Технический SEO-аудит» (DOC/XLSX):
Раздел «Индексация» — карта покрытия, страницы вне индекса, мусор.
Раздел «Скорость» — Core Web Vitals по типам страниц с находками.
Раздел «Техническое» — мета, разметка, перелинковка, дубли.
Раздел «Ссылки» — профиль против конкурентов, разрывы.
Бэклог (XLSX) — задачи с оценкой влияния, трудозатрат и приоритета.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Проверена индексация: найдены страницы вне индекса и мусор в индексе.
✓  Замерены Core Web Vitals по ключевым типам страниц.
✓  Проведён аудит мета, разметки и перелинковки.
✓  Оценён ссылочный профиль против конкурентов.
✓  Собран бэклог с приоритизацией по влиянию и трудозатратам.
✓  Выделены Quick Wins для немедленного внедрения.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Править без диагностики индексации | Работа над невидимыми для поиска страницами | Сначала Search Console, потом правки |
| Игнорировать краулинговый бюджет | Мусор съедает обход важных страниц | Чистить index bloat |
| CWV только на десктопе | Мобильные проблемы не видны | Замерять мобильную версию отдельно |
| Бэклог без приоритизации | Ресурс уходит на мелочь | Ранжировать по влиянию × трудозатраты |
