# PB-32 · AI Use Cases и портфель с ROI

| --- | --- |
| Срабатывает по правилам | по итогам диагностики |
| Вопросы-источники | AI-106, AI-117, AI-118, AI-125 |

| Владелец у клиента | COO / AI-лид |


### 1  Зачем нужен этот плейбук
AI внедряется либо по моде, либо не внедряется вовсе — и в обоих случаях бизнес теряет. Без оценки эффекта деньги уходят на модные, но бесполезные проекты, а реальные возможности автоматизации упускаются. AI Use Cases с ROI превращают хайп в приоритизированный портфель проектов с понятной отдачей.
Плейбук выявляет и приоритизирует AI-кейсы по ROI: где автоматизация даёт реальный эффект, что реализуемо на текущих данных и с чего начать для быстрых побед.

|  | Корневая проблема AI внедряется по моде, без оценки эффекта, или не внедряется из-за неясности. Ресурсы уходят на эффектные, но малополезные проекты, а простые высокоэффективные автоматизации упускаются. Нет портфеля кейсов с ROI. |
| --- | --- |


### 2  Когда подключать: симптомы и триггеры
Плейбук подключается, если в ходе Discovery подтвердился хотя бы один из триггеров ниже.

| Триггер (что услышали от клиента) | Правило |
| --- | --- |
| Нет оценки эффекта AI-внедрений | — |
| AI внедряется по моде | — |
| Нужны быстрые AI-победы | — |


### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Карта процессов с объёмом повторяемых операций — Приоритет автоматизации. [обязательно]
Данные о трудозатратах по процессам — Оценка эффекта. [обязательно]
Оценка готовности данных (из PB-54) — Реализуемость. [обязательно]
Стоимость AI-инструментов — ROI-расчёт. [желательно]

|  | Проверка перед стартом Оценка реализуемости кейсов опирается на AI Readiness (PB-54): без понимания готовности данных и процессов ROI-оценки будут оптимистичной фантазией. |
| --- | --- |


### 4  Пошаговый процесс
Шаг 1. Картировать процессы-кандидаты
Собрать процессы с высоким объёмом повторяемых операций.
Оценить трудозатраты и болевые точки каждого.
Выделить кандидатов на автоматизацию.
Шаг 2. Сгенерировать AI use cases
Для каждого процесса сформулировать возможные AI-применения.
Классифицировать: контент, поддержка, аналитика, прогноз, персонализация.
Собрать длинный список кейсов.
Шаг 3. Оценить эффект каждого кейса
Оценить потенциальный эффект: экономия времени, рост выручки, качество.
Перевести эффект в деньги где возможно.
Учесть частоту и масштаб применения.
Шаг 4. Оценить реализуемость
Оценить готовность данных и процессов (из PB-54).
Оценить сложность и стоимость реализации.
Учесть риски (качество, комплаенс — PB-56).
Шаг 5. Приоритизировать портфель
Построить матрицу эффект × реализуемость.
Выделить Quick Wins (высокий эффект, низкая сложность).
Сформировать дорожную карту AI-проектов.
Шаг 6. Связать со смежными плейбуками
Готовность → PB-54.
Конкретные кейсы → PB-33 (контент), PB-35 (поддержка).
Governance → PB-56.

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| ROI кейса | (Эффект − стоимость) / стоимость | Отдача проекта |
| Эффект в деньгах | Экономия/прирост × частота × масштаб | Монетизация кейса |
| Реализуемость | Готовность данных × простота | Осуществимость |
| Priority score | Эффект / сложность | Порядок в портфеле |


### 6  Что получается на выходе (Deliverable)
«Портфель AI-кейсов с ROI» (XLSX):
Процессы-кандидаты — с объёмом операций и болями.
Список use cases — кейсы по типам.
Оценка эффекта — эффект в деньгах где возможно.
Оценка реализуемости — готовность и сложность.
Приоритизированный портфель — матрица и дорожная карта.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Картированы процессы-кандидаты с трудозатратами.
✓  Сгенерирован список AI use cases по типам.
✓  Оценён эффект каждого кейса, где возможно — в деньгах.
✓  Оценена реализуемость с учётом готовности данных.
✓  Построен приоритизированный портфель с Quick Wins.
✓  Связано с PB-54, PB-33, PB-35, PB-56.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Внедрять AI по моде | Ресурс на эффектные, но бесполезные проекты | Оценивать ROI каждого кейса |
| Оценка эффекта без реализуемости | Кейсы, невозможные на текущих данных | Учитывать готовность (PB-54) |
| Начинать со сложного | Долго, дорого, без ранних побед | Начинать с Quick Wins |
| Игнорировать риски | Проблемы качества и комплаенса | Учитывать governance (PB-56) |
