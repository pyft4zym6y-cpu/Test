### 1  Зачем нужен этот плейбук
Все решения на данных бессмысленны, если данным нельзя доверять. Расхождение аналитики с бэкендом, отсутствие атрибуции, дырявый трекинг — и вся диагностика, вся оптимизация строятся на песке. Перестройка аналитики создаёт достоверную событийную модель, на которую можно опереться.
Плейбук приводит в порядок сбор данных: аудирует трекинг, проектирует событийную модель, настраивает атрибуцию и обеспечивает сходимость с реальными заказами.

|  | Корневая проблема Данные аналитики недостоверны и расходятся с бэкендом. Событий нет или они настроены криво, атрибуция отсутствует, отчёты противоречат друг другу. Компания либо не доверяет цифрам, либо принимает решения на неверных. |

### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Доступ к GA4 и GTM — Аудит событий и трекинга. [обязательно]
Доступ к бэкенду/заказам для сверки — Сверка данных. [обязательно]

Доступ к рекламным кабинетам (атрибуция) — Модель атрибуции. [желательно]

|  | Проверка перед стартом Нужны доступы к GA4/GTM и к бэкенду для сверки. Настраивать аналитику без возможности сверить её с реальными заказами — значит чинить вслепую. |

### 4  Пошаговый процесс
Шаг 1. Провести аудит текущего трекинга
Сверить ключевые метрики аналитики с данными бэкенда (заказы, выручка).
Проверить настройку событий, целей и электронной торговли.
Найти разрывы: где данные теряются или дублируются.
Шаг 2. Спроектировать событийную модель
Определить ключевые события пути пользователя: просмотр, корзина, чекаут, покупка.
Задать единый data layer и структуру параметров.
Стандартизировать именование событий.
Шаг 3. Настроить атрибуцию
Выбрать модель атрибуции под структуру каналов.
Связать рекламные кабинеты с аналитикой.
Обеспечить сквозной путь от источника до заказа.
Шаг 4. Обеспечить сходимость данных
Настроить сверку аналитики с бэкендом на регулярной основе.
Устранить расхождения до приемлемого уровня погрешности.
Задокументировать источники истины для каждой метрики.
Шаг 5. Подготовить данные для AI и BI
Обеспечить чистоту и структуру данных для будущей аналитики.
Согласовать модель с требованиями PB-11 (BI-слой).
Учесть требования AI-готовности из PB-54.
Шаг 6. Оформить план внедрения
Приоритизировать исправления трекинга по критичности.
Составить ТЗ для разработки и настройки GTM.
Задать процесс поддержания качества данных.

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Сходимость данных | 1 − /аналитика − бэкенд/ / бэкенд | Цель: погрешность < 5% |
| Покрытие событий | Настроенных событий / нужных | Полнота трекинга |
| Атрибутированная выручка | Выручка с известным источником / общая | Качество атрибуции |
| Data quality score | Доля метрик с источником истины | Достоверность модели |


### 6  Что получается на выходе (Deliverable)
D-26 «План внедрения аналитики» (DOC) + событийная модель:
Аудит трекинга — расхождения с бэкендом и разрывы событий.
Событийная модель — карта событий, data layer, именование.
Схема атрибуции — модель и связка с рекламными кабинетами.
Регламент сверки — процесс поддержания сходимости данных.
ТЗ на внедрение — задачи для разработки и настройки GTM.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Проведена сверка аналитики с бэкендом, найдены разрывы.
✓  Спроектирована событийная модель с единым data layer.
✓  Настроена атрибуция и связка с рекламными кабинетами.
✓  Достигнута сходимость данных в пределах допустимой погрешности.
✓  Задокументированы источники истины для метрик.
✓  Модель согласована с PB-11 и PB-54.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Доверять аналитике без сверки | Решения на неверных данных | Всегда сверять с бэкендом |
| События без единой модели | Хаос параметров и именования | Единый data layer и стандарт |
| Игнорировать атрибуцию | Непонятно, какие каналы работают | Настроить сквозную атрибуцию |
| Разовая настройка | Данные снова деградируют | Регламент поддержания качества |
