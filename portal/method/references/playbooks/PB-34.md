# PB-34 · Операционная модель управления

| Домен | Управление |
| --- | --- |
| Срабатывает по правилам | по итогам диагностики |
| Вопросы-источники | GV-001…GV-012, CEO-003 |
| Длительность | 3 недели |
| Deliverable | D-03 Реестр рисков с митигацией (XLSX) + D-47 Операционная модель управления (DOC) |
| Владелец у клиента | COO / собственник |


### 1  Зачем нужен этот плейбук
Без управленческого ритма компания реагирует, а не управляет: решения принимаются хаотично, метрики не отслеживаются регулярно, проблемы всплывают поздно. Операционная модель управления задаёт ритм и структуру: какие встречи, какие метрики, как принимаются решения и как эскалируются проблемы.
Плейбук проектирует операционную модель управления: управленческий ритм, панель метрик, процесс принятия решений и эскалации.

|  | Корневая проблема Нет управленческого ритма и структуры. Решения принимаются реактивно и без данных, метрики не отслеживаются системно, нет эскалации и регулярной отчётности. Управление держится на ручном режиме собственника. |
| --- | --- |


### 2  Когда подключать: симптомы и триггеры
Плейбук подключается, если в ходе Discovery подтвердился хотя бы один из триггеров ниже.

| Триггер (что услышали от клиента) | Правило |
| --- | --- |
| Нет управленческого ритма | — |
| Решения без структуры | — |
| Нет эскалации и отчётности | — |


### 3  Что нужно на входе
Полный список требований к данным и доступам — в документе «Реестр данных и доступов». Ключевые входы:
Текущие управленческие ритмы и встречи — Аудит управления. [обязательно]
Система отчётности и метрик — Управленческая панель. [обязательно]
Процесс принятия решений — Decision framework. [обязательно]
Данные о структуре компании — Контур управления. [желательно]

### 4  Пошаговый процесс
Шаг 1. Аудировать текущее управление
Собрать текущие встречи, отчёты, процессы решений.
Выявить пробелы: что не отслеживается, где решения буксуют.
Оценить нагрузку на собственника.
Шаг 2. Задать управленческий ритм
Определить набор регулярных встреч: дневные, недельные, месячные.
Задать цель, состав и формат каждой.
Избежать избыточных совещаний.
Шаг 3. Построить панель метрик
Определить ключевые метрики для управления (связь с PB-11).
Привязать метрики к владельцам (из PB-30).
Задать целевые значения и триггеры внимания.
Шаг 4. Задать процесс принятия решений
Определить, какие решения на каком уровне принимаются.
Задать формат подготовки решений (данные, варианты).
Использовать Decision Framework из диагностики.
Шаг 5. Настроить эскалацию и отчётность
Задать процесс эскалации проблем.
Настроить регулярную управленческую отчётность.
Замкнуть с обратной связью клиентов (PB-45).
Шаг 6. Оформить и связать
Собрать операционную модель управления.
Связать с дашбордами (PB-11) и оргдизайном (PB-30).
Связать с governance бренда (PB-49).

### 5  Формулы и определения

| Показатель | Формула | Ориентир / комментарий |
| --- | --- | --- |
| Meeting efficiency | Решений на встрече / время | Продуктивность ритма |
| Metric coverage | Управляемых метрик с ревью / всего | Полнота контроля |
| Decision latency | Время от проблемы до решения | Скорость управления |
| Owner dependency | Решений, требующих собственника / всего | Автономность управления |


### 6  Что получается на выходе (Deliverable)
«Операционная модель управления» (DOC):
Аудит управления — текущие встречи, отчёты, пробелы.
Управленческий ритм — встречи с целями и форматом.
Панель метрик — метрики, владельцы, цели.
Процесс решений — уровни и формат принятия.
Эскалация и отчётность — процессы и регулярность.

### 7  Критерии приёмки
Работа считается выполненной, когда выполнены все условия ниже.
✓  Проведён аудит текущего управления.
✓  Задан управленческий ритм без избыточных встреч.
✓  Построена панель метрик с владельцами и целями.
✓  Задан процесс принятия решений по уровням.
✓  Настроены эскалация и регулярная отчётность.
✓  Связано с PB-11, PB-30, PB-49.

### 8  Типовые ошибки

| Ошибка | Чем грозит | Как избежать |
| --- | --- | --- |
| Управление в ручном режиме | Зависимость от собственника | Задать ритм и делегирование решений |
| Встречи без результата | Потеря времени | Каждая встреча с целью и решениями |
| Решения без данных | Реактивность и ошибки | Подготовка решений с данными |
| Нет эскалации | Проблемы всплывают поздно | Настроить процесс эскалации |
