# Глава 11. Information Architecture (IA)

## 11.1 Что такое Information Architecture
Information Architecture (IA) — это система организации, структурирования, классификации и взаимосвязи информации внутри цифрового продукта.
Для eCommerce информационная архитектура определяет:
структуру каталога;
дерево категорий;
принципы навигации;
внутренние взаимосвязи страниц;
логику поиска;
систему фильтрации;
структуру URL;
информационные модели страниц.
До начала проектирования любого интерфейса должна быть разработана IA.
Дизайн без информационной архитектуры приводит к хаотичной навигации, дублированию информации и росту технического долга.

## 11.2 Цели Information Architecture
Качественная IA должна обеспечивать:
быстрое нахождение информации;
предсказуемую навигацию;
минимальную глубину поиска;
масштабируемость каталога;
поддержку SEO;
поддержку фильтрации;
поддержку персонализации;
простоту сопровождения.

## 11.3 Принципы построения IA

### Принцип 1. От пользователя, а не от компании
Структура должна строиться вокруг пользовательской логики.
Неправильно:
Продукция
↓
Серия А
↓
Линейка Х
↓
Коллекция 2026
Правильно:
Для спальни
↓
Пледы
↓
Шерстяные
↓
200×220
Пользователь мыслит задачами, а не внутренней организационной структурой компании.

### Принцип 2. Взаимоисключающие категории
Каждый товар должен иметь очевидное место в структуре.
Если один товар одновременно подходит в несколько категорий, это решается через:
дополнительные категории;
фильтрацию;
теги;
рекомендации.
Не следует создавать дублирующие разделы.

### Принцип 3. Масштабируемость
Структура должна учитывать рост каталога.
Плохая архитектура работает при 500 товарах, но становится неуправляемой при 50 000 SKU.
Перед проектированием необходимо учитывать:
потенциальный рост ассортимента;
новые бренды;
новые рынки;
новые языки;
новые типы товаров.

### Принцип 4. Минимальная глубина
Любой товар должен быть доступен за минимальное количество переходов.
Рекомендуемая глубина:
Главная
↓
Категория
↓
Подкатегория
↓
Карточка
Чем больше уровней, тем выше вероятность потери пользователя.

### Принцип 5. Последовательность
Одинаковые сущности должны иметь одинаковую структуру.
Если один раздел использует фильтрацию слева, остальные категории также должны использовать аналогичную модель.

## 11.4 Основные элементы IA
Информационная архитектура интернет-магазина состоит из нескольких взаимосвязанных уровней.

### Глобальная навигация
Определяет основные разделы сайта.
Например:
Каталог
Акции
Новинки
Бренды
Доставка
Оплата
Блог
Контакты

### Каталог
Каталог является ядром IA.
Основные требования:
логичное деление;
отсутствие пересечений;
поддержка фильтрации;
поддержка SEO;
поддержка поиска.

### Категории
Категория объединяет товары по понятному пользователю признаку.
Категории должны быть:
взаимоисключающими;
понятными;
масштабируемыми;
устойчивыми во времени.

### Подкатегории
Используются только тогда, когда действительно упрощают навигацию.
Не рекомендуется создавать уровни вложенности без необходимости.

### Карточка товара
Конечная точка большинства пользовательских сценариев.
IA определяет:
состав блоков;
последовательность информации;
взаимосвязь с другими страницами.

## 11.5 Каркас информационной архитектуры
Для большинства eCommerce проектов используется следующая модель.
Главная
│
├── Каталог
│      ├── Категория
│      │       ├── Подкатегория
│      │       │        ├── Товар
│      │       │        ├── Товар
│      │       │        └── Товар
│      │       └── Подкатегория
│      └── Категория
├── Бренды
├── Акции
├── Новинки
├── Блог
├── FAQ
├── Доставка
├── Оплата
├── Возврат
├── Контакты
└── Личный кабинет

## 11.6 Глубина навигации
Каждый дополнительный уровень увеличивает вероятность потери пользователя.
Рекомендуемые значения.
Главная
↓
Категория
↓
Подкатегория
↓
Товар
Максимум четыре уровня.
Исключения допускаются только при очень больших каталогах.

## 11.7 Логика построения категорий
Существует несколько моделей.

### По типу товара
Ноутбуки
Телевизоры
Холодильники

### По назначению
Для дома
Для офиса
Для путешествий

### По аудитории
Для мужчин
Для женщин
Для детей

### По бренду
Apple
Samsung
Sony

### По сценарию использования
Подарки
Для ремонта
Для кемпинга
Для автомобиля
На практике часто используется комбинированная модель.

## 11.8 Принцип “От общего к частному”
Структура должна последовательно уменьшать количество вариантов выбора.
Пример.
Электроника
↓
Ноутбуки
↓
Игровые ноутбуки
↓
ASUS
↓
ROG
↓
Карточка товара
Каждый уровень уменьшает количество доступных вариантов.

## 11.9 Навигационные модели
Информационная архитектура должна включать несколько уровней навигации.

### Global Navigation
Основные разделы сайта.

### Local Navigation
Навигация внутри категории.

### Context Navigation
Связанные товары.
Похожие товары.
Комплекты.
Совместимые товары.

### Utility Navigation
Авторизация.
Профиль.
Корзина.
Избранное.

### Footer Navigation
Служебные страницы.

## 11.10 Проверка качества IA
Информационная архитектура должна проходить обязательную валидацию.
Используются методы:
Card Sorting;
Tree Testing;
First Click Testing;
Navigation Testing;
Search Analytics;
Heatmaps;
Session Replay.

## 11.11 Типичные ошибки
Проектирование структуры на основе внутренних процессов компании.
Избыточная вложенность категорий.
Дублирование категорий.
Пересекающиеся категории.
Непонятные названия разделов.
Разные принципы классификации в пределах одного уровня.
Отсутствие масштабируемости.
Игнорирование SEO.
Игнорирование поиска.
Игнорирование фильтрации.
Создание структуры исключительно под текущий ассортимент.

## 11.12 Deliverables
После проектирования Information Architecture должны быть подготовлены следующие артефакты:
Master Sitemap;
Category Tree;
Taxonomy Document;
Content Inventory;
Navigation Map;
Entity Relationship Map;
Content Model;
URL Structure;
Page Hierarchy;
Information Architecture Specification;
IA Validation Report.
