# Глава 60. Enterprise Anti-Patterns Encyclopedia

## 60.1 Назначение энциклопедии Anti-Patterns
Если Best Practices показывают, что следует делать, то Anti-Patterns объясняют, чего необходимо избегать.
Большинство ошибок в eCommerce повторяются из проекта в проект.
Цель энциклопедии:
предотвращение типичных ошибок;
сокращение UX Debt;
повышение качества проектирования;
ускорение Design Review;
повышение конверсии.
Полная энциклопедия должна содержать более 1500 Anti-Patterns.

## 60.17 Severity Matrix

| Severity | Описание |
| --- | --- |
| Critical | Блокирует выполнение ключевых сценариев или создаёт существенный риск для бизнеса |
| High | Значительно ухудшает UX или коммерческие показатели |
| Medium | Вызывает неудобства, но существуют обходные пути |
| Low | Незначительно влияет на пользовательский опыт |
| Recommendation | Потенциальная возможность улучшения |

## 60.19 Anti-Pattern Detection Checklist
Для каждого Anti-Pattern определяется:
где возникает;
как обнаружить;
какими метриками подтверждается;
какие пользовательские сценарии страдают;
влияние на KPI;
рекомендуемый способ исправления;
сложность устранения;
ожидаемый эффект после исправления.

## 60.20 KPI Anti-Patterns

| KPI | Назначение |
| --- | --- |
| UX Debt Index | Объём накопленных UX-проблем |
| Critical Anti-Patterns | Количество критических ошибок |
| Anti-Pattern Resolution Rate | Скорость устранения проблем |
| Repeat Issue Rate | Частота повторного появления одинаковых ошибок |
| Design Review Prevention Rate | Доля ошибок, предотвращённых до разработки |
| Production UX Defect Rate | UX-дефекты, обнаруженные после релиза |
| Root Cause Resolution Rate | Доля устранённых первопричин |
| Anti-Pattern Coverage | Покрытие библиотеки типовыми ошибками |
