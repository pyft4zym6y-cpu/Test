# Глава 29. Personal Account (My Account / Customer Dashboard)

## 29.1 Роль личного кабинета
Личный кабинет — это персональный цифровой центр взаимодействия клиента с компанией после первой покупки.
Во многих интернет-магазинах личный кабинет ограничивается отображением истории заказов.
Это стратегическая ошибка.
Современный Customer Dashboard должен выполнять четыре функции:
управление покупками;
управление персональными данными;
управление отношениями с компанией;
стимулирование повторных продаж.
Личный кабинет является одним из основных инструментов удержания клиентов (Retention).

## 29.2 Цели Personal Account
Современный личный кабинет должен:
сокращать количество обращений в поддержку;
ускорять повторные покупки;
повышать Lifetime Value (LTV);
увеличивать Retention;
повышать удовлетворённость клиентов;
обеспечивать полный self-service.

## 29.4 Dashboard
Главная страница кабинета должна отвечать на вопрос:
Что сейчас наиболее важно для пользователя?
Рекомендуемый состав.
Последний заказ.
↓
Статус доставки.
↓
Бонусы.
↓
Персональные предложения.
↓
Недавно просмотренные товары.
↓
Быстрый повтор заказа.
↓
Избранное.
↓
Уведомления.
Dashboard должен быть максимально персонализирован.

## 29.5 Orders
История заказов является ядром кабинета.
Каждая карточка заказа должна содержать:
Номер.
↓
Дата.
↓
Статус.
↓
Стоимость.
↓
Состав заказа.
↓
Повторить заказ.
↓
Документы.
↓
Возврат.
↓
Отслеживание.
↓
Поддержка.

## 29.6 Order Details
Страница заказа должна содержать:
полную информацию о товарах;
стоимость;
скидки;
применённые бонусы;
способ оплаты;
адрес доставки;
статус доставки;
трек-номер;
историю изменения статусов;
документы.
Пользователь не должен обращаться в поддержку для получения этой информации.

## 29.7 Repeat Order
Повторная покупка должна выполняться одним действием.
Например.
Повторить заказ
↓
Добавить все товары в корзину
↓
Проверка наличия
↓
Checkout
При отсутствии отдельных товаров необходимо предложить аналоги.

## 29.8 Returns
Раздел возвратов должен содержать:
доступные товары для возврата;
статус заявок;
инструкции;
адрес возврата;
историю возвратов;
денежные компенсации.
Все этапы должны быть прозрачны.

## 29.9 Wishlist
Избранное должно поддерживать:
несколько списков;
совместный доступ;
уведомления о снижении цены;
уведомления о появлении товара;
быстрый перенос в корзину;
фильтрацию и сортировку.

## 29.10 Compare
Пользователь должен иметь возможность:
просматривать список сравнения;
добавлять товары;
удалять товары;
быстро переходить в карточки товаров;
добавлять выбранный товар в корзину.

## 29.11 Saved Addresses
Поддерживаются:
домашний адрес;
рабочий адрес;
адрес получателя;
самовывоз;
несколько адресов доставки.
Каждый адрес можно:
создать;
изменить;
удалить;
назначить основным.

## 29.12 Payment Methods
Если бизнес-модель допускает хранение платёжных данных, пользователь должен иметь возможность:
добавить способ оплаты;
удалить;
назначить способом по умолчанию;
просмотреть последние операции.
Конфиденциальные данные отображаются только в безопасном формате.

## 29.13 Loyalty Dashboard
Отображаются:
баланс бонусов;
история начислений;
история списаний;
доступный уровень программы;
следующий уровень;
индивидуальные предложения.
Пользователь должен понимать:
сколько бонусов доступно;
когда они истекают;
как их использовать.

## 29.14 Coupons
Раздел содержит:
активные промокоды;
использованные;
истёкшие;
персональные предложения.
Промокоды должны применяться автоматически, если это возможно.

## 29.15 Notifications Center
Все уведомления собираются в одном месте.
Например.
Статусы заказов.
↓
Возвраты.
↓
Начисление бонусов.
↓
Изменение цены в избранном.
↓
Появление товара.
↓
Ответ поддержки.
↓
Акции.
Пользователь должен управлять каждым типом уведомлений отдельно.

## 29.16 Documents
Раздел документов включает:
чеки;
счета;
накладные;
гарантийные талоны;
сертификаты;
акты возврата.
Все документы должны быть доступны для скачивания.

Чат.
↓
FAQ.
↓
Телефон.
↓
Email.
↓
Статусы заявок.

## 29.18 Subscription Management
Пользователь управляет:
Email.
SMS.
Push.
Telegram.
WhatsApp.
Маркетинговыми сообщениями.
Транзакционными уведомлениями.
Каждый канал настраивается отдельно.

## 29.19 Security Center
Раздел безопасности включает:
смену пароля;
двухфакторную аутентификацию;
историю входов;
активные устройства;
управление сессиями;
удаление аккаунта.
Все действия сопровождаются подтверждением.

## 29.20 Personalization
Dashboard может содержать:
рекомендации;
персональные подборки;
историю просмотров;
товары, ожидающие снижения цены;
предложения по повторной покупке;
индивидуальные акции.
Персонализация должна помогать пользователю, а не перегружать интерфейс.

## 29.21 Mobile Dashboard
На мобильных устройствах рекомендуется:
карточный интерфейс;
фиксированную нижнюю навигацию;
быстрые действия;
компактные виджеты;
минимальное количество текста.

## 29.22 Analytics
Необходимо отслеживать:
Dashboard View;
Order Details View;
Repeat Order;
Wishlist Usage;
Compare Usage;
Bonus View;
Coupon Usage;
Address Update;
Notification Open;
Document Download;
Support Request;
Logout.

## 29.23 KPI Personal Account

| KPI | Назначение |
| --- | --- |
| Active Account Rate | Доля активных пользователей кабинета |
| Repeat Order Rate | Повторные покупки через кабинет |
| Wishlist Usage | Использование избранного |
| Loyalty Engagement | Активность в программе лояльности |
| Support Deflection Rate | Снижение обращений в поддержку за счёт self-service |
| Profile Completion Rate | Полнота профиля |
| Notification Engagement | Взаимодействие с уведомлениями |
| Average Dashboard Session | Средняя продолжительность сессии |


## 29.24 Типичные ошибки
Личный кабинет содержит только историю заказов.
Отсутствует повторный заказ.
Нет управления возвратами.
Нельзя скачать документы.
Нет центра уведомлений.
Отсутствует управление безопасностью.
Избранное не синхронизируется между устройствами.
Персонализация отсутствует или нерелевантна.
Нет мобильной оптимизации.

## 29.25 Personal Account QA Checklist
Перед запуском необходимо проверить:
Dashboard отображает наиболее важную информацию;
история заказов полная и удобна;
повторный заказ выполняется в один-два клика;
возвраты доступны без обращения в поддержку;
документы доступны для скачивания;
управление адресами и способами оплаты интуитивно понятно;
раздел безопасности соответствует требованиям;
аналитика настроена;
Accessibility соблюдена;
интерфейс протестирован на Desktop, Tablet и Mobile.
