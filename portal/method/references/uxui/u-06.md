# Глава 21. UI Components Library … Глава 23. Product Detail Page (PDP)

## Глава 21. UI Components Library

## 21.1 Введение
UI Components Library — это централизованная библиотека всех повторно используемых элементов интерфейса.
В Enterprise eCommerce библиотека компонентов является фундаментом:
Design System;
Front-end Framework;
UX Consistency;
масштабируемости продукта;
скорости разработки;
качества интерфейсов.
Каждый компонент должен существовать в библиотеке только один раз.
Любое изменение выполняется централизованно.

## 21.2 Архитектура библиотеки компонентов

### Composite Components

## Глава 22. Product Listing Page (PLP)

## 22.1 Роль Product Listing Page
Product Listing Page (PLP) — страница отображения списка товаров, являющаяся центральным элементом большинства пользовательских сценариев eCommerce.
Практически каждый пользователь проходит через PLP перед переходом в карточку товара.
Основные задачи страницы:
помочь пользователю быстро найти подходящий товар;
сократить количество вариантов до управляемого уровня;
обеспечить сравнение товаров;
ускорить переход к покупке;
предоставить необходимый минимум информации для принятия решения.
PLP не должна пытаться заменить карточку товара.
Её задача — помочь пользователю выбрать, какой товар стоит изучить подробнее.

## 22.2 Цели Product Listing Page
Правильно спроектированная PLP должна обеспечивать:
быстрое сканирование каталога;
удобную фильтрацию;
понятную сортировку;
минимальное время поиска товара;
высокую производительность;
качественную мобильную адаптацию;
поддержку SEO;
интеграцию с аналитикой;
персонализацию выдачи.

## 22.6 Заголовок категории
Должен содержать:
Название категории.
Количество товаров.
Краткое описание (при необходимости).
SEO-текст не должен мешать пользовательскому сценарию.

## 22.7 Product Count
Количество найденных товаров должно обновляться динамически.
Например.
Найдено 342 товара
После применения фильтров.
Найдено 27 товаров
Это снижает неопределённость пользователя.

## 22.8 Сортировка
Сортировка должна быть независимой от фильтрации.
Рекомендуемый набор.
По популярности.
По релевантности.
По цене ↑
По цене ↓
По рейтингу.
По отзывам.
По новизне.
По скидке.
По наличию.
Не рекомендуется использовать более 8–10 вариантов сортировки.

## 22.9 Переключение вида
Допускаются режимы.
Grid View.
List View.
Compact View.
Выбранный режим должен сохраняться между посещениями.

## 22.10 Product Grid
Grid является ядром PLP.
Основные требования.
Равномерная сетка.
Одинаковая высота карточек.
Понятные интервалы.
Высокая скорость сканирования.
Рекомендуемое количество карточек.
Desktop.
4–5 колонок.
Tablet.
3 колонки.
Mobile.
2 колонки.
В отдельных случаях допустима одна колонка (например, B2B или технические товары с большим количеством характеристик).

## 22.11 Product Card
Каждая карточка должна содержать только информацию, необходимую для выбора товара.

## 22.12 Quick Actions

Quick Add to Cart.
Quick View.
Wishlist.
Compare.

Быстрые действия не должны визуально конкурировать с основной CTA.

## 22.13 Hover Behavior (Desktop)
При наведении допустимо:
отображение второй фотографии;
быстрый просмотр;
кнопка покупки;
выбор варианта;
дополнительные характеристики.
Запрещается смещение соседних карточек или изменение размеров сетки.

## 22.14 Mobile Behavior
На мобильных устройствах отсутствует Hover.
Поэтому все критически важные действия должны быть доступны без него.
Не допускается скрывать:
цену;
наличие;
CTA;
варианты товара.

## 22.15 Infinite Scroll vs Pagination

#### Pagination
Преимущества:
удобство возврата;
лучшая индексируемость;
предсказуемость;
проще анализировать поведение.
Недостатки:
дополнительный клик;
прерывание сценария.

#### Infinite Scroll
Преимущества:
непрерывный просмотр;
высокая вовлечённость;
меньшее количество действий.
Недостатки:
сложность возврата;
проблемы с футером;
повышенная нагрузка на устройство;
потенциальные сложности для SEO.

#### Гибридная модель (рекомендуется)
Автоматическая подгрузка нескольких страниц с возможностью явного перехода к следующей странице и сохранением URL/позиции просмотра.

## 22.16 Skeleton Loading
Во время загрузки рекомендуется использовать Skeleton вместо Spinner.
Skeleton должен повторять структуру Product Card.
Это снижает субъективное ощущение ожидания.

## 22.17 Empty Category
Если категория не содержит товаров, пользователь должен получить:
объяснение;
альтернативные категории;
поиск;
рекомендации;
контакты поддержки.
Не допускается отображение пустой страницы.

## 22.18 No Results
После применения фильтров возможна ситуация отсутствия результатов.
Страница должна предложить:
сброс фильтров;
изменение диапазона цены;
похожие товары;
популярные категории;
рекомендации.

## 22.19 SEO на PLP
Категория должна содержать:
уникальный Title;
Meta Description;
H1;
структурированные данные;
SEO-текст (ниже основного каталога);
FAQ;
внутреннюю перелинковку;
канонические URL.
SEO не должно ухудшать пользовательский опыт.

## 22.20 Персонализация

акций;

контента.

## 22.23 Accessibility
PLP должна поддерживать:
клавиатурную навигацию;
видимый фокус;
корректные заголовки;
альтернативный текст изображений;
достаточный контраст;
работу без мыши;
корректное объявление изменений результатов поиска и фильтрации для экранных дикторов.

## 22.24 Типичные ошибки
Использование карточек разной высоты.
Перегруженные карточки товаров.
Слишком большое количество бейджей.
Отсутствие информации о наличии.
Скрытая сортировка.
Медленная загрузка изображений.
Смещение элементов во время загрузки (Layout Shift).
Отсутствие состояния “Нет результатов”.
Несогласованность фильтрации и сортировки.
Отсутствие аналитики взаимодействия с каталогом.

## 22.25 PLP Quality Checklist
Перед выпуском страницы необходимо проверить:

## Глава 23. Product Detail Page (PDP)

## 23.1 Product Detail Page как центр eCommerce
Карточка товара (Product Detail Page, PDP) является наиболее важной страницей интернет-магазина.
Именно на ней пользователь принимает решение:
покупать;
отложить покупку;
сравнить с конкурентами;
покинуть сайт.
Практически все предыдущие страницы (Главная, Каталог, Поиск, Категории, Фильтрация) существуют только для того, чтобы привести пользователя в карточку товара.
Следовательно, Product Detail Page должна проектироваться как самостоятельный цифровой продукт.

## 23.2 Основные цели PDP
Карточка товара должна одновременно решать несколько задач.

#### Пользовательские
понять, подходит ли товар;
получить ответы на все вопросы;
убедиться в надежности магазина;
оформить покупку максимально быстро.

#### Бизнес-задачи
увеличить Add to Cart Rate;
увеличить Conversion Rate;
увеличить Average Order Value;
увеличить Cross Sell;
увеличить Upsell;
уменьшить количество возвратов;
уменьшить количество обращений в поддержку.

## 23.3 Главный принцип PDP
Карточка товара должна отвечать на вопросы пользователя именно в том порядке, в котором они возникают.
Правильная последовательность.
Что это?
↓
Подойдет ли мне?
↓
Сколько стоит?
↓
Есть ли в наличии?
↓
Когда получу?
↓
Можно ли доверять?
↓
Что говорят другие?
↓
Есть ли альтернатива?
↓
Покупать или нет?
Именно эта последовательность лежит в основе архитектуры PDP.

## 23.24 Cross Sell
Показывает товары, которые дополняют выбранный.
Например:
Чехол.
Защитное стекло.
Зарядное устройство.
Кабель.
Cross Sell должен решать задачу пользователя, а не просто увеличивать количество товаров в корзине.

## 23.25 Upsell
Предлагает более функциональные или дорогие варианты.
Например:
256 GB → 512 GB.
Стандартная модель → Pro.
Upsell должен объяснять ценность улучшенной версии.

Пользователь должен видеть индивидуальную стоимость каждого элемента и итоговую выгоду.

## 23.27 Recently Viewed

Рекомендуется отображать 6–12 последних товаров с возможностью очистки списка.

## 23.30 Типичные ошибки

Незаметная кнопка покупки.
Несколько Primary CTA.
Недостаточное количество фотографий.
Отсутствие отзывов.
Смешивание описания и характеристик.
Непонятный статус наличия.
Отсутствие доверительных элементов.
Длинные неструктурированные тексты.
Полная перезагрузка страницы при выборе варианта товара.

## 23.31 PDP Quality Checklist
Перед выпуском карточки товара необходимо проверить:
первый экран отвечает на ключевые вопросы пользователя;
цена и CTA видны без прокрутки;
галерея поддерживает увеличение и мобильные жесты;
варианты обновляются без перезагрузки;
доставка и оплата отображаются до Checkout;
отзывы и характеристики структурированы;
Cross Sell и Upsell релевантны;
аналитические события настроены;
страница соответствует требованиям Accessibility;
отсутствуют Layout Shift и критические проблемы производительности.
