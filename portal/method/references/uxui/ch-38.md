# Глава 38. Experimentation, CRO & A/B Testing Framework

## 38.1 Роль Experimentation в eCommerce
Современный eCommerce развивается не за счёт интуитивных решений, а за счёт непрерывных экспериментов.
Каждое изменение интерфейса, логики, каталога, маркетинга или Checkout должно рассматриваться как гипотеза.
Главный принцип:
Не мнение определяет решение, а данные.
Эксперименты позволяют:
повышать конверсию;
увеличивать средний чек;
снижать количество отказов;
уменьшать стоимость привлечения клиента;
улучшать пользовательский опыт;
принимать решения на основе статистически подтверждённых результатов.

## 38.2 CRO как процесс
Conversion Rate Optimization (CRO) — это непрерывный цикл.
Исследование
↓
Поиск проблемы
↓
Формирование гипотез
↓
Приоритизация
↓
Эксперимент
↓
Анализ
↓
Внедрение
↓
Мониторинг
↓
Новые гипотезы
CRO никогда не заканчивается.

## 38.5 Формат гипотезы
Каждая гипотеза оформляется по единому шаблону.
Если
↓
Изменить
↓
То
↓
Потому что
↓
Метрика
↓
Ожидаемый эффект
Пример.
Если сделать Sticky Add to Cart на мобильной PDP, то Add to Cart Rate увеличится на 8–12%, потому что CTA будет постоянно доступна при прокрутке.

## 38.9 A/B Testing
Наиболее распространённый формат.
Контроль
↓
50%
↓
Пользователей
──────────────
Новая версия
↓
50%
↓
Пользователей
Сравнивается влияние одного изменения.

## 38.10 Multivariate Testing
Одновременно тестируется несколько факторов.
Например.
Кнопка.
×
Цена.
×
Изображение.
×
Отзывы.
Используется при большом объёме трафика.

## 38.11 Feature Flags
Новые функции рекомендуется запускать через Feature Flags.
Преимущества:
быстрое отключение;
поэтапный запуск;
тестирование отдельных сегментов;
снижение риска.

## 38.13 Метрики экспериментов
Перед запуском необходимо определить:
Primary Metric.
Secondary Metrics.
Guardrail Metrics.
Например.
Primary:
Conversion Rate.
Secondary:
AOV.
Guardrail:
Bounce Rate.

## 38.14 Guardrail Metrics
Guardrail защищают бизнес от ложных побед.
Например.
Конверсия выросла.
↓
Но возвраты увеличились.
↓
Или прибыль снизилась.
↓
Или время загрузки ухудшилось.
Эксперимент считается успешным только при сохранении Guardrail Metrics.

## 38.15 Статистическая значимость
Эксперимент завершается только после достижения заранее определённого уровня статистической достоверности.
Не рекомендуется:
останавливать тест раньше времени;
принимать решение по промежуточным данным;
анализировать слишком маленькую выборку.

## 38.16 Сегментация результатов
Результаты рекомендуется анализировать отдельно по:
Desktop.
Mobile.
Tablet.
Новым пользователям.
Постоянным клиентам.
Источникам трафика.
Странам.
Иногда общий результат скрывает значимые различия между сегментами.

## 38.17 AI-assisted Experimentation
AI может использоваться для:
генерации гипотез;
поиска аномалий;
анализа пользовательского поведения;
приоритизации тестов;
генерации новых вариантов интерфейса.
Окончательное решение о внедрении должно приниматься на основе измеримых результатов.

## 38.18 Post Experiment Review
После завершения каждого эксперимента необходимо зафиксировать:
цель;
гипотезу;
результаты;
победителя;
неожиданные эффекты;
полученные выводы;
рекомендации для следующих тестов.
Каждый эксперимент должен пополнять базу знаний компании.

## 38.19 Experiment Repository
Рекомендуется вести единый реестр.
Каждый эксперимент содержит:
ID.
Описание.
Макеты.
Скриншоты.
Метрики.
Результаты.
SQL-запросы (при необходимости).
BI-отчёты.
Причины принятого решения.
Это предотвращает повторное тестирование уже проверенных идей.

## 38.20 Analytics

Experiment Started;
Variant Assignment;
Variant Exposure;
Primary Metric;
Secondary Metrics;
Guardrail Metrics;
Statistical Significance;
Experiment Completed;
Rollout Completed.

## 38.21 KPI Experimentation

| KPI | Назначение |
| --- | --- |
| Experiments per Month | Количество завершённых экспериментов |
| Win Rate | Доля успешных экспериментов |
| Revenue Lift | Прирост выручки |
| Conversion Lift | Прирост конверсии |
| Average Experiment Duration | Средняя длительность теста |
| Time to Decision | Время до принятия решения |
| Experiment Coverage | Доля продукта, охваченная тестированием |
| Hypothesis Validation Rate | Доля подтверждённых гипотез |
| Rollout Success Rate | Успешность внедрения изменений |


## 38.22 Experimentation Maturity Model

| Уровень | Характеристика |
| --- | --- |
| Level 1 | Разовые A/B-тесты без единой методологии |
| Level 2 | Регулярное тестирование с единым backlog гипотез |
| Level 3 | Централизованная платформа экспериментов и Feature Flags |
| Level 4 | Автоматизированная приоритизация, сегментация и BI-отчётность |
| Level 5 | AI-assisted Experimentation, непрерывная оптимизация и автоматические рекомендации |


## 38.23 Типичные ошибки
Запуск экспериментов без чёткой гипотезы.
Изменение нескольких факторов в обычном A/B-тесте.
Остановка теста до достижения статистической значимости.
Игнорирование Guardrail Metrics.
Отсутствие единого реестра экспериментов.
Повторное тестирование уже проверенных решений.
Отсутствие сегментного анализа.
Внедрение изменений без последующего мониторинга.

## 38.24 Experimentation QA Checklist
Перед запуском необходимо проверить:
гипотеза сформулирована корректно;
определены Primary, Secondary и Guardrail Metrics;
рассчитан необходимый объём выборки;
выбран подходящий тип эксперимента;
настроена аналитика;
определены критерии завершения теста;
предусмотрен план отката изменений;
Feature Flags протестированы;
результаты будут сохранены в общем репозитории знаний.
