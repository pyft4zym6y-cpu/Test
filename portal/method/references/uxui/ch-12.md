# Глава 12. Navigation Design

## 12.1 Что такое Navigation Design
Navigation Design — это система проектирования пользовательских маршрутов внутри цифрового продукта, обеспечивающая быстрое, предсказуемое и интуитивное перемещение между разделами сайта.
Если Information Architecture отвечает на вопрос:
Как организована информация?
то Navigation Design отвечает:
Как пользователь будет перемещаться между этой информацией?
Навигация должна минимизировать время поиска, количество ошибок и когнитивную нагрузку.

## 12.2 Цели Navigation Design
Качественная система навигации должна обеспечивать:
быстрое нахождение информации;
понимание текущего местоположения;
понимание структуры сайта;
возможность быстрого перехода;
возможность возврата;
минимальное количество кликов;
предсказуемость поведения.

## 12.3 Принципы Navigation Design

### Принцип 1. Предсказуемость
Пользователь не должен изучать систему навигации.
Она должна работать так, как он ожидает.
Например:
логотип ведёт на главную;
корзина открывает корзину;
хлебные крошки возвращают вверх по структуре;
меню открывается одинаково на всех страницах.

### Принцип 2. Последовательность
Все элементы навигации должны вести себя одинаково.
Недопустимо:
различные стили меню;
разные способы открытия фильтров;
разные состояния активных пунктов.

### Принцип 3. Видимость
Навигация должна быть легко обнаруживаемой.
Не рекомендуется скрывать основные разделы за дополнительными действиями без необходимости.

### Принцип 4. Минимизация выбора
Навигация должна уменьшать количество решений пользователя.
Каждый следующий уровень должен сужать пространство поиска.

### Принцип 5. Обратная связь
Пользователь всегда должен понимать:
где находится;
куда может перейти;
что уже выбрал;
какие действия доступны.

## 12.4 Уровни навигации
Навигация интернет-магазина состоит из нескольких независимых уровней.

### Global Navigation
Главная система навигации сайта.
Обычно содержит:
Каталог;
Акции;
Новинки;
Бренды;
Блог;
Контакты.
Global Navigation должна быть доступна практически на каждой странице.

### Utility Navigation
Содержит сервисные функции.
Например:
Личный кабинет;
Авторизация;
Избранное;
Сравнение;
Корзина;
Поддержка;
Переключение языка;
Переключение валюты.
Utility Navigation должна быть визуально отделена от основной.

### Local Navigation
Навигация внутри конкретного раздела.
Например:
Категория «Ноутбуки»:
Игровые;
Ультрабуки;
Для работы;
MacBook.

### Contextual Navigation
Навигация, основанная на текущем контексте.
Например:
Похожие товары.
Комплектующие.
Совместимые аксессуары.
Покупают вместе.
Просмотренные товары.

### Footer Navigation
Служебная навигация.
Включает:
Доставку;
Оплату;
Возврат;
Политику конфиденциальности;
Пользовательское соглашение;
Вакансии;
Контакты.
Footer не должен использоваться для размещения критически важных сценариев.

## 12.5 Mega Menu
Mega Menu — основной инструмент навигации крупных eCommerce-проектов.

### Когда использовать
Mega Menu рекомендуется использовать, если:
каталог содержит более 300–500 SKU;
существует более 10 категорий первого уровня;
требуется быстрый доступ к большому количеству разделов.

### Структура Mega Menu
Рекомендуемая структура:
Категория
├── Подкатегория
│      ├── Раздел
│      ├── Раздел
│      ├── Раздел
│      └── Раздел
├── Популярные товары
├── Новинки
├── Акции
└── Баннер

### Правила проектирования Mega Menu
Каждая колонка должна содержать логически связанные элементы.
Основные категории должны визуально отличаться от подкатегорий.
Не рекомендуется использовать более 4–5 уровней вложенности.
Не следует перегружать меню графикой.
Баннеры допустимы только при наличии коммерческой ценности.

## 12.6 Breadcrumbs
Breadcrumb Navigation позволяет пользователю понять своё положение в структуре сайта.
Пример.
Главная
↓
Ноутбуки
↓
Игровые ноутбуки
↓
ASUS
↓
ROG Strix G16
Breadcrumbs должны:
соответствовать IA;
быть кликабельными;
отображаться на всех внутренних страницах.
Типичные ошибки:
использование нестандартных названий;
несоответствие структуре каталога;
отсутствие кликабельности.

## 12.7 Навигация каталога
Каталог должен поддерживать несколько способов навигации.
По категориям.
По брендам.
По сценариям использования.
По акциям.
По новинкам.
По подборкам.
По рекомендациям.
По поиску.
Каждый способ должен быть доступен независимо.

## 12.8 Навигация поиска
Поиск является полноценной системой навигации.
Поиск должен поддерживать:
автодополнение;
исправление опечаток;
синонимы;
морфологию;
популярные запросы;
историю поиска;
рекомендации;
быстрый переход в категории.

## 12.9 Навигация мобильной версии
На мобильных устройствах пространство значительно ограничено.
Поэтому рекомендуется использовать:
Bottom Navigation.
Sticky Header.
Sticky Search.
Off-canvas Menu.
Floating CTA.
Основные действия должны находиться в зоне комфортного доступа большого пальца.

## 12.10 Sticky Navigation
Фиксированные элементы значительно сокращают количество прокрутки.
Допустимо фиксировать:
поиск;
категории;
фильтры;
корзину;
CTA;
кнопку покупки.
Не следует фиксировать слишком большое количество элементов одновременно.

## 12.11 Навигация фильтрации
Фильтрация является частью навигационной системы.
Пользователь должен понимать:
какие фильтры применены;
сколько найдено товаров;
как удалить фильтр;
как сбросить все фильтры;
какие фильтры доступны.
Каждое изменение фильтра должно сопровождаться понятной обратной связью.

## 12.12 Навигация карточки товара
Карточка товара также содержит навигационные элементы.
Например:
галерея;
табуляция;
якорные ссылки;
FAQ;
отзывы;
характеристики;
похожие товары;
совместимые товары.
Все переходы должны быть логичными и не разрывать основной сценарий покупки.

## 12.13 Навигация Checkout
Во время оформления заказа рекомендуется использовать упрощённую навигацию.
Следует скрывать элементы, отвлекающие пользователя:
рекламные баннеры;
второстепенное меню;
большие каталоги.
Основной фокус — завершение покупки.

## 12.14 Проверка качества Navigation Design
Каждая система навигации должна оцениваться по следующим критериям:
время поиска товара;
First Click Success Rate;
Navigation Success Rate;
количество возвратов;
использование поиска;
количество тупиковых страниц;
глубина просмотра;
среднее количество переходов;
процент отказов после открытия меню.

## 12.15 Типичные ошибки
Проектирование навигации по организационной структуре компании.
Использование профессиональной терминологии вместо языка пользователя.
Избыточное количество пунктов первого уровня.
Скрытие основных разделов.
Перегруженное Mega Menu.
Отсутствие мобильной оптимизации.
Разные принципы навигации на разных страницах.
Неочевидные названия категорий.
Несогласованность хлебных крошек с информационной архитектурой.
Отсутствие контекстной навигации.

## 12.16 Deliverables
После проектирования Navigation Design должны быть подготовлены:
Navigation Specification;
Navigation Inventory;
Mega Menu Structure;
Mobile Navigation Map;
Breadcrumb Specification;
Navigation Component Library;
Navigation States Guide;
Navigation Validation Report;
Navigation KPI Dashboard;
Navigation UX Checklist.
