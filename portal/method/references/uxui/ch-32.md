# Глава 32. Navigation Systems & Information Scent

## 32.1 Роль навигации в eCommerce
Навигация — это система, позволяющая пользователю понимать:
где он находится;
какие разделы существуют;
как попасть в нужное место;
как вернуться назад;
какие альтернативные пути доступны.
Навигация является визуальным отображением Information Architecture.
Даже качественная IA теряет ценность, если пользователь не способен её использовать.
Основная задача навигации — минимизировать время поиска информации и снизить когнитивную нагрузку.

## 32.2 Information Scent
Information Scent (“информационный запах”) — степень уверенности пользователя в том, что выбранный путь приведёт к нужному результату.
На каждом этапе пользователь бессознательно отвечает на вопрос:
Если я нажму сюда — получу ли то, что ищу?
Чем сильнее Information Scent, тем выше вероятность продолжения сценария.

## 32.3 Wayfinding
Wayfinding — способность пользователя ориентироваться внутри цифрового продукта.
Пользователь всегда должен понимать:
Где я?
↓
Откуда я пришёл?
↓
Куда могу перейти?
↓
Как вернуться?
↓
Что будет дальше?
Потеря ориентации практически всегда приводит к отказу.

## 32.4 Архитектура навигации
Современная навигация состоит из нескольких уровней.
Global Navigation
↓
Local Navigation
↓
Context Navigation
↓
Utility Navigation
↓
Footer Navigation
Каждый уровень решает собственную задачу.

## 32.5 Global Navigation
Главная навигация отображается на всех страницах.
Обычно включает:
Логотип.
↓
Каталог.
↓
Поиск.
↓
Избранное.
↓
Сравнение.
↓
Личный кабинет.
↓
Корзина.
↓
Контакты.
Глобальная навигация должна быть максимально стабильной.

## 32.6 Mega Menu
Для крупных интернет-магазинов рекомендуется использовать Mega Menu.
Mega Menu позволяет одновременно отображать:
категории;
подкатегории;
бренды;
акции;
изображения;
быстрые ссылки.
Рекомендуемая структура.
Категория
↓
Подкатегория
↓
Группа товаров
↓
Популярные бренды
↓
Акции
↓
Популярные категории

## 32.7 Принципы Mega Menu
Mega Menu должно:
открываться быстро;
не требовать высокой точности курсора;
оставаться стабильным;
закрываться предсказуемо;
работать с клавиатуры.
Не рекомендуется:
использовать более трёх уровней вложенности;
анимировать каждое действие;
использовать сложные Hover-сценарии.

## 32.8 Mobile Navigation
Для мобильных устройств используются:
Bottom Navigation.
↓
Hamburger Menu.
↓
Bottom Sheet.
↓
Search.
Основные действия должны быть доступны без открытия Hamburger Menu.

## 32.9 Breadcrumbs
Breadcrumb Navigation показывает положение пользователя.
Например.
Главная
>
Электроинструмент
>
Шуруповёрты
>
Аккумуляторные
Breadcrumbs должны:
соответствовать IA;
быть кликабельными;
отражать реальную структуру каталога.

## 32.10 Faceted Navigation
Faceted Navigation позволяет уточнять список товаров.
Например.
Категория.
↓
Бренд.
↓
Цена.
↓
Размер.
↓
Материал.
↓
Цвет.
↓
Рейтинг.
↓
Наличие.
Каждый фильтр является независимой характеристикой.

## 32.11 Context Navigation
Контекстная навигация помогает переходить между связанными объектами.
Например.
Похожие товары.
↓
Совместимые товары.
↓
Другие модели бренда.
↓
Категории.
↓
Статьи.
Контекстная навигация увеличивает глубину просмотра.

## 32.12 Utility Navigation
Содержит второстепенные действия.
Например.
Доставка.
Оплата.
Возврат.
Контакты.
Поддержка.
FAQ.
Эти элементы не должны конкурировать с основной навигацией.

## 32.13 Footer Navigation
Footer завершает навигационную систему.
Рекомендуемый состав.
Компания.
↓
Каталог.
↓
Покупателям.
↓
Поддержка.
↓
Контакты.
↓
Социальные сети.
↓
Юридическая информация.
↓
Подписка.
Footer используется как дополнительная карта сайта.

## 32.14 Navigation Labels
Названия разделов должны быть максимально понятными.
Хорошо.
Ноутбуки.
Планшеты.
Инструменты.
Пледы.
Плохо.
Решения.
Продукты.
Каталог Plus.
Smart Collection.
Названия должны соответствовать языку пользователя.

## 32.15 Progressive Disclosure
Не следует показывать всю структуру сразу.
Информация раскрывается постепенно.
Категория
↓
Подкатегория
↓
Товары
↓
Характеристики
Это уменьшает когнитивную нагрузку.

## 32.16 Sticky Navigation
Sticky Navigation рекомендуется использовать:
на длинных страницах;
в карточках товаров;
в каталогах;
в документации.
Sticky Header не должен занимать чрезмерную часть экрана.

## 32.17 Navigation Feedback
Каждое действие должно иметь визуальное подтверждение.
Например.
Активный раздел.
↓
Подсветка.
↓
Индикатор.
↓
Анимация.
↓
Состояние выбора.
Пользователь всегда должен понимать, где находится.

## 32.18 Navigation Depth
Рекомендуется ограничивать глубину структуры.
Идеально.
Главная
↓
Категория
↓
Подкатегория
↓
Товар
Глубокая вложенность значительно ухудшает ориентирование.

## 32.19 Cross Navigation
Допустимо использовать дополнительные связи.
Например.
Бренд.
↓
Категория.
↓
Коллекция.
↓
Акция.
↓
Совместимость.
Это повышает вероятность обнаружения товаров.

## 32.20 Navigation Analytics
Необходимо анализировать:
использование меню;
использование поиска;
клики по Breadcrumbs;
использование фильтров;
использование Footer;
глубину навигации;
частоту возвратов;
время поиска товара;
использование Mega Menu.

## 32.21 KPI Navigation

| KPI | Назначение |
| --- | --- |
| Navigation Success Rate | Доля пользователей, достигших нужного раздела без повторных попыток |
| Time to Product | Время до открытия карточки товара |
| Menu CTR | Кликабельность элементов меню |
| Search Usage Rate | Использование поиска вместо навигации |
| Breadcrumb Usage | Использование Breadcrumbs |
| Filter Usage | Использование фильтрации |
| Category Exit Rate | Выходы из категорий |
| Average Navigation Depth | Средняя глубина переходов |
| Navigation Error Rate | Частота возвратов и отмен действий |


## 32.22 Типичные ошибки
Слишком глубокая структура каталога.
Непонятные названия категорий.
Несколько разных навигационных паттернов.
Скрытие поиска.
Перегруженное Mega Menu.
Несоответствие Breadcrumbs реальной структуре.
Отсутствие активного состояния меню.
Перегруженный Footer.
Использование Hover как единственного способа навигации.
Отсутствие аналитики использования навигации.

## 32.23 Navigation QA Checklist
Перед выпуском необходимо проверить:
пользователь всегда понимает своё текущее местоположение;
структура соответствует Information Architecture;
Mega Menu удобно использовать на Desktop;
мобильная навигация оптимизирована под управление одной рукой;
Breadcrumbs работают корректно;
фильтрация не нарушает ориентирование;
поиск доступен с любого ключевого экрана;
навигация поддерживает Accessibility;
аналитика настроена;
протестированы сценарии с большим количеством категорий и SKU.

## 32.24 Deliverables

Mega Menu Specification;
Mobile Navigation Guide;
Breadcrumb Specification;
Faceted Navigation Rules;
Navigation Label Dictionary;
Navigation Analytics Specification;
Navigation KPI Dashboard;
Navigation QA Checklist.
