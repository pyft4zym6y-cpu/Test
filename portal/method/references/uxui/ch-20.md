# Глава 20. Color System

## 20.1 Назначение цветовой системы
Цветовая система (Color System) — это стандартизированный набор цветов, правил их применения и взаимосвязей, обеспечивающий единообразие интерфейсов, поддержку бренда, визуальную иерархию и доступность.
В eCommerce цвет выполняет не декоративную функцию, а служит средством передачи информации, формирования доверия и управления вниманием пользователя.
Каждый цвет в интерфейсе должен иметь функциональное назначение.
Если цвет используется исключительно для украшения, необходимость его применения должна быть обоснована.

## 20.2 Цели Color System
Цветовая система должна обеспечивать:
единообразие интерфейсов;
поддержку брендинга;
формирование визуальной иерархии;
быстрое распознавание состояний;
поддержку Accessibility;
масштабируемость;
поддержку различных тем оформления;
совместимость с Design Tokens.

## 20.3 Архитектура Color System
Рекомендуемая архитектура состоит из четырех уровней.
Primitive Colors
↓
Semantic Colors
↓
Component Colors
↓
Product Theme
Каждый последующий уровень зависит только от предыдущего.

## 20.4 Primitive Colors
Primitive Colors представляют собой базовую палитру.
Например.
Blue 50
Blue 100
Blue 200
Blue 300
Blue 400
Blue 500
Blue 600
Blue 700
Blue 800
Blue 900
Аналогичные шкалы создаются для:
Gray.
Green.
Red.
Orange.
Yellow.
Purple.
Teal.
Primitive Colors никогда не используются напрямую в интерфейсе.

## 20.5 Semantic Colors
Интерфейс должен использовать семантические цвета.
Например.
Primary.
Secondary.
Success.
Error.
Warning.
Info.
Accent.
Disabled.
Border.
Background.
Surface.
Text.
Link.
Semantic Colors позволяют менять фирменную палитру без изменения компонентов.

## 20.6 Design Tokens
Цвета должны использоваться исключительно через токены.
Например.
Color.Primary
Color.Primary.Hover
Color.Primary.Active
Color.Secondary
Color.Background
Color.Surface
Color.Error
Color.Success
Color.Warning
Color.Link
Использование HEX-кодов непосредственно в макетах запрещается.

## 20.7 Цветовые роли
Каждый цвет имеет строго определённую функцию.

### Primary
Главное действие.
Основная CTA.
Активные элементы.

### Secondary
Второстепенные действия.

### Success
Успешное выполнение операции.
Например.
Заказ оформлен.
Оплата выполнена.

### Warning
Предупреждение.
Например.
Заканчивается товар.

### Error
Ошибка.
Например.
Не удалось выполнить оплату.

### Info
Информационные сообщения.

### Neutral
Фоновая информация.
Текст.
Границы.
Контейнеры.

## 20.8 Цвет и визуальная иерархия
Цвет является одним из инструментов формирования приоритетов.
Рекомендуется использовать принцип:
Primary Action
↓
Secondary Action
↓
Passive Elements
↓
Decorative Elements
Количество акцентных цветов должно быть минимальным.

## 20.9 Цветовая система кнопок
Каждая кнопка должна иметь фиксированный цветовой сценарий.
Например.
Primary.
↓
Основной фирменный цвет.
Secondary.
↓
Нейтральный цвет.
Ghost.
↓
Прозрачный фон.
Danger.
↓
Красный.
Success.
↓
Зелёный.
Использование случайных цветов недопустимо.

## 20.10 Состояния компонентов
Каждый компонент должен иметь документированные состояния.
Например.
Button.
Default.
Hover.
Focus.
Pressed.
Disabled.
Loading.
Success.
Error.
Все состояния используют Design Tokens.

## 20.11 Контраст
Контраст обеспечивает читаемость интерфейса.
Проверяется:
Текст ↔ Фон.
Иконка ↔ Фон.
Border ↔ Surface.
Button ↔ Background.
Badge ↔ Background.
Контраст должен соответствовать требованиям WCAG.

## 20.12 Цвет и эмоции
Хотя восприятие цвета зависит от культуры и контекста, в eCommerce обычно используются следующие ассоциации:

| Цвет | Частые ассоциации |
| --- | --- |
| Синий | Надёжность, стабильность, безопасность |
| Зелёный | Подтверждение, экологичность, успех |
| Красный | Ошибка, срочность, акция |
| Оранжевый | Активность, внимание |
| Жёлтый | Предупреждение, новинка |
| Фиолетовый | Премиальность, креативность |
| Серый | Нейтральность, второстепенная информация |

Цвет не должен использоваться как единственный способ передачи смысла.

## 20.13 Цвет в карточке товара
Рекомендуется использовать цветовые акценты только для действительно важных элементов.
Например.
Цена.
Скидка.
CTA.
Статус наличия.
Badges.
Отзывы.
Все остальные элементы должны иметь нейтральное оформление.

## 20.14 Цвет и скидки
Акционные элементы требуют единообразной системы.
Например.
Старая цена.
↓
Серый.
↓
Перечёркнутый текст.
Новая цена.
↓
Высокий контраст.
Размер скидки.
↓
Badge.
Акция.
↓
Отдельный Accent.
Пользователь должен мгновенно различать обычную цену и акционное предложение.

## 20.15 Dark Mode
Если продукт поддерживает тёмную тему, необходимо определить:
палитру Surface;
палитру Background;
текст;
состояния;
изображения;
иллюстрации;
иконки.
Нельзя получать Dark Mode простым инвертированием цветов.

## 20.16 Brand Colors
Фирменные цвета используются ограниченно.
Основные области применения:
логотип;
Primary CTA;
акцентные элементы;
навигация;
маркетинговые блоки.
Не рекомендуется окрашивать весь интерфейс в фирменный цвет.

## 20.17 Цвет и Accessibility
Цвет не должен быть единственным способом передачи информации.
Например.
Неправильно.
Ошибка отображается только красным цветом.
Правильно.
Ошибка сопровождается:
иконкой;
цветом;
текстом.
Также проверяется восприятие интерфейса пользователями с различными формами нарушения цветового зрения.

## 20.18 Темизация
Color System должна поддерживать:
Light Theme;
Dark Theme;
White Label;
Multi Brand;
Seasonal Themes.
Все темы должны использовать единую систему токенов.

## 20.19 Проверка качества Color System
Перед выпуском интерфейса необходимо проверить:
отсутствие прямых HEX-значений;
использование только токенов;
достаточный контраст;
единое использование семантических цветов;
корректность состояний компонентов;
соответствие брендбуку;
поддержку всех тем оформления.

## 20.20 Типичные ошибки
Использование большого количества акцентных цветов.
Использование цвета как единственного способа передачи смысла.
Недостаточный контраст текста.
Прямое использование HEX-кодов.
Отсутствие семантических токенов.
Несогласованность между Figma и кодом.
Различные оттенки одного и того же цвета в разных компонентах.
Отсутствие Dark Mode.
Отсутствие проверки на дальтонизм.
Использование насыщенных цветов для больших областей интерфейса.

## 20.21 Deliverables
По результатам разработки должны быть подготовлены:
Color System Specification;
Primitive Palette;
Semantic Color Tokens;
Theme Tokens;
Component Color Rules;
Dark Mode Specification;
Brand Color Guide;
Contrast Compliance Report;
Accessibility Color Checklist;
Color Governance Guide;
Color QA Checklist.
