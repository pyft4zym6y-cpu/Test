# Глава 57. Enterprise Templates, Deliverables & Documentation Standards

## 57.1 Документация как продукт
Документация — это не побочный результат проекта.
Это самостоятельный продукт, который:
снижает зависимость от отдельных сотрудников;
ускоряет адаптацию новых участников;
обеспечивает повторяемость процессов;
уменьшает количество ошибок;
сохраняет знания компании.
Каждый документ должен иметь владельца, версию и жизненный цикл.

## 57.22 Naming Convention
Рекомендуемый формат.
AREA_DOCUMENT_VERSION_DATE
Например
UX_PDP_Wireframe_v1.4
Analytics_EventDictionary_v2.1
PRD_Checkout_v3.0
Именование должно быть единообразным во всей организации.

## 57.24 Documentation Governance
Необходимо определить:
владельца документа;
процесс утверждения;
процесс изменения;
версионирование;
архивирование;
периодичность пересмотра.
Документация должна обновляться одновременно с изменением продукта.

## 57.25 KPI Documentation

| KPI | Назначение |
| --- | --- |
| Documentation Coverage | Доля процессов, имеющих документацию |
| Documentation Freshness | Актуальность документов |
| Documentation Completeness | Полнота описания |
| Template Adoption | Использование корпоративных шаблонов |
| Review Compliance | Прохождение обязательных Review |
| Documentation Reuse | Повторное использование шаблонов |
| Time to Documentation | Время подготовки документа |
| Knowledge Availability | Доступность знаний для команд |
| Documentation Quality Score | Комплексная оценка качества документации |
| Documentation Update SLA | Соблюдение сроков актуализации документов |


## 57.26 Типичные ошибки
Создание документов без владельца.
Несколько версий одного документа.
Хранение документов в разных местах.
Отсутствие истории изменений.
Документы, не соответствующие реальному продукту.
Избыточная детализация без практической ценности.
Отсутствие единых шаблонов.
Отсутствие регулярного пересмотра.

## 57.27 Documentation QA Checklist
Перед публикацией необходимо проверить:
документ использует корпоративный шаблон;
указаны версия, автор и владелец;
ссылки на связанные документы актуальны;
терминология соответствует корпоративному глоссарию;
документ прошёл Review;
определены критерии применения;
история изменений заполнена;
документ опубликован в едином репозитории;
предыдущая версия архивирована;
установлен срок следующего пересмотра.
