# Глава 58. Enterprise Knowledge Management & Continuous Improvement Framework

## 58.1 Knowledge как стратегический актив
В зрелой eCommerce-компании знания становятся таким же важным активом, как:
клиенты;
технологии;
данные;
бренд;
интеллектуальная собственность.
Если знания существуют только в головах сотрудников, организация остаётся уязвимой.
Knowledge Management обеспечивает сохранение, передачу и развитие экспертизы.

## 58.5 Knowledge Lifecycle
Любое знание проходит жизненный цикл.
Created
↓
Reviewed
↓
Approved
↓
Published
↓
Used
↓
Updated

Устаревшие знания не должны использоваться.

## 58.6 Knowledge Capture
После каждого проекта необходимо сохранить:
решения;
ошибки;
успешные практики;
метрики;
инсайты;
эксперименты;
причины принятых решений.
Опыт должен оставаться в компании независимо от смены сотрудников.

## 58.7 Lessons Learned
После каждого крупного этапа проводится анализ.
Что планировали?
↓
Что произошло?
↓
Почему?
↓
Что удалось?
↓
Что не удалось?
↓
Что изменить?
↓
Какие рекомендации?
Lessons Learned становятся частью корпоративной базы знаний.

## 58.20 KPI Knowledge Management

| KPI | Назначение |
| --- | --- |
| Knowledge Coverage | Покрытие процессов документацией |
| Knowledge Freshness | Актуальность знаний |
| Search Success Rate | Успешность поиска информации |
| Documentation Reuse | Повторное использование документов |
| Lessons Learned Adoption | Использование накопленного опыта |
| Knowledge Contribution Rate | Активность авторов |
| Time to Find Information | Время поиска нужной информации |
| Knowledge Quality Score | Качество базы знаний |
| Training Completion Rate | Прохождение обучения |
| Continuous Improvement Rate | Количество внедрённых улучшений |


## 58.21 Enterprise Knowledge Maturity Model

| Уровень | Характеристика |
| --- | --- |
| Level 1 | Знания распределены между отдельными сотрудниками |
| Level 2 | Существует централизованная документация |
| Level 3 | Формализованная база знаний с Playbooks, шаблонами и стандартами |
| Level 4 | Корпоративная система управления знаниями с Communities of Practice и Lessons Learned |
| Level 5 | AI-поддерживаемая Learning Organization с непрерывным обновлением знаний, поиском по корпоративной базе и системным развитием компетенций |


## 58.22 Типичные ошибки
Документация без владельцев.
Отсутствие обновлений.
Повторное решение уже известных проблем.
Потеря знаний при увольнении сотрудников.
Разрозненные источники информации.
Отсутствие Decision Log.
Игнорирование Lessons Learned.
Сложный поиск информации.
Отсутствие культуры обмена знаниями.

## 58.23 Knowledge QA Checklist
Перед публикацией необходимо проверить:
материал прошёл экспертную проверку;
назначен владелец;
определена дата следующего пересмотра;
документ связан с другими материалами;
используется единая терминология;
информация пригодна для практического применения;
знания доступны через корпоративный поиск;
предыдущие версии архивированы;
материал включён в программу обучения при необходимости;
определены KPI использования.
