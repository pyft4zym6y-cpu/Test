## Глава 30. Personalization & Recommendation Systems

## 30.1 Роль персонализации в eCommerce
Персонализация — это адаптация пользовательского опыта под конкретного пользователя на основе его поведения, предпочтений, контекста и прогнозируемых намерений.
Современный eCommerce больше не должен показывать одинаковый магазин всем посетителям.
Каждый пользователь имеет:
различную историю покупок;
различные интересы;
различный бюджет;
различные цели;
различную вероятность покупки.
Следовательно, интерфейс должен адаптироваться под каждого пользователя.
Персонализация должна помогать пользователю принимать решения быстрее, а не усложнять интерфейс.

## 30.2 Цели персонализации
Грамотно реализованная персонализация должна увеличивать:
Conversion Rate;
Average Order Value (AOV);
Lifetime Value (LTV);
Repeat Purchase Rate;
Retention;
Customer Satisfaction;
Engagement.
При этом необходимо минимизировать ощущение навязчивости.

## 30.23 Типичные ошибки
Показывать одинаковые рекомендации всем пользователям.
Чрезмерная персонализация, нарушающая предсказуемость интерфейса.
Использование устаревших данных.
Нерелевантные рекомендации.
Навязчивые предложения в Checkout.
Игнорирование новых пользователей без истории.
Отсутствие A/B-тестирования алгоритмов.
Невозможность отключить персонализацию там, где это требуется.

персонализация не нарушает навигацию;
рекомендации не препятствуют основному пользовательскому сценарию;
аналитика и A/B-тестирование настроены;
соблюдены требования конфиденциальности и прозрачности использования данных;
интерфейс корректно работает на Desktop, Tablet и Mobile.

## Глава 31. Mobile UX & Responsive eCommerce

## 31.1 Mobile First как стратегия
Mobile UX — это не адаптация Desktop-интерфейса под меньший экран.
Это самостоятельная стратегия проектирования, в которой мобильное устройство рассматривается как основная платформа взаимодействия пользователя с интернет-магазином.
Во многих категориях eCommerce более половины всех сессий приходится на мобильные устройства.
Следовательно, качество Mobile UX напрямую влияет на:
Conversion Rate;
Bounce Rate;
Average Session Duration;
Add to Cart Rate;
Checkout Completion Rate;
Revenue.
Проектирование должно начинаться с Mobile First, а не заканчиваться адаптацией Desktop-макета.

## 31.2 Принципы Mobile UX
Мобильный интерфейс должен соответствовать следующим принципам:
минимальное количество действий;
максимальная скорость взаимодействия;
управление одной рукой;
понятная навигация;
высокая производительность;
простота сканирования информации;
отсутствие лишних элементов.

## 31.3 Архитектура мобильного интерфейса

Home
↓

↓

↓
Product

↓

↓

Каждый переход должен занимать минимальное количество действий.

## 31.4 Thumb Zone
Одним из важнейших факторов Mobile UX является зона досягаемости большого пальца.
Экран условно делится на три зоны.

### Easy Zone
Нижняя центральная часть экрана.
Здесь рекомендуется размещать:
основные CTA;
нижнюю навигацию;
подтверждение действий;
кнопку Checkout.

### Stretch Zone
Средняя часть экрана.
Допускается размещение:
карточек товаров;
фильтров;
характеристик.

### Hard Zone
Верхние углы.
Не рекомендуется размещать:
основные CTA;
часто используемые действия.

## 31.5 Bottom Navigation
Для мобильных интернет-магазинов рекомендуется использовать нижнюю навигацию.
Типичный состав.
Главная.
Каталог.
Поиск.
Избранное.
Профиль.
Корзина.
Количество пунктов рекомендуется ограничить пятью.

## 31.6 Header
Мобильный Header должен быть максимально компактным.
Рекомендуемый состав.
Логотип.
Поиск.
Корзина.
Меню.
При прокрутке допускается использование Sticky Header.

## 31.7 Search
Поиск должен быть доступен с любого экрана.
Поддерживаются:
Autocomplete.
Voice Search.
Recent Searches.
Popular Searches.
Image Search.
Поиск является одним из самых используемых элементов мобильного eCommerce.

## 31.8 Mobile Category
Каталог должен поддерживать:
быстрые фильтры;
Sticky Filter;
Bottom Sheet;
быстрый сброс фильтров;
отображение количества найденных товаров.
Фильтрация не должна закрывать результаты без явного подтверждения пользователя.

## 31.9 Mobile Product Card
Карточка товара должна содержать:
изображение;
название;
цену;
скидку;
наличие;
CTA.
Дополнительная информация раскрывается по мере необходимости.

## 31.10 Mobile PDP
Карточка товара должна быть переосмыслена.
Первый экран содержит:
галерею;
цену;
CTA;
варианты;
наличие.
При длинной странице рекомендуется использовать Sticky Add to Cart.

## 31.11 Sticky CTA
Кнопка покупки должна оставаться доступной при прокрутке.
Рекомендуемый состав.
Цена.
↓
Название.
↓
CTA.
Sticky Bar особенно эффективен на экранах с длинным описанием товара.

## 31.12 Bottom Sheet
Bottom Sheet рекомендуется использовать вместо полноэкранных модальных окон.
Подходит для:
фильтров;
выбора вариантов;
выбора доставки;
выбора оплаты;
подтверждения действий.
Bottom Sheet сохраняет ощущение контекста и требует меньше когнитивных усилий.

## 31.13 Mobile Cart
Корзина должна содержать:
компактные карточки;
быстрое изменение количества;
Sticky Checkout;
стоимость заказа;
стоимость доставки.
Изменение количества должно выполняться одним касанием.

## 31.14 Mobile Checkout
При проектировании рекомендуется:
использовать цифровые клавиатуры;
разбивать длинные формы;
поддерживать Autofill;
поддерживать Apple Pay и Google Pay;
уменьшать количество обязательных полей.

## 31.15 Жесты
Допустимые жесты:
свайп;
pinch-to-zoom;
долгое нажатие (при необходимости);
горизонтальная прокрутка галереи;
pull-to-refresh (где это уместно).
Критически важные действия не должны зависеть только от жестов.

## 31.16 Производительность
Мобильные интерфейсы особенно чувствительны к скорости.
Необходимо:
оптимизировать изображения;
использовать Lazy Loading;
минимизировать JavaScript;
применять Skeleton вместо Spinner;
избегать Layout Shift.
Каждая дополнительная секунда загрузки увеличивает вероятность отказа.

## 31.17 Responsive Images
Изображения должны:
адаптироваться под разрешение устройства;
использовать современные форматы;
загружаться по мере необходимости;
не ухудшать качество восприятия товара.

## 31.18 Mobile Accessibility
Необходимо обеспечить:
размер интерактивных элементов не менее 44×44 px;
достаточные интервалы между элементами;
поддержку масштабирования;
читаемость текста;
корректную работу экранных дикторов.

## 31.19 Offline Experience
При использовании PWA рекомендуется поддерживать:
кэширование;
просмотр ранее открытых страниц;
сохранённую корзину;
повторную отправку действий после восстановления сети.

## 31.20 PWA
Progressive Web App может обеспечить:
установку на устройство;
Push-уведомления;
офлайн-режим;
быструю загрузку;
полноэкранный режим.
PWA особенно полезны для проектов, где нативное приложение экономически нецелесообразно.

## 31.21 iOS и Android

Apple Pay.
Android:
системную кнопку «Назад»;
различные размеры экранов;
Material-компоненты;
Google Pay.
Интерфейс должен учитывать нативные ожидания пользователей каждой платформы.

## 31.22 Analytics

## 31.24 Типичные ошибки
Механическое уменьшение Desktop-интерфейса.
Слишком маленькие зоны касания.
Отсутствие Sticky CTA.
Скрытие важных действий в меню.
Использование Hover-сценариев.
Сложные формы.
Медленная загрузка.
Перегруженные карточки товаров.
Игнорирование Safe Area.
Отсутствие тестирования на реальных устройствах.

## 31.25 Mobile UX QA Checklist
Перед выпуском необходимо проверить:
управление одной рукой возможно для основных сценариев;
интерактивные элементы имеют достаточный размер;
навигация интуитивно понятна;
Sticky CTA работает корректно;
фильтры реализованы через Bottom Sheet или аналогичный паттерн;
скорость загрузки соответствует целевым требованиям;
поддерживаются жесты, не являясь единственным способом взаимодействия;
Accessibility соблюдена;
аналитика настроена;
интерфейс протестирован на популярных устройствах iOS и Android.

## Глава 32. Navigation Systems & Information Scent

## 32.1 Роль навигации в eCommerce
Навигация — это система, позволяющая пользователю понимать:
где он находится;
какие разделы существуют;
как попасть в нужное место;
как вернуться назад;
какие альтернативные пути доступны.
Навигация является визуальным отображением Information Architecture.
Даже качественная IA теряет ценность, если пользователь не способен её использовать.
Основная задача навигации — минимизировать время поиска информации и снизить когнитивную нагрузку.

## 32.2 Information Scent
Information Scent (“информационный запах”) — степень уверенности пользователя в том, что выбранный путь приведёт к нужному результату.
На каждом этапе пользователь бессознательно отвечает на вопрос:
Если я нажму сюда — получу ли то, что ищу?
Чем сильнее Information Scent, тем выше вероятность продолжения сценария.

## 32.3 Wayfinding
Wayfinding — способность пользователя ориентироваться внутри цифрового продукта.
Пользователь всегда должен понимать:
Где я?
↓
Откуда я пришёл?
↓
Куда могу перейти?
↓
Как вернуться?
↓
Что будет дальше?
Потеря ориентации практически всегда приводит к отказу.

## 32.4 Архитектура навигации
Современная навигация состоит из нескольких уровней.
Global Navigation
↓
Local Navigation
↓
Context Navigation
↓
Utility Navigation
↓
Footer Navigation
Каждый уровень решает собственную задачу.

## 32.5 Global Navigation
Главная навигация отображается на всех страницах.
Обычно включает:
Логотип.
↓
Каталог.
↓
Поиск.
↓
Избранное.
↓
Сравнение.
↓
Личный кабинет.
↓
Корзина.
↓
Контакты.
Глобальная навигация должна быть максимально стабильной.

## 32.6 Mega Menu
Для крупных интернет-магазинов рекомендуется использовать Mega Menu.
Mega Menu позволяет одновременно отображать:
категории;
подкатегории;
бренды;
акции;
изображения;
быстрые ссылки.
Рекомендуемая структура.
Категория
↓
Подкатегория
↓
Группа товаров
↓
Популярные бренды
↓
Акции
↓
Популярные категории

## 32.7 Принципы Mega Menu
Mega Menu должно:
открываться быстро;
не требовать высокой точности курсора;
оставаться стабильным;
закрываться предсказуемо;
работать с клавиатуры.
Не рекомендуется:
использовать более трёх уровней вложенности;
анимировать каждое действие;
использовать сложные Hover-сценарии.

## 32.8 Mobile Navigation
Для мобильных устройств используются:
Bottom Navigation.
↓
Hamburger Menu.
↓
Bottom Sheet.
↓
Search.
Основные действия должны быть доступны без открытия Hamburger Menu.

## 32.9 Breadcrumbs
Breadcrumb Navigation показывает положение пользователя.
Например.
Главная
>
Электроинструмент
>
Шуруповёрты
>
Аккумуляторные
Breadcrumbs должны:
соответствовать IA;
быть кликабельными;
отражать реальную структуру каталога.

## 32.10 Faceted Navigation
Faceted Navigation позволяет уточнять список товаров.
Например.
Категория.
↓
Бренд.
↓
Цена.
↓
Размер.
↓
Материал.
↓
Цвет.
↓
Рейтинг.
↓
Наличие.
Каждый фильтр является независимой характеристикой.

## 32.11 Context Navigation
Контекстная навигация помогает переходить между связанными объектами.
Например.
Похожие товары.
↓
Совместимые товары.
↓
Другие модели бренда.
↓
Категории.
↓
Статьи.
Контекстная навигация увеличивает глубину просмотра.

## 32.12 Utility Navigation
Содержит второстепенные действия.
Например.
Доставка.
Оплата.
Возврат.
Контакты.
Поддержка.
FAQ.
Эти элементы не должны конкурировать с основной навигацией.

## 32.13 Footer Navigation
Footer завершает навигационную систему.
Рекомендуемый состав.
Компания.
↓
Каталог.
↓
Покупателям.
↓
Поддержка.
↓
Контакты.
↓
Социальные сети.
↓
Юридическая информация.
↓
Подписка.
Footer используется как дополнительная карта сайта.

## 32.14 Navigation Labels
Названия разделов должны быть максимально понятными.
Хорошо.
Ноутбуки.
Планшеты.
Инструменты.
Пледы.
Плохо.
Решения.
Продукты.
Каталог Plus.
Smart Collection.
Названия должны соответствовать языку пользователя.

## 32.15 Progressive Disclosure
Не следует показывать всю структуру сразу.
Информация раскрывается постепенно.
Категория
↓
Подкатегория
↓
Товары
↓
Характеристики
Это уменьшает когнитивную нагрузку.

## 32.16 Sticky Navigation
Sticky Navigation рекомендуется использовать:
на длинных страницах;
в карточках товаров;
в каталогах;
в документации.
Sticky Header не должен занимать чрезмерную часть экрана.

## 32.17 Navigation Feedback
Каждое действие должно иметь визуальное подтверждение.
Например.
Активный раздел.
↓
Подсветка.
↓
Индикатор.
↓
Анимация.
↓
Состояние выбора.
Пользователь всегда должен понимать, где находится.

## 32.18 Navigation Depth
Рекомендуется ограничивать глубину структуры.
Идеально.
Главная
↓
Категория
↓
Подкатегория
↓
Товар
Глубокая вложенность значительно ухудшает ориентирование.

## 32.19 Cross Navigation
Допустимо использовать дополнительные связи.
Например.
Бренд.
↓
Категория.
↓
Коллекция.
↓
Акция.
↓
Совместимость.
Это повышает вероятность обнаружения товаров.

## 32.20 Navigation Analytics
Необходимо анализировать:
использование меню;
использование поиска;
клики по Breadcrumbs;
использование фильтров;
использование Footer;
глубину навигации;
частоту возвратов;
время поиска товара;
использование Mega Menu.

## 32.21 KPI Navigation

| KPI | Назначение |
| --- | --- |
| Navigation Success Rate | Доля пользователей, достигших нужного раздела без повторных попыток |
| Time to Product | Время до открытия карточки товара |
| Menu CTR | Кликабельность элементов меню |
| Search Usage Rate | Использование поиска вместо навигации |
| Breadcrumb Usage | Использование Breadcrumbs |
| Filter Usage | Использование фильтрации |
| Category Exit Rate | Выходы из категорий |
| Average Navigation Depth | Средняя глубина переходов |
| Navigation Error Rate | Частота возвратов и отмен действий |


## 32.22 Типичные ошибки
Слишком глубокая структура каталога.
Непонятные названия категорий.
Несколько разных навигационных паттернов.
Скрытие поиска.
Перегруженное Mega Menu.
Несоответствие Breadcrumbs реальной структуре.
Отсутствие активного состояния меню.
Перегруженный Footer.
Использование Hover как единственного способа навигации.
Отсутствие аналитики использования навигации.

## 32.23 Navigation QA Checklist
Перед выпуском необходимо проверить:
пользователь всегда понимает своё текущее местоположение;
структура соответствует Information Architecture;
Mega Menu удобно использовать на Desktop;
мобильная навигация оптимизирована под управление одной рукой;
Breadcrumbs работают корректно;
фильтрация не нарушает ориентирование;
поиск доступен с любого ключевого экрана;
навигация поддерживает Accessibility;
аналитика настроена;
протестированы сценарии с большим количеством категорий и SKU.

## 32.24 Deliverables
По результатам проектирования должны быть подготовлены:

Global Navigation Map;
Mega Menu Specification;
Mobile Navigation Guide;
Breadcrumb Specification;
Faceted Navigation Rules;
Navigation Label Dictionary;
Navigation Analytics Specification;
Navigation KPI Dashboard;
Navigation QA Checklist.
