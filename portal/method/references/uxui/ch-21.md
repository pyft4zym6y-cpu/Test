# Глава 21. UI Components Library

## 21.1 Введение
UI Components Library — это централизованная библиотека всех повторно используемых элементов интерфейса.
В Enterprise eCommerce библиотека компонентов является фундаментом:
Design System;
Front-end Framework;
UX Consistency;
масштабируемости продукта;
скорости разработки;
качества интерфейсов.
Каждый компонент должен существовать в библиотеке только один раз.
Любое изменение выполняется централизованно.

## 21.2 Архитектура библиотеки компонентов
Компоненты рекомендуется разделять по уровням сложности.
Foundation
↓
Primitive Components
↓
Composite Components
↓
Patterns
↓
Templates

### Foundation
Базовые элементы.
Например.
Цвета.
Шрифты.
Отступы.
Иконки.
Grid.

### Primitive Components
Самые простые элементы.
Button.
Input.
Checkbox.
Radio.
Icon.
Avatar.
Divider.

### Composite Components
Состоят из нескольких Primitive Components.
Product Card.
Navbar.
Modal.
Search.
Dropdown.
Accordion.
Carousel.

### Patterns
Объединяют несколько компонентов.
Например.
Checkout Form.
Header.
Catalog Grid.
Product Gallery.

## 21.3 Структура описания компонентов
Каждый компонент должен документироваться по единому шаблону.

#### Назначение
Для чего используется.

#### Когда использовать
В каких сценариях допустимо применение.

#### Когда не использовать
Какие существуют ограничения.

#### Anatomy
Из каких частей состоит компонент.

#### States
Все возможные состояния.

#### Variants
Все допустимые варианты исполнения.

#### Properties
Все настраиваемые параметры.

#### Accessibility
Требования WCAG.

#### Analytics
Какие события должны отправляться.

#### UX Recommendations
Лучшие практики использования.

#### Anti-patterns
Типичные ошибки применения.

## 21.4 Button

### Назначение
Запуск пользовательского действия.

### Anatomy
Контейнер.
↓
Label.
↓
Icon.
↓
Loading Indicator.

### States
Default.
Hover.
Focus.
Pressed.
Loading.
Disabled.
Success.
Error.

### Variants
Primary.
Secondary.
Outlined.
Ghost.
Text.
Icon Only.
Danger.
Success.

### UX Rules
На одном экране рекомендуется использовать только один Primary Button.
Размер области клика — не менее 44×44 px (ориентир для сенсорных устройств).
Текст кнопки должен описывать действие.
Плохо:
“ОК”
Хорошо:
“Оформить заказ”

## 21.5 Input

### Типы
Text.
Email.
Password.
Phone.
Number.
Date.
Search.
Currency.
Каждый Input должен содержать:
Label.
Placeholder.
Helper Text.
Validation.
Error State.
Success State.
Запрещается использовать Placeholder вместо Label.

Содержит:
Input.
Autocomplete.
Suggestions.
History.
Recent Searches.
Popular Queries.
Voice Search.
Image Search.
Состояния.
Idle.
Typing.
Loading.
Results.
No Results.

## 21.7 Dropdown
Используется при ограниченном количестве вариантов.
Если количество значений превышает примерно 20–30, рекомендуется предусмотреть поиск внутри списка.
Состояния.
Closed.
Open.
Hover.
Selected.
Disabled.
Search.
No Results.

## 21.8 Checkbox
Используется при множественном выборе.
Состояния.
Unchecked.
Checked.
Indeterminate.
Disabled.
Error.

## 21.9 Radio
Используется при выборе только одного значения.
Не рекомендуется применять для длинных списков.

## 21.10 Switch
Используется для мгновенного включения или выключения настройки.
Не рекомендуется использовать Switch для действий, требующих подтверждения.

## 21.11 Tooltip
Используется только для дополнительной информации.
Tooltip не должен содержать критически важный контент.

## 21.12 Badge
Используется для отображения статуса.
Например.
Новинка.
Хит.
−20%.
TOP.
Предзаказ.
Количество.
Badge не должен заменять полноценные сообщения интерфейса.

## 21.13 Chip
Используется для:
активных фильтров;
тегов;
категорий;
выбранных значений.
Каждый Chip должен иметь возможность удаления, если представляет пользовательский выбор.

### Обязательные элементы

Цена.

Badge.
Рейтинг.
Отзывы.
Наличие.
CTA.
Wishlist.
Compare.
Quick View (при необходимости).

### Состояния
Стандартное.
Hover.
Нет товара.
Акция.
Предзаказ.
Loading.

### Analytics
Impression.
Click.
Add to Wishlist.
Add to Compare.
Add to Cart.
Quick View.

## 21.15 Price Component
Компонент отображения цены.
Содержит:
Текущую цену.
Старую цену.
Размер скидки.
Экономию.
Стоимость за единицу (при необходимости).

## 21.16 Rating
Содержит:
Количество звёзд.
Количество отзывов.
Средний рейтинг.
Должен поддерживать:
0–5.
Половинные значения.
Отсутствие отзывов.

## 21.17 Product Gallery
Содержит:
Основное изображение.
Миниатюры.
Zoom.
Fullscreen.
Видео.
360°.
AR (если поддерживается).

## 21.18 Accordion
Используется для:
FAQ.
Характеристик.
Описание.
SEO.
Доставка.
Оплата.
Не рекомендуется скрывать критически важную информацию внутри Accordion.

## 21.19 Tabs
Используются только для равнозначных разделов.
Например.
Описание.
Отзывы.
Характеристики.
Доставка.
Не рекомендуется использовать более 6–7 вкладок.

## 21.20 Modal
Используется только для действительно важных сценариев.
Например.
Подтверждение удаления.
Авторизация.
Выбор региона.
Возрастные ограничения.
Недопустимо использовать Modal для навязчивой рекламы, блокирующей основной пользовательский сценарий.

## 21.21 Drawer
Используется преимущественно на мобильных устройствах.
Например.
Фильтрация.
Корзина.
Навигация.
Меню.

## 21.22 Toast
Краткое уведомление.
Продолжительность отображения должна быть ограничена.
Toast не используется для критических ошибок.

## 21.23 Notification
Используется для сообщений, требующих внимания пользователя.
Например.
Ошибка оплаты.
Изменение заказа.
Проблема доставки.

## 21.24 Skeleton
Используется вместо Loader.
Skeleton показывает структуру будущего контента.
Преимущество — снижение субъективного времени ожидания.

## 21.25 Empty State
Каждое пустое состояние должно содержать:
объяснение;
причину;
следующее действие.
Например.
Корзина пуста.
↓
Перейти в каталог.

## 21.26 Error State
Сообщение должно содержать:
что произошло;
почему;
что делать дальше.
Недопустимо:
“Ошибка 500”
Правильно:
“Не удалось загрузить список товаров. Попробуйте обновить страницу.”

## 21.27 Loading State
Каждый компонент должен иметь собственное состояние загрузки.
Нельзя блокировать весь интерфейс без необходимости.

## 21.28 Accessibility
Каждый компонент обязан поддерживать:
клавиатурную навигацию;
корректный порядок фокуса;
ARIA-атрибуты;
управление с клавиатуры;
поддержку экранных дикторов;
достаточный контраст;
понятные названия элементов.

## 21.29 Analytics
Для каждого компонента документируются события.
Например, для Product Card:
Impression;
Click;
Hover (при необходимости);
Add to Cart;
Add to Wishlist;
Compare;
Quick View.
Для Button:
Click;
Disabled Click (если отслеживается);
Success;
Error.

## 21.30 QA Checklist
Перед выпуском каждый компонент проверяется по следующим критериям:
соответствует Design Tokens;
соответствует Accessibility;
поддерживает все состояния;
адаптивен;
документирован;
протестирован;
интегрирован с аналитикой;
соответствует библиотеке компонентов;
отсутствуют дубли;
протестирован на Desktop, Tablet и Mobile.

## 21.31 Каталог компонентов Enterprise
Для Enterprise eCommerce рекомендуется библиотека из 120–180 компонентов, сгруппированных по следующим разделам:

| Раздел | Примеры |
| --- | --- |
| Navigation | Header, Mega Menu, Breadcrumbs, Pagination, Tabs |
| Forms | Input, Select, Checkbox, Radio, Date Picker, File Upload |
| Commerce | Product Card, Price, Gallery, Stock Status, Variant Selector |
| Feedback | Toast, Alert, Banner, Modal, Snackbar |
| Data Display | Table, List, Timeline, Accordion, Tooltip |
| Layout | Grid, Container, Card, Divider, Drawer |
| Marketing | Hero Banner, Promo Tile, Countdown, Coupon, Trust Badges |
| Account | Order Card, Address Card, Loyalty Widget, Profile Summary |


### Следующая глава
Глава 22. Product Listing Page (PLP) станет первой из серии специализированных глав по страницам интернет-магазина. Она будет детально описывать UX/UI каталога товаров: структуру страницы, карточки товаров, сортировку, фильтрацию, пагинацию, бесконечную прокрутку, режимы отображения, SEO-блоки, аналитику, CRO-паттерны и чек-листы качества. Эта глава будет значительно объёмнее предыдущих, поскольку Product Listing Page — один из ключевых экранов eCommerce.
