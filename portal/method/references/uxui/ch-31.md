# Глава 31. Mobile UX & Responsive eCommerce

## 31.1 Mobile First как стратегия
Mobile UX — это не адаптация Desktop-интерфейса под меньший экран.
Это самостоятельная стратегия проектирования, в которой мобильное устройство рассматривается как основная платформа взаимодействия пользователя с интернет-магазином.
Во многих категориях eCommerce более половины всех сессий приходится на мобильные устройства.
Следовательно, качество Mobile UX напрямую влияет на:
Conversion Rate;
Bounce Rate;
Average Session Duration;
Add to Cart Rate;
Checkout Completion Rate;
Revenue.
Проектирование должно начинаться с Mobile First, а не заканчиваться адаптацией Desktop-макета.

## 31.2 Принципы Mobile UX
Мобильный интерфейс должен соответствовать следующим принципам:
минимальное количество действий;
максимальная скорость взаимодействия;
управление одной рукой;
понятная навигация;
высокая производительность;
простота сканирования информации;
отсутствие лишних элементов.

## 31.3 Архитектура мобильного интерфейса
Типичный пользовательский сценарий.
Home
↓
Search
↓
Category
↓
Product
↓
Cart
↓
Checkout
↓
Order Confirmation
Каждый переход должен занимать минимальное количество действий.

## 31.4 Thumb Zone
Одним из важнейших факторов Mobile UX является зона досягаемости большого пальца.
Экран условно делится на три зоны.

### Easy Zone
Нижняя центральная часть экрана.
Здесь рекомендуется размещать:
основные CTA;
нижнюю навигацию;
подтверждение действий;
кнопку Checkout.

### Stretch Zone
Средняя часть экрана.
Допускается размещение:
карточек товаров;
фильтров;
характеристик.

### Hard Zone
Верхние углы.
Не рекомендуется размещать:
основные CTA;
часто используемые действия.

## 31.5 Bottom Navigation
Для мобильных интернет-магазинов рекомендуется использовать нижнюю навигацию.
Типичный состав.
Главная.
Каталог.
Поиск.
Избранное.
Профиль.
Корзина.
Количество пунктов рекомендуется ограничить пятью.

## 31.6 Header
Мобильный Header должен быть максимально компактным.
Рекомендуемый состав.
Логотип.
Поиск.
Корзина.
Меню.
При прокрутке допускается использование Sticky Header.

## 31.7 Search
Поиск должен быть доступен с любого экрана.
Поддерживаются:
Autocomplete.
Voice Search.
Recent Searches.
Popular Searches.
Image Search.
Поиск является одним из самых используемых элементов мобильного eCommerce.

## 31.8 Mobile Category
Каталог должен поддерживать:
быстрые фильтры;
Sticky Filter;
Bottom Sheet;
быстрый сброс фильтров;
отображение количества найденных товаров.
Фильтрация не должна закрывать результаты без явного подтверждения пользователя.

## 31.9 Mobile Product Card
Карточка товара должна содержать:
изображение;
название;
цену;
скидку;
наличие;
CTA.
Дополнительная информация раскрывается по мере необходимости.

## 31.10 Mobile PDP
Карточка товара должна быть переосмыслена.
Первый экран содержит:
галерею;
цену;
CTA;
варианты;
наличие.
При длинной странице рекомендуется использовать Sticky Add to Cart.

## 31.11 Sticky CTA
Кнопка покупки должна оставаться доступной при прокрутке.
Рекомендуемый состав.
Цена.
↓
Название.
↓
CTA.
Sticky Bar особенно эффективен на экранах с длинным описанием товара.

## 31.12 Bottom Sheet
Bottom Sheet рекомендуется использовать вместо полноэкранных модальных окон.
Подходит для:
фильтров;
выбора вариантов;
выбора доставки;
выбора оплаты;
подтверждения действий.
Bottom Sheet сохраняет ощущение контекста и требует меньше когнитивных усилий.

## 31.13 Mobile Cart
Корзина должна содержать:
компактные карточки;
быстрое изменение количества;
Sticky Checkout;
стоимость заказа;
стоимость доставки.
Изменение количества должно выполняться одним касанием.

## 31.14 Mobile Checkout
При проектировании рекомендуется:
использовать цифровые клавиатуры;
разбивать длинные формы;
поддерживать Autofill;
поддерживать Apple Pay и Google Pay;
уменьшать количество обязательных полей.

## 31.15 Жесты
Допустимые жесты:
свайп;
pinch-to-zoom;
долгое нажатие (при необходимости);
горизонтальная прокрутка галереи;
pull-to-refresh (где это уместно).
Критически важные действия не должны зависеть только от жестов.

## 31.16 Производительность
Мобильные интерфейсы особенно чувствительны к скорости.
Необходимо:
оптимизировать изображения;
использовать Lazy Loading;
минимизировать JavaScript;
применять Skeleton вместо Spinner;
избегать Layout Shift.
Каждая дополнительная секунда загрузки увеличивает вероятность отказа.

## 31.17 Responsive Images
Изображения должны:
адаптироваться под разрешение устройства;
использовать современные форматы;
загружаться по мере необходимости;
не ухудшать качество восприятия товара.

## 31.18 Mobile Accessibility
Необходимо обеспечить:
размер интерактивных элементов не менее 44×44 px;
достаточные интервалы между элементами;
поддержку масштабирования;
читаемость текста;
корректную работу экранных дикторов.

## 31.19 Offline Experience
При использовании PWA рекомендуется поддерживать:
кэширование;
просмотр ранее открытых страниц;
сохранённую корзину;
повторную отправку действий после восстановления сети.

## 31.20 PWA
Progressive Web App может обеспечить:
установку на устройство;
Push-уведомления;
офлайн-режим;
быструю загрузку;
полноэкранный режим.
PWA особенно полезны для проектов, где нативное приложение экономически нецелесообразно.

## 31.21 iOS и Android
При проектировании необходимо учитывать особенности платформ.
iOS:
Safe Area;
Dynamic Island;
системные жесты;
Apple Pay.
Android:
системную кнопку «Назад»;
различные размеры экранов;
Material-компоненты;
Google Pay.
Интерфейс должен учитывать нативные ожидания пользователей каждой платформы.

## 31.22 Analytics
Необходимо отслеживать:
Mobile Session;
Device Type;
Screen Orientation;
Touch Events;
Swipe Events;
Bottom Navigation Usage;
Sticky CTA Click;
Mobile Search Usage;
Mobile Checkout Completion;
PWA Installation.

## 31.23 KPI Mobile UX

| KPI | Назначение |
| --- | --- |
| Mobile Conversion Rate | Конверсия на мобильных устройствах |
| Mobile Bounce Rate | Процент отказов |
| Mobile Add to Cart Rate | Добавление в корзину |
| Mobile Checkout Completion | Завершение оформления заказа |
| Average Mobile Session | Средняя продолжительность сессии |
| Sticky CTA Usage | Использование фиксированной CTA |
| Bottom Navigation Usage | Использование нижней навигации |
| Mobile Search Usage | Использование поиска |
| PWA Installation Rate | Установка PWA |


## 31.24 Типичные ошибки
Механическое уменьшение Desktop-интерфейса.
Слишком маленькие зоны касания.
Отсутствие Sticky CTA.
Скрытие важных действий в меню.
Использование Hover-сценариев.
Сложные формы.
Медленная загрузка.
Перегруженные карточки товаров.
Игнорирование Safe Area.
Отсутствие тестирования на реальных устройствах.

## 31.25 Mobile UX QA Checklist
Перед выпуском необходимо проверить:
управление одной рукой возможно для основных сценариев;
интерактивные элементы имеют достаточный размер;
навигация интуитивно понятна;
Sticky CTA работает корректно;
фильтры реализованы через Bottom Sheet или аналогичный паттерн;
скорость загрузки соответствует целевым требованиям;
поддерживаются жесты, не являясь единственным способом взаимодействия;
Accessibility соблюдена;
аналитика настроена;
интерфейс протестирован на популярных устройствах iOS и Android.
