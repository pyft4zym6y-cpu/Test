# Глава 17. Visual Hierarchy & Layout Design

## 17.1 Что такое Visual Hierarchy
Visual Hierarchy — это система организации визуальных элементов интерфейса, определяющая порядок, в котором пользователь воспринимает информацию.
Интерфейс никогда не воспринимается целиком.
Пользователь последовательно переводит внимание между отдельными элементами.
Задача визуальной иерархии — управлять этим процессом.
Каждый экран должен отвечать на три вопроса:
Что пользователь должен увидеть первым?
Что он должен понять вторым?
Какое действие должен выполнить далее?
Если последовательность восприятия не спроектирована, пользователь формирует её самостоятельно, что увеличивает вероятность ошибок.

## 17.2 Принципы визуальной иерархии
Визуальная иерархия строится за счёт управления несколькими параметрами.

### Размер
Крупные объекты воспринимаются раньше.
Используются для:
заголовков;
цены;
основной CTA;
ключевых преимуществ.

### Контраст
Высокий контраст усиливает визуальный приоритет.
Контраст формируется:
цветом;
насыщенностью;
яркостью;
размером;
формой.

### Положение
Элементы, расположенные выше и левее (для LTR-интерфейсов), замечаются раньше.
Наиболее важная информация должна находиться в верхней части первого экрана.

### Свободное пространство
Большое количество свободного пространства вокруг объекта увеличивает вероятность его восприятия.
Whitespace является инструментом управления вниманием.

### Повторение
Повторяющиеся элементы формируют визуальный ритм.
Нарушение ритма используется для создания акцентов.

## 17.3 Законы движения взгляда
Большинство пользователей не читают страницу последовательно.
Они сканируют её.
При проектировании необходимо учитывать наиболее распространённые паттерны.

### F-Pattern
Используется преимущественно для:
каталогов;
текстовых страниц;
блогов;
документации.
Пользователь:
читает верхнюю строку;
↓
просматривает начало следующих строк;
↓
быстро сканирует левую часть страницы.
Выводы.
Самая важная информация должна находиться:
сверху;
слева;
в начале строк.

### Z-Pattern
Наиболее характерен для:
Landing Page;
Главной страницы;
коротких экранов.
Последовательность внимания:
левый верхний угол
↓
правый верхний угол
↓
левый нижний угол
↓
правый нижний угол
CTA рекомендуется размещать в конечной точке Z-паттерна.

### Layer Cake Pattern
Используется при просмотре длинных страниц.
Пользователь обращает внимание только на:
заголовки;
иллюстрации;
кнопки;
акцентные блоки.
Основной текст часто пропускается.

## 17.4 Визуальные уровни информации
Каждый экран должен иметь несколько уровней приоритетов.

### Primary
Главная информация.
Например.
Название товара.
Цена.
Кнопка покупки.

### Secondary
Дополнительная информация.
Описание.
Рейтинг.
Отзывы.

### Tertiary
Информация низкого приоритета.
Артикул.
Дата обновления.
Дополнительные документы.
Приоритет должен быть очевиден без чтения текста.

## 17.5 Композиция
Композиция определяет расположение элементов относительно друг друга.
Основные принципы.
Баланс.
Ритм.
Пропорции.
Выравнивание.
Контраст.
Единство.
Нарушение любого из принципов ухудшает восприятие страницы.

## 17.6 Grid System
Все страницы должны строиться на единой модульной сетке.
Desktop.
12 колонок.
Tablet.
8 колонок.
Mobile.
4 колонки.
Все элементы должны быть кратны выбранной системе отступов.

## 17.7 Whitespace
Whitespace — свободное пространство между элементами интерфейса.
Его функции:
уменьшение когнитивной нагрузки;
улучшение читаемости;
формирование групп;
создание визуальных акцентов.
Недостаток свободного пространства приводит к ощущению перегруженности.
Избыточное пространство нарушает связность элементов.

## 17.8 Правило близости
Элементы, относящиеся к одной группе, должны располагаться ближе друг к другу, чем к соседним группам.
Например.
Цена.
↓
Скидка.
↓
Кнопка покупки.
Эти элементы должны восприниматься как единый блок.

## 17.9 Визуальный вес
Каждый объект обладает визуальным весом.
На него влияют:
размер;
цвет;
насыщенность;
контраст;
положение;
форма;
количество свободного пространства.
Во время проектирования необходимо распределять визуальный вес таким образом, чтобы главный сценарий воспринимался первым.

## 17.10 Первый экран
Above the Fold остаётся наиболее важной частью большинства eCommerce-страниц.
На первом экране пользователь должен получить ответы на вопросы:
Что это за сайт?
Что здесь можно купить?
Почему стоит доверять?
Что делать дальше?
Если первый экран не отвечает на эти вопросы, вероятность отказа значительно возрастает.

## 17.11 Layout Patterns
Наиболее распространённые схемы компоновки.

### Single Column
Используется:
Mobile;
Checkout;
Forms.

### Sidebar Layout
Категории.
Каталог.
Фильтрация.

### Card Layout
Карточки товаров.
Категории.
Подборки.

### Dashboard Layout
Личный кабинет.
CRM.
ERP.
Каждая схема должна использоваться только в соответствующем контексте.

## 17.12 Визуальные акценты
Акценты создаются с помощью:
цвета;
размера;
контраста;
анимации;
свободного пространства;
формы.
Количество основных акцентов должно быть ограничено.
Если всё выглядит важным — важным не выглядит ничего.

## 17.13 CTA Hierarchy
Каждый экран должен иметь один Primary CTA.
Дополнительно допускаются:
Secondary CTA.
Tertiary CTA.
Например.
Купить — Primary.
Добавить в избранное — Secondary.
Поделиться — Tertiary.
Использование нескольких Primary CTA на одном экране ухудшает принятие решений.

## 17.14 Responsive Layout
При адаптации интерфейса запрещается механически переносить Desktop-макет на Mobile.
Необходимо переосмысливать:
иерархию;
последовательность блоков;
приоритет информации;
доступность элементов;
зоны касания.

## 17.15 Проверка визуальной иерархии
Для каждого экрана рекомендуется проводить проверку.
Если показать страницу пользователю на 5 секунд, должен ли он понять:
что продаётся;
где цена;
где кнопка покупки;
почему этому магазину можно доверять;
что делать дальше.
Если ответ отрицательный — визуальная иерархия требует переработки.

## 17.16 Типичные ошибки
Отсутствие выраженного главного акцента.
Несколько Primary CTA.
Слишком плотное расположение элементов.
Избыточное использование цветов.
Случайные размеры заголовков.
Нарушение сетки.
Недостаток свободного пространства.
Одинаковый визуальный вес всех блоков.
Перегруженный первый экран.
Отсутствие единого ритма.

## 17.17 Deliverables
По результатам проектирования должны быть подготовлены:
Visual Hierarchy Specification;
Layout System Guide;
Grid Specification;
Whitespace Rules;
Visual Weight Matrix;
CTA Hierarchy Guide;
Responsive Layout Rules;
Composition Checklist;
Visual QA Checklist;
Layout Review Report.
