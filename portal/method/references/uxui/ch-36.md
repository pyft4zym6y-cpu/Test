# Глава 36. eCommerce SEO, GEO, AEO & LLM Optimization

## 36.1 Новая эпоха поиска
Традиционное SEO больше не является единственным источником органического трафика.
Сегодня пользователь получает ответы через:
Google Search;
Google AI Overviews;
ChatGPT;
Gemini;
Claude;
Perplexity;
Copilot;
голосовых ассистентов;
встроенные AI-поисковые системы маркетплейсов.
Следовательно, современный eCommerce должен оптимизироваться одновременно для:
поисковых систем;
Answer Engines;
LLM;
AI Search.

Structured Data.

## 36.5 Information Architecture и SEO
Information Architecture должна помогать поисковым системам понимать структуру магазина.
Например.
Главная
↓
Категория
↓
Подкатегория
↓
Товар
Не рекомендуется создавать чрезмерно глубокие структуры.

## 36.6 URL Strategy
Хороший URL.
/site/tools/drills/bosch-gsb-18v
Плохой URL.
/site/product?id=483920&cat=17
URL должны быть:
понятными;
короткими;
стабильными;
иерархичными.

## 36.7 Metadata
Каждая индексируемая страница должна иметь.
Title.
Meta Description.
H1.
Canonical.
Open Graph.
Twitter Cards (при необходимости).
Title должен отражать основное намерение пользователя.

## 36.8 Category SEO
Категория должна содержать.
H1.
Описание.
FAQ.
Популярные фильтры.
Внутренние ссылки.
Schema.
SEO-текст.
Рекомендации.
Контент не должен мешать пользовательскому сценарию.

## 36.9 Product SEO
Карточка товара должна содержать.
Уникальный Title.
Описание.
Характеристики.
Отзывы.
FAQ.
Изображения.
ALT.
Видео.
Structured Data.
Дублирование описаний производителя нежелательно.

## 36.10 Structured Data
Минимальный набор Schema.org.
Product.
Offer.
AggregateRating.
Review.
BreadcrumbList.
Organization.
FAQPage.
WebSite.
SearchAction.
ItemList.
Структурированные данные помогают поисковым системам и AI лучше понимать содержимое страницы.

## 36.11 Core Web Vitals
Необходимо контролировать.
LCP.
INP.
CLS.
Оптимизация должна выполняться без ухудшения пользовательского опыта.

## 36.12 Semantic SEO
Современный поиск анализирует не отдельные ключевые слова, а смысл.
Контент должен отвечать на вопросы пользователя.
Например.
Не только.
“Купить шуруповерт”
Но и.
Как выбрать?
Для чего подходит?
С чем совместим?
Какие есть альтернативы?

## 36.13 Topical Authority
Интернет-магазин должен демонстрировать экспертность.
Например.
Категория.
↓
Гайды.
↓
FAQ.
↓
Сравнения.
↓
Видео.
↓
Инструкции.
↓
Обзоры.
↓
Советы.
Это усиливает доверие как пользователей, так и поисковых систем.

## 36.14 AEO (Answer Engine Optimization)
AEO направлено на подготовку контента для систем, которые сразу дают готовый ответ.
Контент должен:
отвечать на конкретные вопросы;
быть структурированным;
использовать понятные заголовки;
содержать списки;
содержать таблицы;
иметь логичную структуру.

## 36.15 GEO (Generative Engine Optimization)
GEO — оптимизация контента для генеративных AI-систем.
Основные принципы.
Высокая структурированность.
↓
Фактическая точность.
↓
Контекст.
↓
Экспертность.
↓
Актуальность.
↓
Связность.
↓
Машиночитаемость.
AI легче использует материалы, имеющие чёткую структуру и подтверждённые данные.

## 36.16 LLM Visibility
LLM Visibility — способность сайта становиться источником информации для больших языковых моделей.
Этому способствуют:
качественный экспертный контент;
логичная структура;
уникальные данные;
прозрачная информация о компании;
корректная разметка;
стабильные URL;
высокая репутация бренда.

## 36.17 Контент для AI
Контент рекомендуется строить по принципу.
Определение.
↓
Пояснение.
↓
Список.
↓
Таблица.
↓
FAQ.
↓
Пример.
↓
Вывод.
Подобная структура хорошо воспринимается как людьми, так и AI.

## 36.18 FAQ Strategy
FAQ становится обязательным элементом большинства коммерческих страниц.
Каждый ответ должен:
отвечать на один вопрос;
быть кратким;
быть понятным;
не содержать маркетинговых обещаний.

## 36.19 Entity Optimization
Необходимо формировать устойчивые сущности.
Например.
Компания.
↓
Бренд.
↓
Категория.
↓
Товар.
↓
Производитель.
↓
Автор.
↓
Материал.
↓
Технология.
Чем лучше описаны сущности, тем легче AI связывает информацию.

## 36.20 AI Search Optimization
Необходимо учитывать особенности AI-поиска.
AI предпочитает:
структурированные ответы;
экспертные материалы;
актуальные данные;
сравнения;
таблицы;
пошаговые инструкции;
источники с высокой репутацией.

## 36.23 KPI SEO / GEO / AEO

| KPI | Назначение |
| --- | --- |
| Organic Sessions | Органический трафик |
| Organic Revenue | Доход из органического поиска |
| Organic Conversion Rate | Конверсия органического трафика |
| Core Web Vitals Pass Rate | Соответствие CWV |
| Structured Data Coverage | Покрытие Schema.org |
| Rich Results Coverage | Доля страниц с расширенными результатами |
| Topical Authority Growth | Рост тематического покрытия |
| AI Referral Traffic | Переходы из AI-сервисов |
| AI Citation Rate | Частота упоминаний бренда или контента в AI-системах (если измеримо) |
| LLM Visibility Score | Комплексная оценка видимости в AI-экосистеме (при наличии собственной методики) |


## 36.24 Типичные ошибки
Ориентация исключительно на ключевые слова.
Дублирование описаний производителей.
Отсутствие структурированных данных.
Игнорирование FAQ.
Слабая Information Architecture.
Низкое качество контента.
Неуникальные Title и Description.
Отсутствие внутренней перелинковки.
Игнорирование Core Web Vitals.
Попытки создавать контент исключительно “для AI”, а не для пользователя.

## 36.25 SEO / GEO QA Checklist
Перед публикацией необходимо проверить:
Technical SEO соответствует требованиям;
Information Architecture поддерживает индексацию;
URL имеют логичную структуру;
Schema.org реализована корректно;
контент отвечает пользовательскому намерению;
FAQ охватывает ключевые вопросы;
Core Web Vitals соответствуют целевым значениям;
страницы пригодны для цитирования AI-системами;
аналитика SEO и AI-трафика настроена;
контент регулярно актуализируется.
