## Chapter 16

Navigation Acceptance Criteria
Навигационная система соответствует Enterprise-стандарту, если:
□ Пользователь может попасть в любую основную категорию не более чем за 2–3 действия.
□ Архитектура отражает ментальную модель покупателей, а не организационную структуру компании.
□ Все типы навигации (Global, Mega Menu, Breadcrumbs, Faceted, Mobile) работают как единая система.
□ Навигация одинаково удобна на Desktop, Tablet и Mobile.
□ Все действия покрыты аналитикой.
□ Структура масштабируется без полной переработки при расширении каталога.
□ Все изменения проходят проверку через Navigation Experiment Library и Information Architecture Review.

Именно формы лежат в основе регистрации, Checkout, возвратов, подписок и большинства конверсионных сценариев e-commerce.

## Chapter 19

Enterprise Form Acceptance Criteria
Форма считается соответствующей Enterprise-стандарту, если:
□ Каждое поле имеет подтверждённую бизнес-необходимость.
□ Пользователь понимает назначение каждого поля без дополнительных объяснений.
□ Форма поддерживает Autofill, Password Managers и мобильные клавиатуры.
□ Ошибки обнаруживаются максимально рано и помогают пользователю исправить проблему.
□ Введённые данные не теряются при ошибках, обновлении страницы или возврате назад.
□ Все взаимодействия покрыты аналитикой до уровня отдельных полей.
□ Форма одинаково удобна для Desktop, Mobile и пользователей вспомогательных технологий.
□ Любое изменение формы проходит проверку через библиотеку экспериментов и Design Review Framework.

## Chapter 18

Anti-pattern Library
✕
Два одинаковых компонента с разным поведением.
✕
Разные отступы для одинаковых элементов.
✕
Разные цвета Primary CTA.
✕
Несогласованные состояния Loading.
✕
Отсутствие Disabled State.
✕
Компоненты не поддерживают клавиатуру.
✕
Несколько Design Tokens для одного свойства.
✕
Локальные стили вместо системных.
✕
Изменение компонентов без обновления документации.
✕
Создание нового компонента вместо переиспользования существующего.
