Срез 26.08.2026. Часть 1 проверена в коде, часть 2 — внешний поиск.

## Часть 1. Есть, но не подключено

### 1.1 Скилы: 73 установлено, 0 подключено к движку

| Состояние | Сколько |
|---|---|
| Реально загружаются кодом аудита | **0** |
| Только описаны в `worker/TOOLING.md` как «наш стек» | 39 |
| Не упомянуты нигде | 25 |
| Ложные срабатывания при поиске | 7 |

Проверка «ложных»: `cro` нашёлся внутри слова «Mi**cro**phone»; `sm-post-writer`,
`sm-content-matrix`, `sm-reels-scripting` — внутри строки рекомендации, которую
аудит печатает КЛИЕНТУ («Інструмент: скіли sm-content-matrix / …»), то есть мы
советуем клиенту скилы, которых сами не запускаем; `web-design-guidelines` —
в комментарии к коду. Ни одного вызова.

Единственное настоящее подключение — 22 OS-скила методологии
(`worker/reference/weexp-os/`), включённые 25.08 через `domainSkills.ts`.

### 1.2 MCP-серверы: 9 настроено, воркеру недоступен ни один

`.mcp.json` в корне — конфиг **сессии разработки**, а не рантайма аудита.
Воркер на Railway запускается из `worker/Dockerfile` и об этих серверах не знает:

| Сервер | Назначение по TOOLING.md | Доступен воркеру |
|---|---|---|
| `geo-analyzer` | GEO/AEO: видимость в AI-поиске | нет |
| `search-console-mcp` | GSC + Bing WMT + GA4 → AC-03 | нет |
| `screaming-frog-seo-spider-mcp-server` | тех-SEO краул → AC-03/04 | нет |
| `notfair-googleads` | рекламные кабинеты → AC-07 | нет |
| `posthog` | продуктовая аналитика/воронки | нет |
| `openbrand`, `citedy-seo-agent`, `labelhead`, `codebase-memory` | бренд, SEO-агент, память | нет |

Три из них (`citedy-seo-agent`, `labelhead-artist-momentum`, `notfair-googleads`)
не авторизованы даже в сессии — им нужен OAuth, который в неинтерактивной сессии
пройти нельзя. Авторизуются через настройки коннекторов claude.ai или `/mcp`
в интерактивной сессии.

### 1.3 Внешний поиск воркера мёртв на проде

`worker/src/agentReach.ts` зовёт `mcporter call exa.web_search_exa`.
**`mcporter` не устанавливается в `worker/Dockerfile`** — бинаря в образе нет.
Вызов падает и деградирует молча: в отчёте это выглядит как «внешний поиск не дал
результатов», а не как «инструмент отсутствует». Затронуты соцсети, внешний
инфофон и отзывы (`externalAudits.ts`).

### 1.4 Эталонный прогон лежит без дела

`worker/reference/weexp-os/lanavitta-run01/` — реальный прогон L0 с `findings.json`
и `coverage.json`. Идеальный материал для регресс-теста движка (у которого сейчас
ноль тестов на 13,5 тыс. строк), но как тест не используется.

## Часть 2. Чего не хватает — внешний поиск

### 2.1 CrUX API — самое сильное из бесплатного

Chrome UX Report: реальные полевые Core Web Vitals (LCP, CLS, INP) от живых
пользователей Chrome. Бесплатно, через API или BigQuery.

**Почему это важно именно нам:** данные доступны по ЛЮБОМУ домену — значит
конкурентов можно мерить без единого доступа. Сейчас Website-аудит опирается на
PageSpeed (лабораторные данные одного прогона); CrUX даёт распределение по реальным
пользователям и прямое сравнение «клиент против конкурентов» в разделе, где у нас
сегодня только собственный замер.

### 2.2 Базы бенчмарков для раздела «против рынка»

Наш `40-benchmark-standards.md` — внутренний. Признанные внешние источники, на
которые ссылается индустрия: **Baymard Institute** (UX/чекаут — эталон отрасли,
именно на нём стоит строить AQC-критерии), **IRP Commerce** (помесячные метрики
по нишам), **Littledata**, **Dynamic Yield**, **Statista**, **Klaviyo**.

Порядок чисел для сверки: средняя конверсия e-commerce 2026 — 1.4–3.0%;
Food & Beverage 4.9–6.2% вверху диапазона, luxury/jewelry 0.5–1% внизу.
Это диапазоны из вторичных публикаций — для отчёта клиенту нужен первоисточник.

### 2.3 Измерение видимости в AI-поиске

`robots.txt` намеренно приглашает GPTBot, PerplexityBot, ClaudeBot, но
**измерения видимости нет**: мы не знаем, цитируют ли клиента ChatGPT, Perplexity,
AI Overviews, Gemini. Категория инструментов сложилась: LLM Pulse (от €49/мес),
Peec AI, AIclicks, LLMrefs — трекинг упоминаний, цитат, доли голоса и того, какие
URL движки цитируют по запросу. Плюс наш собственный `geo-analyzer` MCP, который
делает часть этого и не подключён.

## Порядок действий

1. **Поставить `mcporter` в Dockerfile** и заменить тихую деградацию на явную
   пометку в отчёте: «внешний поиск недоступен». Час работы, чинит три раздела.
2. **Решить, как воркер получает инструменты.** MCP из `.mcp.json` ему не видны
   by design. Либо ставить нужные MCP в образ, либо ходить в их API напрямую.
   Без этого решения TOOLING.md описывает стек, которого у аудита нет.
3. **CrUX API** — прямой HTTP, ключ Google, никакой авторизации клиента.
   Самое дешёвое усиление Website-аудита и единственный способ мерить конкурентов
   по реальным пользователям.
4. **Baymard** как основа AQC-критериев — со ссылкой в отчёте: чужой признанный
   стандарт весит больше нашего внутреннего чек-листа.
5. **GEO-измерение** — сначала подключить свой `geo-analyzer`, и только если не
   хватит, смотреть на платные трекеры.
6. **`lanavitta-run01` → регресс-тест** движка. Первый тест на 13,5 тыс. строк.
